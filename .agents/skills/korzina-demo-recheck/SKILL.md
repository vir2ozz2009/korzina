# Перепроверка исправления Korzina

1. Определить ID и одну актуальную передачу из задания. В checkout `vir2ozz2009/korzina` прочитать корневой AGENTS и `docs/context/recheck.md`; без checkout получить их через GitHub на зафиксированном свежем main. Не читать все старые отчёты. Канонические процедуры — `docs/WORKFLOW.md` раздел «Короткий цикл исправления» и `docs/TESTING.md` §5/§8, только применимое.
2. Установить ожидаемое поведение, разрешённые сценарии/среды, выпущенный SHA, CI/smoke и СТОП. Если отсутствует существенное поле, найти его в текущей передаче; неизвестное не угадывать. Для недостающей границы запросить только её, продолжая независимую подготовку. Новое продуктовое поведение вернуть в Work.
3. Проверить фактическую ревизию проверяемого клиента. Ответ сервера или curl на Mac не объявлять подтверждением SHA DOM на iPhone. При несовпадении/неизвестном клиентском SHA отделить наблюдение от PASS целевой сборки; выяснить причину и сохранить ограничение.
4. Локальный исполнитель проверяет физический iPhone через Mirroring, Safari/Telegram по заданию. При недоступности устройства/входа использовать установленную процедуру восстановления; известный блокер без новых условий повторно не настраивать. Зависимые шаги отметить ⏸, продолжить независимые. Эмуляцию и API учитывать отдельно; не выдавать за физическую проверку.
5. Подготовить только свои восстановимые учебные данные. Приватно сохранить исходное состояние; не затрагивать prod, Lavka или невосстановимое удаление. API-подготовка не подтверждает UI-сценарий. Соблюдать разрешения AGENTS/WORKFLOW; навык сам не разрешает публикацию, исправление кода или расширение объёма.
6. Выполнить дефект и непосредственно затронутые зависимости. Сохранить сценарий → среда → SHA → результат → доказательство. При повторении дефекта сообщить сборку/шаг и продолжить независимое. Незатронутый остаток блока не присоединять; старые PASS не переносить на новый SHA.
7. Восстановить свои данные и закрыть временные сессии. Ошибку уборки явно записать. Обновить одну передачу: проверенный объём, доказательства, ограничения, открытый остаток по ссылке, уборка, следующий исполнитель и СТОП. Полный журнал и личные данные не публиковать. Окончательная приёмка — Андрей.
8. Завершить форматом WORKFLOW: результат, ограничение, следующий шаг/исполнитель и одна команда передачи. Без инструмента отправки дать текст команды; не утверждать, что другой агент запущен.
