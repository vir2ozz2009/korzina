# Реализация согласованной задачи

Карточка → строка изменения в карте блока → требования и критерии своих историй → контракт/символ и его потребители. Границы — [WORKFLOW: золотые правила](../WORKFLOW.md#золотые-правила), порядок выпуска — [полный цикл до demo](../WORKFLOW.md#полный-технический-цикл-до-demo) и [проверки](../WORKFLOW.md#проверки). Без нового поведения вне задания.

| Изменение | Дополнительные разделы |
|---|---|
| Любой код | [CONVENTIONS](../CONVENTIONS.md): затронутый слой и «Автоматическая проверка архитектуры»; [TESTING](../TESTING.md) §1 и §2 |
| Сервер | ARCHITECTURE §1, §4–7 по затронутой ответственности; PERFORMANCE §1, §5–6 по запросам/бюджетам |
| Данные на клиенте | PERFORMANCE §2–4, §7 по изменённым запросам, кешу и загрузке |
| UI | DESIGN §2–5а, строки компонентов/токенов; одобренная ревизия; TESTING §7. Процедуру сборки холста не читать заново, если холст уже одобрен и не меняется |
| Новый/изменённый тест, решение, найденный дефект | TESTING §8; §3 при бюджете времени; §4 при нестабильности/удалении/дублировании тестов |
| Выпуск | TESTING §6; §7 для видимых изменений; явный СТОП задания |

[Критические зависимости](README.md#когда-расширить-карту) обязательны. Каждый реализуемый кодом критерий/решение покрыть тестом по TESTING §2/§8; визуальные доказательства не заменяют поведение. Перед завершением — [документы и передача](documentation.md).
