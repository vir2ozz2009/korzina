Решение Андрея 28.11.2026: до нового холста составить карту затронутых существующих экранов → ранее одобренный холст/точная ревизия → актуальная спецификация и поздние принятые правки → экран свежего main → согласованное добавление. Адресно просмотреть прежние холсты, не только перечислить ссылки. Показать новые элементы внутри существующих разделов и сквозные переходы туда/обратно; сохранить соседние элементы, данные и действия. Отсутствие прежнего элемента на новом холсте не означает его удаления. Не пересобирать весь прошлый блок. Если исходный холст недоступен, явно записать ограничение; main использовать как реализацию, не как замену одобрению. Противоречие источников разрешить в Work до сборки затронутого экрана.

Тесты правил будущего блока описать по TESTING §8; после одобрения — [реализация](implementation.md). Передача — [документы](documentation.md).
