# Визуальная правка без новой логики

Прочитать конкретное замечание Андрея, затронутый экран и соответствующие строки DESIGN/дизайн-системы. Сохранить принятое поведение и соседние элементы. Использовать UI-кит и токены; изменение более трёх компонентов UI-кита — отдельная задача/PR и СТОП.

TESTING §1 выбирает локальную проверку; §7 — preview smoke и снимки видимого изменения. Изменение расчёта, команды, контракта, прав или состояния переводит задачу в [реализацию](implementation.md) с [критическими зависимостями](README.md#когда-расширить-карту).

Мелкое замечание после одобрения не требует новой ревизии холста по WORKFLOW «Проверки». Новый экран или новое поведение — [подготовка](preparation.md), согласование сохраняется. Финал — [передача](documentation.md).
