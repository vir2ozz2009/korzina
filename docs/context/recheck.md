# Физическая проверка demo

Обязательное правило: [только изменения и прямые зависимости, максимум 10 минут](../TESTING.md#проверка-изменений-максимум-10-минут), включая подготовку и восстановление данных. До лимита продолжать выбранные сценарии, по лимиту остановить проверки и записать остаток; не продолжать автоматически.

Актуальная передача с выпущенным SHA, средой и CI/smoke → согласованные сценарии и нужные фикстуры. TESTING §5, §8 и [стандарт блока: шаги 7–8](../specs/README.md#стандартный-порядок-блока-решение-андрея-18112026-эталон--блок-2-покупка). Облачный Codex до прямой передачи локальному сам сверяет покрытие: первичное — полностью, исправление — только изменение покрытия.

Первичная приёмка: полный чек-лист и таблица покрытия задают требования; физические сценарии выбирать по изменению и лимиту, остальные доказательства брать из актуальных автотестов и артефактов с их границами. Перепроверка: только дефект и непосредственные зависимости по [короткому циклу](../WORKFLOW.md#короткий-цикл-исправления); старые отчёты/спецификации — лишь для конкретного пробела. Карта/карточка — если передаче не хватает границ.

Локальный Codex использует физический iPhone через Mirroring, Safari/Telegram по заданию. Недоступное отметить ⏸ и продолжить независимое; API-подготовка не является UI-доказательством. Сохранять приватно исходное состояние своих фикстур и восстанавливать после прогона. При некритичной неполноте диагностики продолжать сценарии по [TESTING §5](../TESTING.md#продолжение-при-некритичных-ограничениях): функциональный результат и подтверждение SHA отмечать раздельно. Неизвестный SHA iPhone не блокирует прогон; эмуляцию учитывать отдельно. Итог — [одна передача](documentation.md); принимает Андрей.
