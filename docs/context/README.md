# Чтение по задаче и этапу

Всегда: корневой AGENTS → короткий PROGRESS → маршрут своего этапа. Для продуктовой подготовки/реализации: карточка текущей задачи → карта подблока → строки своих историй. Карточка и отчёт CTX-1 нужны только для работы над самим CTX-1; для обычной продуктовой задачи они не обязательны. Для локальной перепроверки: актуальная передача с выпущенным SHA → остаток чек-листа → нужные фикстуры; карточка/карта — если не хватает границ или покрытия. PLAN — только строка задачи/блока. Карты: [12.1](../blocks/12.1.md), [12.2](../blocks/12.2.md), [12.3](../blocks/12.3.md). Для другого блока тот же порядок по ссылкам карточки. Вложенный AGENTS не подгружается «по теме»: его применимость зависит от рабочей папки.

## Как открыть раздел

Сначала заголовки: `rg -n '^#{1,4} ' docs/specs/promo-discounts.md`. Найти нужный заголовок, затем `sed -n '224,236p' docs/specs/promo-discounts.md` (пример §13 «Настоящая корзина покупателя»; номера перепроверять после изменений). Читать до следующего заголовка того же/старшего уровня. Для историй искать точный ID с границами: `rg -n '(^|[^[:alnum:]_-])US-A01([^[:alnum:]_-]|$)' docs/stories/README.md`; US-A01b и US-A11 — отдельные запросы. Для PLAN/DECISIONS использовать точный ID задачи или формулировку решения, без общего поиска `12.1` по всем файлам.

Выводить небольшие порции: заголовки отдельно, затем один раздел или несколько строк таблицы. Длинный раздел делить на неперекрывающиеся диапазоны; при усечении уменьшить порцию и дочитать только недостающую часть. Уже прочитанные разделы использовать повторно без нового вывода, пока файл не изменился или не возникло конкретное противоречие. Длинная строка таблицы тоже расходует контекст: число строк не бюджет токенов.

## Когда расширить карту

Проследить цепочку от изменённого поля/команды до потребителей и миграций. Деньги → расчёт, заказ, оплаченные доли и возврат; новые данные → слияние профилей/гостя, копирование, выход и удаление. Права → отзыв доступа и другой магазин/сессия; команда → повтор, версия и гонка. Открывать соответствующие DOMAIN/контракты/тесты, даже если их нет в карте. COSTS — до платного изменения; NEW_FEATURE — при новой функции; Lavka — лишь при разрешённой ссылке. Расхождение источников — в Work с рекомендацией, без выбора нового процесса или разрешений по догадке.

Архивы и DECISIONS целиком не читать. В отчёте назвать основные прочитанные разделы и причину каждого расширения. Структура ограничивает ненужное чтение, но не доказывает фактическую экономию токенов: её проверяют в новых чатах.

## Поддержание контекста

Постоянное правило Андрея от 27.11.2026: поддерживать компактность в обычной работе, без отдельного повторного аудита на каждую задачу.

- **Один источник правила.** Действующее поведение хранить в спецификации блока, общие инварианты — в DOMAIN, процедуры — в WORKFLOW/TESTING. Карточка задаёт границы и ссылки; DECISIONS — дата, краткое решение и ссылка. При новой правке обновлять действующий раздел и критерии, сохранять историю решения ссылкой; не оставлять цепочку противоречащих дополнений единственным способом узнать правило.
- **Один вход в передачу.** Использовать существующий актуальный документ задачи: точная ревизия холста/SHA приложения, что подтверждено, ограничения и остаток, следующий исполнитель. PROGRESS содержит только этап и ссылку. Комментарий PR и чат ссылаются на передачу; не создают другую версию её статуса. Исторические доказательства сохранять со своей ревизией, не переносить старый PASS на новый код автоматически.
- **Карта по ответственности.** В карте блока — основные точки входа, контракт, расчёт/команда, потребители и связанные тесты с причиной связи. Не делать полный реестр файлов и не копировать их содержимое. При переносе файла, изменении контракта или появлении зависимости обновлять затронутую карту/ссылки в том же PR. Для короткой задачи достаточно точных путей в карточке, отдельная карта не обязательна.
- **Код читать по зависимости.** Сначала точный символ/путь и его вызовы, затем нужные функции и тесты. Большой файл не читать целиком по умолчанию. Разделять код по самостоятельным обязанностям, когда это обосновано изменением; не дробить механически по числу строк, не добавлять абстракции ради экономии контекста и не затевать общий рефакторинг в несвязанной задаче.
- **Ограничивать вывод инструментов.** Искать инструменты по точному сервису/действию; выводить описание только выбранных методов. Фильтровать дерево, diff, поиск и логи до нужных путей/полей. Независимые чтения можно объединять, но не выводить большой пакет полных файлов. Предпочитать диапазоны на стороне источника; если инструмент получил весь файл, не называть выбранный фрагмент всем объёмом загрузки.
- **Минимальная проверка перед завершением.** В рамках обычного просмотра diff проверить затронутые ссылки, отсутствие нового дублирующего правила, актуальность этапа и карты. Исправлять обнаруженную рассинхронизацию затронутой задачи; чужие статусы и архивы не переписывать. Новые CI, обязательный замер токенов и полный аудит репозитория для этого не нужны.
- **Результат без лишнего отчёта.** Обычной задаче достаточно кратко назвать источники и существенное расширение маршрута. Полный журнал диапазонов/байтов/повторов — только по запросу аудита. Не обещать точную экономию токенов без измерения. Права, деньги, изоляция, повторы, возвраты, обязательные проверки и решения Андрея имеют приоритет над сокращением чтения.

На переходе этапа использовать [короткую передачу в новый чат](../WORKFLOW.md#чат-на-этап); текущую итерацию не обрывать. Автоматически подгружаемые внешние инструкции содержат только проект, маршрут входа и критические границы. Не дублировать в них спецификации, статусы, историю и таблицы проверок. Системные инструкции и память сервиса не считать управляемыми файлами проекта.

Внешние инструкции Work/локального Codex должны ссылаться на этот маршрут, а не копировать его целиком. В текущем PR не требуется просматривать и переписывать все старые документы; порядок применяется к новым и затронутым материалам.
