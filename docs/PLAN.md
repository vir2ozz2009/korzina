# План разработки Korzina

Порядок строгий: задача начинается, когда закрыты её зависимости. Каждая задача — одна ветка, один чат Codex (иногда два), результат на demo.
**Карточка каждой задачи — отдельный файл `docs/tasks/<ID>.md`** (шаблон и правила — [`docs/tasks/README.md`](tasks/README.md)). Здесь — только блоки и индекс. Codex читает одну карточку своей задачи, а не этот файл целиком. Истории задачи — `docs/stories/README.md`, колонка «Задача».

**Уровень модели Codex (выбирает Андрей в чате):** «Среднее» — экраны из готовых компонентов, правки текста и стилей, документы, чистка; «Высокое» — деньги, оформление и оплата, заказы и их статусы, права и сессии, миграции данных, архитектура и аудит.

Легенда фаз: **F** — фундамент · **B** — покупатель (волна 1) · **S** — продавец управляет магазином (волна 2) · **O** — жизненный цикл заказа (волна 3) · **L** — запуск · **A** — дополнения под флагами (волна 4+).

## Блоки (решение Андрея 18.11.2026)

Работа идёт **логическими блоками**: блок — законченный сценарий, который в конце работает целиком. Порядок работы в блоке (карточки → спецификация → холст → правки → сервер → экраны → приёмка) — `docs/specs/README.md` «Стандартный порядок блока»; эталон — блок 2 «Покупка».

**Порядок блоков (решение Андрея 18.11.2026, после разбора плана):** сразу за входом продавца — минимальные заказы у продавца (O1, O2), чтобы главный сценарий «покупатель заказал → продавец увидел и выполнил» заработал раньше; каталог продавца — до настроек магазина; рабочий день и уведомления (O3, O4) — после бота (S7), от которого зависят уведомления.
