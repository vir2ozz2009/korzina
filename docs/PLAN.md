# План разработки Korzina

Порядок строгий: задача начинается, когда закрыты её зависимости. Каждая задача — одна ветка, один чат Codex (иногда два), результат на demo.
Истории задачи (что должен получить пользователь) — `docs/stories/README.md`, колонка «Задача».
Формат карточки: **Цель** · **Читать** · **Figma** (блоки → `SCREENS.md`) · **Готово, когда**.

Легенда фаз: **F** — фундамент · **B** — покупатель (волна 1) · **S** — продавец управляет магазином (волна 2) · **O** — жизненный цикл заказа (волна 3) · **L** — запуск · **A** — дополнения под флагами (волна 4+).

---

## Фаза F — фундамент (до первого экрана)

Без неё каждая страница будет изобретать своё — это и тормозило Lavka.

### F1 · Чистый каркас
- **Цель:** репозиторий пустой (код удалён 17.11.2026, сохранены `cloudflare.config.ts`, `.node-version`, `.codex/`, `public/brand/korzina.svg`). Создать `package.json` и каркас Vite + React + TS strict + Tailwind v4 + Biome + Vitest + Hono в том же Worker. Скрипты `dev`, `build`, `check`, `check:arch` (CONVENTIONS «Автоматическая проверка»), `deploy`.
- **Читать:** ARCHITECTURE §2–3, CONVENTIONS.
- **Готово, когда:** `npm run check` зелёный; на demo открывается пустая страница Korzina, `GET /api/health` → `{ok:true}`; Workers Builds проходит.

### F2 · Магазины: платформа + Durable Object
- **Цель:** D1 `platform` (shops, domains), DO `Shop` с Drizzle и автоприменением миграций, `resolveShop(host)`, сид из двух магазинов (`lavka`, `test2`).
- **Читать:** ARCHITECTURE §4–5, §8.
- **Готово, когда:** `GET /api/shop` возвращает разные магазины для разных host и `?shop=`; тест изоляции: запись в `lavka` не видна в `test2`.

### F3 · Контракты, ошибки, идемпотентность
- **Цель:** `src/shared/contracts`, `errors.ts`, `money.ts` (+ тесты), Hono RPC-клиент, middleware: request-id, формат ошибок, `Idempotency-Key` (таблица `idempotency` в DO), лимит запросов.
- **Готово, когда:** повтор POST с тем же ключом возвращает тот же ответ, с другим телом — `IDEMPOTENCY_CONFLICT`; `money.ts` покрыт тестами распределения и округления.

### F4 · Сессии и роли
- **Цель:** гостевая сессия, проверка Telegram `initData` (HMAC, срок), вход продавца (Telegram платформы или код на email — заглушка отправки в dev), `memberships`, `requireRole`/`requirePermission`.
- **Читать:** ARCHITECTURE §7, DOMAIN «Роли». Пример проверки initData: Lavka `server/telegram-accounts.mjs` (только как справку).
- **Готово, когда:** тесты: поддельная или просроченная initData отклоняется; сотрудник без права получает `FORBIDDEN`; отозванный доступ гаснет сразу.

### F5 · Флаги функций
- **Цель:** реестр `flags.ts` (`addon`, `rollout`), `feature_overrides`, `requireFeature`, `useFeature`, скрипт `npm run flag`.
- **Готово, когда:** addon выключен по умолчанию, включается для одного магазина, второй его не видит; core без флага.

### F6 · Токены и тема MagicPath
- **Цель:** снять палитру, типографику, радиусы и тени с айдентики и блока 47 → `src/styles/tokens.css`; создать или обновить тему **Korzina** в MagicPath; логотип SVG и иконка в `public/brand/`.
- **Читать:** DESIGN §1–2. **Figma:** айдентика, логотип, блок 47.
- **Готово, когда:** `get-theme Korzina` и `tokens.css` совпадают; таблица токенов в DESIGN.md обновлена.

### F7 · UI-кит + витрина кита
- **Цель:** примитивы из DESIGN §3 в `src/ui`, страница `/dev/kit` со всеми вариантами и состояниями; тот же кит как компонент «Korzina UI Kit» на холсте MagicPath.
- **Figma:** 45, 46, 47, 30 (кнопки, капсула цены, плитки, степпер).
- **Готово, когда:** Андрей одобрил кит на холсте; `/dev/kit` на demo; в фичах нет ни одного hex.

### F8 · Каркас приложения и переходы
- **Цель:** TanStack Router, `Screen`/`Header`/`TabBar`/`QueryBoundary`/`SheetRoute`/`Transition` (push, sheet, tab), адаптер Telegram (viewport, safe-area, BackButton, тема, раскрытие на всю высоту), тосты, восстановление прокрутки, десктоп — колонка по центру.
- **Читать:** DESIGN §4, CONVENTIONS «Экраны».
- **Готово, когда:** три демо-маршрута показывают все виды переходов; «назад» работает жестом, кнопкой браузера и BackButton в Telegram; состояния загрузки, пусто и ошибки демонстрируются на флаге `?simulate=`.

### F9 · Медиа
- **Цель:** загрузка в R2 (подписанный POST через Worker, проверка типа и размера), выдача через Images-ресайз, компонент `<Img>` с `srcset` и плейсхолдером.
- **Готово, когда:** фото до 10 МБ загружается, отдаётся в 3 размерах, чужой магазин не может прочитать приватный файл.

### F10 · CI и превью
- **Цель:** GitHub Action: `npm run check` на PR; превью-версия Worker на ветку; Playwright-заготовка с одним smoke-тестом.
- **Готово, когда:** PR показывает статус проверок и ссылку на превью.

## Фаза B — покупатель покупает (волна 1)

### B1 · Модель каталога + сид
- **Цель:** таблицы categories, brands, products, variants, media; запросы витрины (главная, категория, товар, поиск); сид из Lavka `server/demo-catalog.json` + фото.
- **Читать:** DOMAIN «Каталог».
- **Готово, когда:** API отдаёт каталог с кешем по `catalogVersion`; скрытые и без остатка ведут себя по правилам; тесты.

### B2 · Главная — **Figma 45** (+57 маленькая витрина — позже, A)
- Шапка магазина, поиск, категории, подборки и товары с `PriceCapsule`. Без историй и обложек (они в A).
- **Готово, когда:** на demo главная из серверных данных; загрузка, пусто, ошибка и повтор; переход в товар (`push`) и обратно сохраняет прокрутку.

### B3 · Категории и каталог — **46**
- Дерево категорий, бренды, список товаров категории, фильтр-чипы.

### B4 · Карточка товара и фасовки — **47**
- Галерея с увеличением, выбор фасовки, лимит по остатку, «подробнее» (шторка), поделиться (ссылка на товар магазина), рекомендации.

### B5 · Поиск — **48**
- Поиск по опубликованному каталогу (название, категория, бренд, описание), история запросов на устройстве, пустой результат. Нейропоиск — A.

### B6 · Корзина — **30, 36**
- Серверная корзина с ревизией, оптимистичные изменения, сохранение после перезагрузки и на другом устройстве после входа, предупреждения об изменении цены или наличия.
- **Готово, когда:** тесты: 3 из 2 → 2; конкурентные изменения; гость → вход → слияние.

### B7 · Адрес и зона доставки — **31, 32**
- Ввод адреса + точка на карте (Leaflet + тайлы провайдера), проверка зоны и тариф, самовывоз. Геокодер — по решению D12, до него ручная точка.

### B8 · Время получения — **37**
- Дни и интервалы по расписанию и вместимости магазина, часовой пояс магазина, резерв при оформлении.

### B9 · Вход в корзине — **38**
- Вход через Telegram (deep link → бот → возврат к оформлению), контакт для заказа. Поток уточняется в D01.

### B10 · Проверки и оформление, оплата — **35, 39**
- `quote` → экран проверки → способ оплаты (наличные или инструкция с QR) → `checkout`.
- **Готово, когда:** выполняются T03 и T04 из `system-analysis.md` §12 (тесты API); двойное нажатие даёт один заказ.

### B11 · Заказ после оформления и мои заказы — **40, 44 (частично)**
- Экран «Заказ оформлен», карточка заказа покупателя со статусом, список заказов, отмена в пределах правила.

### B12 · Избранное — **50** · *e2e*
- Гостевое избранное, слияние после входа.
- **Готово, когда:** сквозной Playwright-тест: главная → товар → корзина → адрес → время → оформление → заказ виден в «Моих заказах».
