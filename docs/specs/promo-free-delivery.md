# 12.3 · Бесплатная доставка

## 0. Рамки

[A6](../tasks/A6.md) · [US-A06](../stories/later.md) · [корзина и получение](purchase.md) · [деньги и доплата](money-and-sales.md) · [общая форма и один код](promo-discounts.md) · [контрольные корзины](../progress/block-12-compatibility.md). Продавец управляет автоматическим порогом и самостоятельными кодами доставки. Зоны, адреса, интервалы, тарифы и плательщик приходят из действующих настроек получения.

## 1. Путь

«Акции» → «Продвижение» содержит общий список предложений. «Создать акцию» → «Все виды акций» → «Бесплатная доставка от суммы» создаёт/открывает отдельную автоматическую акцию с порогом и сроком. Её плитка открывает обычную карточку с условиями, результатами, изменением и отключением. Цель «Увеличить сумму заказа» ведёт в ту же форму.

«Создать акцию» → «Промокод» → «Выгода: Бесплатная доставка» использует общую форму промокода, сводку и предпросмотр. Отдельного вложенного создания кодов из автоматической доставки нет. Строку «Способ применения: по промокоду» не показывать: выбранный тип уже определяет этот способ. Несколько кодов действуют независимо, у каждого свой минимум, срок и лимиты; выбор/создание одного не заменяет другие. Возврат сохраняет фильтр, позицию и ввод; сохранённый черновик восстанавливается после перезагрузки. Каждый вход проверяет те же права.

«Ещё» → «Доставка и самовывоз» следует актуальному [shop-settings §12–14](shop-settings.md#12-правки-андрея-после-первой-ревизии-холста-21112026). Здесь базовая цена и получатель оплаты, а не вторая акция. Ссылка на автоматическую доставку открывает ту же запись предложения в «Продвижении», с теми же id/revision. В настройках нет своей независимой копии порога, срока или включённости акции.

Покупатель выбирает адрес и получение в корзине → видит стоимость и остаток до порога → при желании вводит код в общем поле → видит итог магазину → оформляет. Для поздней цены «Мои заказы» открывает тот же заказ с состоянием кода до и после подтверждения тарифа продавцом.

Через цель «Увеличить сумму заказа» пункт «Бесплатная доставка от суммы» открывает те же условия с фокусом на поле порога. Результаты по каждому основанию льготы — по [спецификации результатов](promo-discounts.md#11-результаты-предложения); у действующего порога доступны из его условий, у кода — из его карточки.

## 2. Данные

| Сущность | Серверные значения |
|---|---|
| Предложения продвижения | shopId, id, revision, статус и срок. Автоматическая «Бесплатная доставка от суммы» — отдельная запись с порогом; ссылка из настроек читает эту же запись. Каждый промокод — самостоятельная запись общей сущности с видом выгоды «Бесплатная доставка», необязательным минимумом и личным/общим лимитами. Настройки базовой доставки не дублируют эти поля |
| Контекст получения | Способ, зона, время, кому платят, состояние тарифа (известен / уточняется), стоимость до льготы, стоимость после, сумма до каждого применимого порога. Неизвестная сумма отличается от нуля; базовый тариф и прежние зоны доступны по правилам получения даже при выключенном дополнении |
| Заказ и использование | Снимок версии условий и способа получения, основание автоматической льготы или введённый код, состояние «зарезервирован / применён / освобождён», сумма льготы при известной цене. В историю дописывается решение по тарифу, сохранённый первоначальный расчёт остаётся читаемым |

## 3. Экраны

| Экран / шаблон | Сверху вниз | Нажатие и результат |
|---|---|---|
| Автоматическая акция / общие список, карточка, форма | Название, выгода «Бесплатная доставка», минимум товаров, срок, пример и сводка. Карточка — условия и результаты | Открывается из «Продвижения» и по ссылке из настроек. Изменение/отключение действует на одну запись акции, не меняя базовый тариф и коды. Вложенного списка/создания кодов нет |
| Промокод / общие список, карточка, форма | Название, код, выбор выгоды «Бесплатная доставка», минимум, срок, лимиты, пример, сводка | Общий путь создания промокода без избыточного «Способа применения». Изменение/отключение одного кода не меняет другие и автоматическую акцию |
| Доставка и самовывоз / существующий S4 | «Цена доставки»: бесплатно / фиксированная сумма / посчитаем после заказа; получатель оплаты; «Покупатель увидит»; ссылка к акции | Меняется базовая доставка по действующим правилам зон/получения. Ссылка открывает единственное предложение, не копирует его условия в настройки |
| Пример и корзина / итог | Сумма товаров, «До бесплатной доставки ещё …», тариф либо «Бесплатно», «Промокод», сумма к оплате магазину. Остаток по доступному автоматическому порогу показывать только пока доставка ещё платная. Если введённый код уже обеспечил бесплатную доставку — «Доставка бесплатно по промокоду», без добора до автоматического порога. Недостигнутый минимум введённого кода подписывать рядом с кодом | Адрес, количество, способ или замена кода обновляют расчёт. «Оставить прежний» сохраняет код и сумму; «Заменить код» подтверждает оба новых значения. При неизвестной цене сравнивать только известную часть. Без обеспеченной льготы — «Стоимость доставки уточняется»; при выполненных условиях и оплате магазину — текст обещанной бесплатной доставки ниже |
| Поздний тариф / существующая карточка заказа | У покупателя при действующем резерве — «Доставка будет бесплатной по промокоду», при зафиксированном автоматическом основании — «Доставка будет бесплатной от суммы заказа». У продавца существующее действие назначения стоимости O2, расчёт скидки и итог к доплате | Продавец подтверждает тариф → сервер завершает резерв. При покрытии тарифа видны исходная цена, скидка и «К доплате за доставку 0 ₽». В O5/O5b задача доплаты возникает только на фактический непокрытый остаток |

При неизвестном исходном тарифе эти же тексты обещанной льготы показывать в корзине, только когда сервер подтвердил подходящие условия и оплату доставки магазину; открытая корзина не резервирует применение, оформление повторно проверяет лимит. Не выдавать неизвестный исходный тариф за ноль и не обещать льготу до проверки адреса и условий. Продавец позднее указывает исходный тариф для учёта; при сохранённом основании покупателю доставка покрывается полностью.

Пока адрес не определён — «Выберите адрес, чтобы узнать условия доставки». На самовывозе скрыть добор, для прямой оплаты написать «Доставку оплачиваете курьеру». При уже нулевом тарифе — «Доставка уже бесплатна». Загрузка и пустые настройки — штатные компоненты; при отсутствии сети — «Нет связи» и «Повторить». Поля и значения сохраняются. Смена статуса доступна текстом, касание от 44 px, цифровая клавиатура суммы. Фокус после ошибки возвращается в поле.

## 4. Сервер и команды

Чтение/сохранение автоматической акции и каждого промокода (магазин, id соответствующего предложения, ожидаемая версия его записи, ключ повтора) проверяет флаг, роль владельца/управляющего, доступность доставки, валюту и принадлежность кода. Изменение условий из любого входа атомарно обновляет соответствующую запись с автором и временем. У кода своя запись и ревизия; изменение одного предложения не заменяет и не выключает другие. Изменение базового тарифа/зоны остаётся в настройках доставки. В открытой корзине перечитать расчёт при смене адреса, способа, времени, суммы, плательщика, тарифа и версии условий. Льгота не делает недоступный адрес или интервал доступным.

Оформление B10 проверяет доступное число применений с учётом действующих резервов. Записать резерв вместе с заказом, только если код подходит, льгота не обеспечена автоматически и клиент платит за доставку магазину. При известной положительной скидке сразу записать расход. Предпросмотр и открытая корзина не занимают лимит. Изоляция и бюджет горячего пути — как в [12.1](promo-discounts.md).

Подтверждение тарифа O2 принимает заказ, версию и ключ повтора, проверяет права текущего сотрудника на это действие. В одной операции записать тариф, результат резерва, фактическую сумму к оплате и событие для денежных экранов. Не перепроверять текущий срок или новую редакцию акции для ранее подтверждённого резерва. При одновременной отмене и вводе тарифа побеждает допустимый переход текущей версии заказа. Повтор или устаревшее событие не возвращает льготу отменённому заказу и не создаёт доплату. Полная отмена до выдачи освобождает резерв либо восстанавливает уже израсходованный код, один раз.

## 5. Ошибки и восстановление

| Условие | Экран и действие |
|---|---|
| Код не для этого магазина / уже использован / исчерпан | Причина рядом с общим полем по правилам 12.1, прежний код при неуспешной замене сохранён |
| Не достигнут минимум | «До бесплатной доставки по коду ещё …». Добавление подходящего товара или удаление кода немедленно меняет известный итог |
| Цена не определена / адрес недоступен | Состояния различимы: уточняемый тариф позволяет оформить по B10; для адреса вне доставки предложить другой адрес или получение |
| Сменились тариф, состав или способ до оформления | Обновить расчёт. При росте суммы — подтверждение B10. При параллельной правке настроек — загрузить текущую версию перед новым сохранением |

Для будущего холста 12.3 использовать ту же композицию реальной корзины, что и в [правках 12.1](promo-discounts.md#13-правки-андрея-к-первому-холсту). Ручной сценарий 24 связывает подпись доставки с известными суммой добора и тарифом. Товарный добор и доставка подписаны каждый у своего условия.

## 6. Правила

1. Порог проверять включая точную границу, по товарам после позиционных скидок и до общей скидки. Сравнивать все допустимые варианты итоговой оплаты с учётом тарифа. Для неизвестной цены явно отделять известную сумму. Автоматический порог не занимает поле промокода.
2. Код доставки совместим с автоматической товарной скидкой. Если тариф уже нулевой или достигнут автоматический порог, код не расходовать и не резервировать. Для самовывоза и прямой оплаты курьеру скидка магазина на доставку неприменима.
3. Поздний положительный тариф магазину переводит действующий резерв в расход один раз и покрывается им. При нулевом тарифе, отмене либо смене на самовывоз или прямую оплату курьеру — освободить. Для заказа с достигнутым автоматическим порогом зафиксировать его основание, поздний тариф покрывается без резерва кода.
4. История заказа и сумма возврата берутся из оплаченных строк и действующих согласованных изменений заказа. Поздний тариф в деньгах отделён от цены товаров, в отчёте товара отражается его оплаченная доля. В общей выручке O9 учитывается также фактически начисленная доставка магазина по правилам §6 П3 блока 11; покрытая доставка даёт 0, прямой платёж курьеру исключён. Если снятие позиции уже уменьшило сумму выполненного заказа, последующий денежный возврат той же разницы не вычитается из выручки повторно.

| № | Дано → действие → результат | Где |
|---|---|---|
| 1 | Акция открыта из «Продвижения» и по ссылке из «Ещё → Доставка и самовывоз» → сохранение обновило одну запись, второй вход показывает ту же ревизию; устаревшее сохранение отклонено. Отключить автоматическую акцию → базовый тариф и коды сохраняются | холст, сервер-тест, smoke |

| 3 | Автоматически от 1 500 ₽, по коду от 800 ₽, платная доставка магазину → на 799 ₽ не хватает 1 ₽ для кода; на 800 ₽ код применим; на 1 499 ₽ бесплатна лишь с кодом, на 1 500 ₽ автоматически. Нулевой тариф сам по себе не тратит код | холст, сервер-тест |
| 4 | Смена ЗАВТРАК → ДОСТАВКА в [примере](../progress/block-12-preparation.md) → показать 620 и 530 ₽ до замены. Удалить код → 650 ₽. Отменить замену → 620 ₽ | холст, smoke |
| 5 | Набор 320 + другой товар 150 + тариф 120 → 590 ₽. Автоматическое 2+1 даёт 350 + 150 и бесплатную доставку от 500 → 500 ₽. Выбран итог 500 ₽, введённый код остаётся без расхода | холст, сервер-тест |
| 6 | До оформления тариф неизвестен, осталось одно применение → одна из двух покупок резервирует, вторая получает свежий расчёт. Срок кода прошёл → тариф 120 ₽ подтверждён дважды → скидка 120 ₽, один расход, доплата 0 ₽ | холст, сервер-тест, smoke |
| 7 | Повторить сценарий с нулевым тарифом, полной отменой, самовывозом и прямой оплатой → резерв освобождён один раз. В том же магазине лимит снова доступен, при истёкшем сроке новый заказ код не применит | сервер-тест |
| 8 | Положительная доставка оплачивается напрямую курьеру → видна подпись получателя. В «Деньгах» сумма к получению магазином исключает эту доставку. При полном возврате до выдачи восстановление лимита привязано к отмене заказа | холст, smoke |
| 9 | Бесплатно от 600 ₽. В открытой корзине убрать товар за 50 ₽ → 550 + 120 = 670 ₽. В уже оформленном заказе на 600 ₽ этот товар убирает магазин → 550 ₽, доставка 0 ₽. Денежные экраны видят уменьшение на 50 ₽ | холст, сервер-тест, smoke |
| 10 | Порог достигнут, ручной код тоже введён → один выполненный заказ с автоматической льготой и ноль применений кода. Если сам исходный тариф равен нулю, предоставленная скидка равна нулю и заказ не попадает в результаты обеих акций | холст, сервер-тест |
| 11 | Через общее создание промокода выбрать выгоду доставки и создать два кода с разными условиями → оба доступны в общем списке; в автоматической акции вложенного создания нет. Изменить/отключить один → второй и автоматический порог сохранены. У покупателя по-прежнему один введённый код, замена — по сценарию 4 | холст, сервер-тест, smoke |
| 12 | Автоматический порог 1 500 ₽, код доставки от 800 ₽, товары 800 ₽, тариф 120 ₽ → «Доставка бесплатно по промокоду», без добора до 1 500 ₽. Удалить код → тариф 120 ₽ и добор 700 ₽. При 799 ₽ недостающий 1 ₽ по коду указан рядом с кодом | холст, сервер-тест |
| 13 | Адрес доступен, доставка оплачивается магазину, исходный тариф неизвестен. При выполненных условиях кода — «Доставка будет бесплатной по промокоду», при автоматическом основании — «Доставка будет бесплатной от суммы заказа». После оформления сохраняется соответствующий резерв/основание; подтвердить тариф 120 ₽ → покупателю доставка 0 ₽. Без льготы — «Стоимость доставки уточняется»; без адреса, при самовывозе/прямой оплате обещание не показывается | холст, сервер-тест, smoke |

## 8. Не входит

Новые зоны, слоты и способы получения (блок 7), переводы курьеру, новая платёжная операция и сводный отчёт по всем кампаниям. При реализации переиспользовать существующие денежные сценарии O2/O5/O5b.

## 9. Решения и передача

Резерв при позднем тарифе и восстановление лимита при полной отмене согласованы 25.11.2026.

27.11.2026 Андрей: «Одобряю спецификацию 12.3 с тремя рекомендованными уточнениями. Зафиксируй их и подготовь задание на холст».

1. Несколько самостоятельных кодов доставки у продавца; вход в существующий список, без единственного выбранного кода магазина. Покупатель вводит один код (§1–4, сценарий 11).
2. Код уже обеспечил бесплатную доставку → скрыть добор до автоматического порога; недостигнутое условие кода остаётся рядом с кодом (§3, сценарий 12).

## 12. Правка Андрея · основания льготы и пути продвижения · 27.11.2026

Этот раздел уточняет §1–6 и имеет приоритет над историческим устройством входов в прежних ревизиях. Реализация приложения не разрешена; обновляются спецификация и холст.

### Три независимых основания

1. **Базовый тариф** приходит из S4: бесплатно, фиксированная сумма или расчёт после заказа. Применяются действующие зона, адрес, способ и получатель оплаты; поздние правки shop-settings §12.2–12.3, §13.1 и §14 не отменяются. Минимальная сумма заказа S4 — отдельное условие оформления, не порог акции доставки.
2. **Автоматическая акция** — отдельное предложение «Бесплатная доставка от суммы» в общем «Продвижении», с собственными условиями/сроком. Срабатывает только при выполнении суммы и срока. Настройки могут открыть ту же запись по ссылке, но не хранить независимый порог/срок/статус.
3. **Льгота по коду** — выгода «Бесплатная доставка» в общем промокоде. Требуется непустой фактически введённый/подставленный код, его подходящий минимум и срок. Пустой черновик, ранее открытый редактор и скрытые настройки другого примера не являются введённым кодом.

При исходном тарифе 0 ₽ показывать «Доставка уже бесплатна»: нет предоставленной скидки акции, расхода/резерва кода и результата кампании. Не приписывать ноль автоматической акции даже при достигнутом пороге. Неизвестный тариф не равен нулю: при подходящих условиях обещание бесплатной доставки сохраняется по §9.

### Чистое состояние предпросмотра

Каждый вход создаёт новый снимок текущего выбранного предложения и контекста базовой доставки. Автоматический пример начинается без кода и не получает предложение из редактора промокода. Пример конкретного кода явно показывает подставленный непустой код в штатном поле. Минимумы и сроки проверяются по снимку этого предложения; начавшийся сегодня/заканчивающийся сегодня срок включителен в часовом поясе магазина. Предпросмотр черновика допускает проверку его условий, но не игнорирование дат. Повторный вход не наследует изменённую учебную дату/состав/код другого примера.

Общий список, карточки, формы, поля и действия — по «Продвижению» `476543507985739776`; различаются только факты текущего вида акции. Настоящую корзину без выбранного адреса не менять. Изоляция приложения, лимиты и серверные повторы остаются будущими проверками, как и отдельный PROMO-EXAMPLE-TRANSFER.
