# Спецификация · Блок 6 · Каталог продавца

## 0. Рамки

- S2 — товары, фасовки, остатки и фото. S3 — категории, подкатегории и бренды. Критерии — [US-M02–M04](../stories/seller-store.md#us-m02--товары).
- Основа — карточки [S2](../tasks/S2.md) и [S3](../tasks/S3.md), [DOMAIN](../DOMAIN.md#каталог-4), решения Андрея от 20.11.2026 в [DECISIONS](../DECISIONS.md#принятые), действующие кабинет продавца и витрина. Решения 1–6 в §9 имеют приоритет над прежними формулировками карточек.
- На раздел уже влияют валюта магазина для всех цен, правило `hideOutOfStock` для покупательской выдачи и доступ сотрудника к каталогу. Настройка этих параметров остаётся в своих задачах. Источники — [DOMAIN «Роли»](../DOMAIN.md#роли) и [S6](../tasks/S6.md).

## 1. Путь

- Кабинет → нижняя вкладка «Товары» → переключатель «Товары · Категории · Бренды». Переключение заменяет содержимое корня вкладки. Вариант по умолчанию — «Товары». Используем корни `/seller/products`, `/seller/categories`, `/seller/brands` из [navigation.md](../design-system/navigation.md#кабинет--товары).
- Список товаров → «Добавить товар» или строка → форма (`push`, `/seller/products/new` или `/seller/products/$id`). Цена и остаток одной фасовки находятся в общей форме. При нескольких фасовках форма содержит их список, а «+ фасовка» и строка фасовки открывают редактор (`push` в рамках того же черновика). Ввод редактора возвращается в форму товара, общий «Сохранить» отправляет команду товара. Кадрирование, просмотр фото и подтверждения открываются через шаблон `feedback`.
- Поле «Категория» → список выбора → «Создать категорию» открывает ту же форму категории, что S3. После сохранения категории её ID выбран в форме товара. После отмены сохраняются прежний выбор и остальные поля товара. Сохранённая категория существует отдельно от черновика товара.
- Категории → категория → «Подкатегории» (`push`, список в контексте родителя) или «Товары категории» (`push`, список S2 с фиксированным фильтром категории). Бренды → бренд → «Товары бренда» (`push`, список S2 с фильтром бренда). Перенос при удалении — шторка из формы категории или бренда.
- «Посмотреть на витрине» открывает существующий покупательский экран с сохранёнными данными. Если для сущности доступен только предпросмотр, его правила и ссылку согласовать в §10. Возврат восстанавливает форму и её черновик.
- «Назад» в списках восстанавливает раздел, запрос, фильтр и прокрутку. В URL сохраняются раздел, запрос, фильтр и контекст магазина. Смена магазина сбрасывает контекст списка и открытые записи. Форма с правками защищена подтверждением выхода, включая смену магазина. После перезагрузки открывается подтверждённое сервером состояние. Черновик живёт в текущем сеансе формы. Прямой URL существующей записи читает её после проверки прав и магазина. Вложенный редактор фасовки открывается из общей формы, ссылка без её черновика возвращает в форму товара.

## 2. Данные и команды

Имена контрактов ниже предлагаются для `src/shared/contracts/seller-catalog.ts`. Поля покупательских ответов переиспользуются по смыслу из [catalog.ts](../../src/shared/contracts/catalog.ts), изображения — из [media.ts](../../src/shared/contracts/media.ts). Ответы кабинета включают скрытые записи и проверяются отдельно от публичного API.

| Контракт | Поля, которые нужны экрану | Когда читать |
|---|---|---|
| `SellerCatalogAccess` | Активный магазин, права чтения и изменения, валюта | При входе, смене магазина и смене доступа. Клиент не определяет права по роли самостоятельно |
| `SellerProductPage` | Строки `{id, name, image, priceSummary, stockSummary, availability, visibility, revision}`, непрозрачный `nextCursor`, версия выборки. Цена — целые minor units, остаток — число или явно указанный сервером смешанный режим | Первый экран, смена поиска/фильтра/магазина, загрузка страницы. Сервер вычисляет сводки и отбор. Правила сводок — §10 |
| `SellerProduct` | ID, ревизия, название, описание, состав и хранение, ID категории, ID бренда или `null`, видимость, режим рекомендаций `auto \| off`, упорядоченные фото с ID и параметрами кадра, фасовки | При открытии карточки и после изменения соответствующей записи. При фоновом обновлении введённое остаётся в форме |
| `SellerVariant` | ID существующей фасовки, название, цена, старая цена или `null`, видимость, `stock: number \| null`, серверная версия остатка | В составе товара. `null` означает «Без лимита», 0 — «Нет в наличии». Цены и доступность подтверждает сервер |
| `SellerCatalogSection` | ID, название, видимость, позиция, ID родителя для категории, фото или `null`, ревизия; в форме и при удалении — актуальное наличие товаров | Список раздела, форма или выбор значения. Дочерние категории читаются по родителю |
| `SellerStockConflict` | ID фасовки, исходный и текущий остаток, текущая версия, количество купленных штук при подтверждённой покупке, ревизия сохранённых полей товара | В ответе на частичное сохранение. Та же версия выявляет смену остатка даже при совпадении исходного и текущего числа. После подтверждения перечитываются только затронутые товар и строки списка |

Список товаров принимает `q`, `filter: all \| out_of_stock \| low_stock \| hidden`, необязательную категорию или бренд и курсор. Курсор связан с магазином, параметрами и версией выборки. «Все» включает скрытые и закончившиеся товары. Фасовки без лимита сами по себе не делают товар заканчивающимся. Скрытая фасовка не участвует в расчёте доступности. Устаревший курсор обновляет список с начала с сохранением фильтров. В API цену передаём целым неотрицательным числом в минимальных единицах валюты, остаток — целым неотрицательным числом или `null`. Для ранее созданных товаров значения новых необязательных полей пустые, рекомендации остаются автоматическими.

| Операция | Вход | Результат |
|---|---|---|
| Чтение товаров, категорий и брендов | Действующий контекст магазина, фильтр/запрос/курсор или ID | Страница, форма или краткий список выбора. При совпадении версии неизменившиеся строки повторно не читаются |
| Создать товар / сохранить товар | Общая форма, ревизия при редактировании, базовые версии остатков. Для новых фото — ID F9 | Сохранённый товар и актуальная ревизия. При расхождении остатков — сохранённые поля и список конфликтов §4.2 |
| Изменить видимость / массово изменить наличие | ID с ожидаемыми ревизиями; для наличия — выбранные SKU, режим или число и их версии | Серверные состояния затронутых строк. Смена видимости из формы проходит через её «Сохранить» |
| Подтвердить остаток | ID товара, ID фасовок, явно выбранный остаток и показанные сервером версии | Актуальные остатки либо новый конфликт |
| Удалить товар | ID и ревизия | ID удалённого товара, новая версия каталога |
| Создать / сохранить / изменить порядок категории или бренда | Поля формы, ID родителя для подкатегории, ID текущих записей и ревизия, порядок соседей для категорий | Запись или новый порядок. Создание из карточки товара возвращает ID для выбора |
| Удалить категорию или бренд | ID и ревизия, ID назначения или явное «Без бренда» | Новая версия каталога, число перенесённых товаров или `NOT_EMPTY` |
| Загрузить фото | Файл и назначение по F9 | ID временного фото, метаданные и прогресс загрузки. При сохранении формы файл привязывается к сущности |

На команду — `Idempotency-Key`. Повтор с тем же ключом и входом возвращает тот же результат, включая частично сохранённый товар. Исправленный ввод, выбранный перенос или новый выбор остатка — новая команда с новым ключом. Ошибки и статусы см. §5.

## 3. Экраны

Общие состояния для всех запросов и форм перечислены в §3.9. Вид — по шаблонам [DESIGN](../DESIGN.md) и [design-system/templates](../design-system/templates.md). ### 3.3 Фасовка

Шаблон `form`. В шапке «Новая фасовка» / «Редактировать фасовку». `Input` «Название фасовки», «Цена», «Старая цена», «Остаток», `Switch` «Без лимита», «Показывать фасовку», затем «Готово» и «Отменить». «Готово» валидирует поля в общем черновике и возвращает к товару, «Отменить» возвращает без записи правок этого редактора. Запросов нет. Во время сохранения товара редактор недоступен. Ошибка дубликата показывается у поля: «Фасовка с таким названием уже есть». Неприменимые к локальному редактору сетевые состояния показаны у формы товара. Правило имени единственной фасовки и переходы между одной и несколькими — §10.

### 3.4 Наличие и конфликт остатка

Шаблон `feedback`. Массовый режим: «Изменить наличие», список выбранных товаров и фасовок с остатками, «Нет в наличии», «В наличии», ввод нового остатка там, где он требуется (§10), «Применить» и «Отменить». «Применить» отправляет изменения выбранных фасовок с версиями. В процессе заблокированы изменение выбора и повтор. Успех — «Наличие обновлено» и обновление списка. Если данные изменились, шторка показывает актуальные остатки и просит подтвердить заново.

Для конфликта при сохранении товара `Sheet` показывает «Уточните остаток», «Остальные изменения сохранены», имя каждой конфликтующей фасовки, «Пока вы редактировали, купили N шт. Сейчас осталось M», поле «Остаток», «Сохранить остаток», «Оставить текущий». Число подставляет сервер. Если остаток изменило другое действие, текст — «Остаток изменился. Сейчас осталось M» или «Сейчас остаток без лимита». Текст «Остаток изменил другой сотрудник» показывается, когда источник подтверждён. Оставить текущий — принять серверный остаток без записи. «Сохранить остаток» требует явного выбора и отправляет только остатки с показанными версиями. Пока команда идёт, блокируются повтор и изменение ввода. При новом конфликте остаются введённое число и свежий остаток. При закрытии шторки форма возвращает к сравнению с текущими данными и не выполняет запись.

### 3.5 Категории, подкатегории и бренды

Шаблон `list`. Сверху: `Header` «Категории» / «Бренды» или «Подкатегории» и название родителя; в корне — переключатель разделов. Строки `ListItem` показывают имя и «На витрине» / «Скрыта на витрине» для категории, «На витрине» / «Скрыт на витрине» для бренда. Для категории — `CategoryPhoto` с правилами F11; для бренда — `BrandTile` с логотипом или инициалами. Кнопка «Добавить категорию» / «Добавить подкатегорию» / «Добавить бренд» доступна с правом записи.

Строка или «Добавить» открывает §3.6. Для категорий перетаскивание либо «Выше» / «Ниже» отправляет порядок среди соседей одного родителя, повтор и другие перестановки этой группы блокируются до ответа. При конфликте показывается «Порядок изменился. Обновите список», «Обновить» перечитывает порядок, при сетевой ошибке список восстанавливает последний подтверждённый порядок. Пусто — «Категорий пока нет», «Подкатегорий пока нет», «Брендов пока нет» с соответствующим действием создания.

### 3.6 Категория, подкатегория, бренд

Шаблон `form`. `Header` «Новая категория» / «Редактировать категорию», «Новая подкатегория» / «Редактировать подкатегорию», «Новый бренд» / «Редактировать бренд». Затем `Input` «Название», `Switch` «Показывать на витрине», `PhotoPicker` «Фото категории» или «Логотип бренда». Без отдельного фото категории показывается предпросмотр фотографии первого товара, при её отсутствии — символ категории. Без логотипа бренда — инициалы. Под сохранённой категорией — «Подкатегории» и «Товары категории», под сохранённым брендом — «Товары бренда». В форме — «Посмотреть на витрине», «Удалить категорию» / «Удалить бренд», общая полоса сохранения §3.2.

| Действие | Результат и запрос | Блокировка |
|---|---|---|
| Изменить название и видимость, добавить или убрать фото | Название и видимость в черновике. F9 загружает файл, рамка F11 редактируется в предпросмотре | Сохранение до конца загрузки |
| «Сохранить» / «Отменить» | Команда S3 или подтверждение ухода с правками. Успех — «Сохранено», возврат в исходный список или к выбору категории в товаре | Форма и повтор отправки до ответа |
| «Подкатегории» / «Товары категории» / «Товары бренда» | `push` и чтение списка с контекстом записи. Уход с правками использует подтверждение §3.2 | На время сохранения |
| «Посмотреть на витрине» / «Удалить…» | §3.8 / §3.7. Удаление доступно с правом записи у сохранённой записи | На время сохранения |

Частные состояния: «Введите название», «У категории пока нет товаров», «Фото первого товара», «Инициалы вместо логотипа», «Скрыто на витрине». Применимы ошибки файла из §3.2.

### 3.7 Удаление и перенос

Шаблон `feedback`. `Dialog` «Удалить товар?» → «Товар исчезнет из каталога и витрины. Оформленные заказы сохранятся», «Отменить», «Удалить товар». Успех — «Товар удалён» и возврат в список.

Для категории/бренда шторка «Удалить категорию?» / «Удалить бренд?». При наличии товаров — «Выберите, куда перенести товары», `Select` «Категория для переноса» / «Бренд для переноса», в брендах опция «Без бренда», затем «Перенести и удалить». Для пустой группы — «Удалить» и «Отменить». Список назначений загружается при открытии, удаляемая группа исключена. «Нет доступных категорий для переноса» блокирует «Перенести и удалить», «Отменить» доступно. При появлении товарных связей между чтением и удалением сервер возвращает `NOT_EMPTY` и открывается выбор переноса. Невалидное назначение — «Выберите другое место переноса». Пока идёт команда, блокируются повтор и изменение выбора. Сетевой повтор использует тот же ключ. Успех — «Категория удалена» / «Бренд удалён». Случай категории с подкатегориями — §10.

### 3.8 Предпросмотр карточки товара, категории и бренда

Переиспользуются покупательские шаблоны `product` и `catalog` с теми же заголовками, фото и данными. Действие из кабинета — «Посмотреть на витрине». «Назад» возвращает к исходному экрану. Чтение при открытии; до ответа виден скелетон шаблона, при 5xx или сети — «Не удалось открыть витрину», «Повторить». У пустой категории/бренда — штатное пустое состояние витрины. Для недоступного публичного URL — «Не видно на витрине». Отдельный продавецкий предпросмотр и интерактивность на скрытых записях — §10.

## 4. Серверные правила

### 4.1 Доступ, чтение и кеш

Каждый запрос проверяет сессию и активное членство в выбранном магазине. Команда дополнительно проверяет право записи до чтения или изменения целевой записи. Все ID, версии, фото и связи принадлежат этому магазину. При отзыве доступа запись запрещена сразу. Поиск и фильтры серверные, с индексом и устойчивой сортировкой страниц. Категории и бренды не загружаются вместе со всеми товарами. Список возвращает данные строки, полные фасовки и фото читаются для открытого товара или выбранной группы массового действия. Учитываются текущие скрытые записи и данные, созданные до S2/S3.

Успешная команда обновляет нужную ревизию и зависимые проекции каталога, корзины и поиска в той же транзакции, где меняются исходные данные. Версии и точечная инвалидация по [PERFORMANCE §2](../PERFORMANCE.md#2-каталог-и-публичные-данные) дают следующий актуальный ответ без повторного чтения неизменившихся данных. При изменении только остатка обновляется оперативная доступность. Приватные ответы кабинета не попадают в публичный кеш.

### 4.2 Товар, фасовка и остаток

1. Сохранение проверяет обязательные поля, связи, цены, наличие хотя бы одной фасовки, ID фасовок и допустимость фото F9. Названия фасовок уникальны по правилу DOMAIN. Цена и старая цена существуют только у SKU. Правки вступают в силу сразу по текущим правилам публикации и видимости.
2. Версия редактируемых полей отделяется от версии остатка. Изменение полей другим сотрудником даёт `VERSION_CONFLICT`, форма остаётся доступной для сверки. Покупка и возврат меняют версию остатка. Неизменённое продавцом поле остатка не записывается поверх свежего значения.
3. При изменении остатка после открытия формы сравнение и запись выполняются атомарно с checkout и возвратом. При покупке остальные валидные поля сохраняются, конфликтующие остатки сохраняют серверное значение, клиент получает список конфликтов. Количество купленных штук определяется по подтверждённым изменениям заказа после исходной версии, с учётом того, что возврат и ручная правка тоже меняют остаток. Если точный источник отдельно не подтверждён, ответ сообщает актуальный остаток без утверждения о покупке. Явное подтверждение снова сравнивает версию. Две покупки или покупка после показа конфликта не ведут к тихой перезаписи и отрицательному остатку.
4. Массовая команда валидирует выбранные фасовки и версии до применения. Предложение для ревью: при конфликте любой строки показать свежие значения до записи пачки, чтобы подтверждённое списание не затерялось. Подробности действий «В наличии» — §10.
5. Привязка фото/порядка/кадра коммитится с товаром. Используем ограничения, права и уборку F9, правила размеров и показа F11. Неудачное сохранение не прикрепляет незаписанные фото к товару.
6. При «Выключены» карточка товара не отдаёт блок рекомендаций. «Автоматически» использует текущие рекомендации каталога с теми же правилами видимости и доступности. Уже существующие товары сохраняют прежнее поведение.

### 4.3 Удаление, связи и видимость

- Удалённый товар и его SKU перестают быть доступны из списков, поиска, прямой карточки, рекомендаций и покупки. Существующая корзина и «Повторить заказ» применяют действующие правила недоступных SKU. Снимки оформленных заказов у покупателя и продавца читаются независимо от живой записи. Имя, фасовка, цена и количество читаются из снимка. Срок хранения изображений, на которые ещё ссылается заказ, требуется согласовать в §10 с правилом уборки F9. Возврат остатков по старому заказу не восстанавливает удалённый товар.
- Перенос всех затронутых товаров и удаление группы происходят в одной транзакции. Место переноса должно быть существующим и допустимым в том же магазине. Если при сохранении цель исчезла или стала недопустимой, исходная группа и её товары сохраняются. При удалении бренда `null` означает явное «Без бренда». Для категории с товарами нужна другая категория. Правило для подкатегорий — §10.
- Категории и бренды при выключении остаются доступны в кабинете. Выключенная категория отсутствует в навигации и поиске витрины. Что происходит с самими товарами и прямыми ссылками при выключении группы — §10. Порядок категорий в кабинете, после фильтрации видимости, совпадает с витриной.
- Команды и частичные ответы используют действующий механизм повторов Shop DO. Изменение каталога не создаёт Telegram-уведомления. Внешние вызовы при сохранении формы не нужны, загрузка файлов идёт отдельно через F9.

### 4.4 Бюджеты

Сохраняем действующие бюджеты публичного каталога, карточки товара, корзины и checkout по [PERFORMANCE §6](../PERFORMANCE.md#6-измерение-и-бюджеты). Для нового списка товаров замеряем с обычным и почти пустым фильтром и несколькими страницами: SQL на страницу и число чтений не должны расти из-за отдельного запроса на каждую строку. Прогоняем бюджетные тесты публичных сценариев и добавляем бюджет для продавецкого списка с числом SQL и строк по замеру реализации. Порядок, массовое наличие и перенос проверяем на пакетных операциях.

## 5. Ошибки сервера → поведение экрана

| Код / результат | Где | Что видит продавец | Что сохраняется и что сделать |
|---|---|---|---|
| `VALIDATION` | Форма, назначение переноса, остаток | Текст у поля из §3, «Проверьте выделенные поля» | Весь черновик. Исправить и подтвердить |
| `DUPLICATE_VARIANT_NAME` | Товар/фасовка | «Фасовка с таким названием уже есть» | Весь черновик. Фокус на дубликате |
| `VERSION_CONFLICT` | Запись или порядок изменены | «Данные изменились» или конфликт порядка §3.5 | Введённое сохраняется. «Обновить» получает свежие данные |
| Сохранено частично / конфликт подтверждения остатка | Сохранение товара или остатка | Шторка §3.4 | Поля, подтверждённые сервером, сохранены. Уточнить только конфликтующий остаток |
| `NOT_EMPTY` | Удаление группы без допустимого переноса | «Выберите, куда перенести товары» | Группа и товары без изменений. Выбрать назначение |
| `NOT_FOUND` | Запись удалена, либо ID недоступен в магазине | Сообщение §3.9 | До ухода форма может показать локальные данные без записи. Вернуться в список |
| 401 / 403 | Сессия, членство, доступ | Сообщение §3.9 | Запись не сделана, доступное состояние перезагружается после входа. Автоповтор отключён |
| `STORAGE_LIMIT`, недопустимый файл | F9 / предпросмотр | Сообщения фото из §3.2 | Остальные поля и успешные загрузки сохраняются в черновике |
| Сеть / 5xx | Чтение или команда | Сообщения §3.9 | Повтор команды с тем же ключом, ввод остаётся |

## 6. Инварианты

- **П1.** SKU — единственный источник цены и остатка. Скрытая фасовка не предлагается и не добавляется через API корзины. [DOMAIN «Каталог»](../DOMAIN.md#каталог-4)
- **П2.** Изменение цены, перенос или удаление товара не переписывает снимки заказов. [DOMAIN «Оформление»](../DOMAIN.md#оформление-5-t03t04)
- **П3.** Каталог и запись ограничены магазином и текущими правами. [DOMAIN «Роли»](../DOMAIN.md#роли)
- **П4.** Порядок фото определяет обложку, кадр не уничтожает исходник. [Фото §2–3](../design-system/photos.md#2-показ-f11-одобрено-19112026)
- **П5.** Гонки остатка проверяются в момент записи. Продавец выбирает новое число после показа факта изменения. См. §9.4.
- **П6.** Публичная выдача отражает сохранённое состояние с соблюдением версий каталога. [PERFORMANCE §2](../PERFORMANCE.md#2-каталог-и-публичные-данные)

| Валидация и конфликт | Сохранить одинаковые нормализованные имена фасовок или устаревшую ревизию → сервер возвращает ошибку, ввод остаётся в форме | сервер-тест, холст |

## 9. Решения Андрея от 20.11.2026

Источник для всех шести пунктов — [S2](../tasks/S2.md) и строка о блоке 6 в [DECISIONS](../DECISIONS.md#принятые).

1. **§9.1 · Навигация.** Нижняя вкладка «Товары» с тремя разделами (§1, §3.1, §3.5).
2. **§9.2 · Фильтры.** «Все · Нет в наличии · Заканчиваются · Скрытые». Порог для видимой конечной фасовки — 5 шт. включительно. Пересечение с нулевым остатком и скрытыми товарами — на согласовании в §10.
3. **§9.3 · Удаление.** Заказ сохраняет снимок, удаление категории/бренда с товарами выполняется с переносом (§3.7, §4.3).
4. **§9.4 · Остаток.** Покупка во время редактирования требует сверки остатка. Остальные поля сохраняются (§3.4, §4.2).
5. **§9.5 · Цена.** Цена и старая цена находятся у фасовки. Единственная фасовка редактируется непосредственно в форме (§3.2, §4.2).
6. **§9.6 · Рекомендации.** Автоматически или выключены (§3.2, §4.2).

## 11. Ответы Андрея на §10 (20.11.2026)

Этот раздел главнее §10 и прежних формулировок карточек S2, S3. Каждый пункт — тест правила с номером в названии.

1. **§11.1 · «Заканчиваются».** Товары с остатком от 1 до 5 шт. у видимой конечной фасовки. Товар с нулём — только в «Нет в наличии», пересечения нет. Скрытые товары тоже участвуют в фильтрах остатка. Строка списка: при нескольких фасовках цена «от X ₽», пометка — по самой дефицитной видимой фасовке.
2. **§11.2 · «В наличии» после нуля.** Окно «Сколько есть?»: поле числа и кнопка «Без лимита». Прежнее число не восстанавливается само.
3. **§11.3 · Выключенная категория или бренд.** Скрывается только вход группы: плитка и страница категории, подкатегории выключенной категории, страница и фильтр бренда. **Товары остаются на витрине, в поиске, в общих списках, по прямой ссылке и продаются.** Тест: товар выключенной категории и выключенного бренда находится поиском и попадает в корзину и заказ, а категория и бренд в навигации не видны. Карточка S3 («выключенная категория скрыта вместе с входами») читается только так.
4. **§11.4 · Удаление категории с подкатегориями.** Подкатегории удаляются вместе с ней. Все товары категории и её подкатегорий переносятся в одну категорию, которую выбирает продавец (любая оставшаяся категория или подкатегория). Одна транзакция, без потерь товаров (тест).
5. **§11.5 · Название фасовки.** Пока фасовка одна — названия нет (поле не показывается). При добавлении второй форма просит назвать обе; без названий сохранить нельзя, повтор названия — ошибка у поля.
6. **§11.6 · «Посмотреть на витрине».** Только у сохранённого видимого товара, категории или бренда. У скрытых и несохранённых кнопки нет. Отдельного предпросмотра не делаем.
7. **§11.7 · Права.** Одно право «Товары» (`products`) на чтение, изменение, видимость, остатки и удаление товаров, категорий и брендов. Без права — только просмотр (если есть доступ к кабинету) или «Нет доступа».
8. **§11.8 · Фото удалённого товара.** Файл хранится, пока на товар ссылается хотя бы один заказ. Уборка F9 через 30 дней не трогает такие фото (тест).

2. **§12.2 · Раздел «Витрина» и размер плиток категорий.** В кабинете отдельный раздел **«Витрина»** (Ещё → «Витрина»), не во вкладке «Товары».
