После перезагрузки сервер восстанавливает заказ, открытое согласование и историю. Локальный выбор сохраняется при переходе в дочернюю шторку и назад. При неизвестном результате восстанавливается та же попытка по её ключу. Черновик сообщений — §3.7.

## 2. Данные и команды

Базовые типы переиспользуются из [buyer-order.ts](../../src/shared/contracts/buyer-order.ts), [seller-order.ts](../../src/shared/contracts/seller-order.ts), [receiving-time.ts](../../src/shared/contracts/receiving-time.ts), [media.ts](../../src/shared/contracts/media.ts) и [staff.ts](../../src/shared/contracts/staff.ts). Имена новых типов задают контракт спецификации. Деньги — целые минимальные единицы с валютой. Сроки задаёт сервер. Даты и окна получения отображаются в часовом поясе магазина.

| Сущность | Поля и типы | Чтение и обновление |
| --- | --- | --- |
| `BuyerOrder` / `SellerOrder` | Номер, этап, версия / ревизия, снимок строк и расчёта, `TimeChoice` или отсутствие времени; доступные действия, краткое активное согласование и итог применённой правки. Финансовые поля продавца по действующим правам. | В текущем запросе заказа. Главная получает ссылку на O6 в виджете `ActiveOrders` с его ревизией. |
| `OrderChange` | ID, номер заказа, вид `composition` / `time`, сторона автора, статус согласования, время создания, срок O6 или `null` у O7. Решение и результат хранят автора и время. | Сводка в заказе, детали по ID при открытии. История через события заказа и карточки O8. |
| `CompositionChange` / `CompositionQuote` | ID строк, вид `remove` / `decrease` / `replace` / `add`, «было» и «стало» (товар, фасовка, количество, цена), допустимое количество, решения. Расчёт: прежний и новый итог, подтверждённая оплата, доплата либо возврат, валюта, идентификатор сверки. | Одна сверка для набора строк. Смена выбора, цены или остатка требует новой сверки. |
| `TimeChange` | Способ получения, часовой пояс, прежнее и предлагаемое время (`TimeChoice` или состояние согласования B8), инициатор, доступные действия. | По открытию шторки читаются режим B8 и `AvailabilityDay[]`. После потери окна обновляются доступность и состояние согласования. |
| `OrderChatSummary` | Номер заказа, этап, подпись и время последней записи, непрочитанные, признак ожидания ответа, режим записи или чтения. Страница списка содержит курсор. | Список и сохранённый счётчик отдельно для своей стороны. Догрузка по курсору. |
| `OrderChatEntry` | ID, порядок, время, сторона и вид: сообщение (текст, приватный `mediaId` назначения `chat` или оба) либо ссылка на типизированное событие заказа. Страница содержит записи, курсор, доступность записи и позицию чтения. | Последняя страница при входе, старые по курсору, новые после текущей позиции. |

| Операция | Вход → результат | Повтор и ошибки |
| --- | --- | --- |
| Сверить состав | Номер, версия или ревизия; правки продавца либо ID и ответы покупателя → `CompositionQuote`. | Чтение. `STOCK_CHANGED`, `CHANGE_EXPIRED`, `VERSION_CONFLICT`, `FORBIDDEN`. |
| `proposeChanges` | Номер, ревизия, правки, идентификатор сверки → заказ, применённые строки и открытое согласование при необходимости. | Ключ команды. `STOCK_CHANGED`, `QUOTE_CHANGED`, `ANOTHER_CHANGE_PENDING`, `VERSION_CONFLICT`, `FORBIDDEN`, `ORDER_CLOSED`. Режим определяет сервер. |
| `answerChanges` | Номер, ID предложения, версия, решения по строкам и идентификатор сверки → согласование, заказ и итог. | Ключ команды. `CHANGE_EXPIRED`, `STOCK_CHANGED`, `QUOTE_CHANGED`, `VERSION_CONFLICT`, `FORBIDDEN`, `ORDER_CLOSED`. |
| Доступность B8 | Способ получения текущего заказа → режим, дни, окна и часовой пояс. | Чтение. Обновить при `SLOT_TAKEN`. |
| `proposeTime` | Номер, версия или ревизия, выбранное время → предложение магазина или просьба покупателя. | Ключ команды. `SLOT_TAKEN`, `ANOTHER_CHANGE_PENDING`, `VERSION_CONFLICT`, `FORBIDDEN`, `ORDER_CLOSED`. |
| `answerTime` / `withdrawTime` | Номер, ID, версия или ревизия, принятие / иной выбор / отказ либо отзыв автором → действующее время и состояние согласования. | Ключ команды. `SLOT_TAKEN`, `CHANGE_EXPIRED`, `VERSION_CONFLICT`, `FORBIDDEN`, `ORDER_CLOSED`. |
| Список, история, отметка чтения | Курсор списка либо номер заказа и курсор ленты → страница. Номер заказа и последний показанный ID → актуальный счётчик. | Чтение с проверкой доступа. Отметка монотонная и идемпотентная. `FORBIDDEN`, `AUTH_REQUIRED`. |
| `send` | Номер, текст и/или ID завершённой загрузки F9 → сообщение и позиция ленты. | `Idempotency-Key`. `MESSAGE_LIMIT`, `CHAT_CLOSED`, `AUTH_REQUIRED`, `FORBIDDEN`, `VALIDATION`. Ошибки F9 — §5. |

Персональные данные читаются в своём контексте, без общего кеша. После записи клиент использует снимок ответа. Ревизия или live-сигнал обновляет затронутый заказ, список или чат. Цены, итог, доступность и права определяет сервер.

## 3. Экраны

### 3.0 Общие состояния и доступность

| Состояние | Что видно и доступно |
| --- | --- |
| Первое чтение | Скелет шаблона. Действия с незагруженными данными выключены, «Назад» доступно. |
| Пусто | Пояснение из раздела экрана. Возврат доступен. Команда без обязательного выбора выключена. |
| Ошибка чтения | «Не удалось загрузить данные» и «Повторить» для текущего запроса. Ввод и уже показанные данные сохраняются. |
| Нет сети | «Нет подключения к интернету». Ввод сохраняется. Действие с запросом доступно после восстановления связи. |
| Запись / неизвестный исход | Подпись ожидания, конфликтующие действия блокируются. При пропаже ответа «Не удалось проверить результат» / «Проверить» с исходным ключом команды. |
| Данные изменились | Обновить только затронутый заказ или подбор, показать актуальные условия по §5. Совместимый ввод сохраняется. |

Вид по [DESIGN §2–4 и §5а](../DESIGN.md) и [шаблонам](../design-system/templates.md). Порядок элементов и новые подписи ниже — предложения для холста. Области нажатия от 44 px, у иконок доступные названия. Шторка возвращает фокус на открывшее действие, ошибка — на первое неверное поле или сообщение. Поиск использует клавиатуру поиска, количество — числовую, сообщение — многострочную. Нижнее действие в `StickyFooter` остаётся доступным с клавиатурой.

### 3.1 O6 · «Изменить состав» у продавца

Шаблон `form`, вход из O2 с правом «Заказы».

| Сверху вниз | Компонент, данные и текст |
| --- | --- |
| Шапка | `Header`, «Изменить состав», «Заказ №<номер>», «Назад». |
| Позиции | `Card`, `ProductRow`, `Stepper`. «Было» / «Стало», товар и фасовка, количество. Действия «Заменить», «Убрать», после строк «Добавить товар». |
| Сверка | `TotalsBlock`, «Итого было», «Итого станет», при изменении обязательства «К возврату» или «К доплате» по действующим правам. Для замены и добавления «Нужно согласие покупателя», для уменьшения и удаления «Покупатель получит уведомление». |
| Подтверждение | `StickyFooter`, «Сохранить» / «Сохраняем…». Доступно при наличии изменения и актуального расчёта. |

| Действие | Результат и запрос | Блокировка |
| --- | --- | --- |
| «Заменить» / «Добавить товар» | Шторка §3.3 → выбор в редакторе → сверка. | Сохранение до сверки. |
| Уменьшить / «Убрать» | Черновик строки и новая сверка. До записи заказ прежний. | Сохранение до сверки. |
| «Сохранить» | `proposeChanges` → карточка заказа. Применённые строки: «Изменения сохранены». Открытое предложение: «Ждём ответа покупателя». Событие в чате. | Редактирование и повтор до результата. |

Если изменение недоступно на этапе заказа, показать «Изменение состава недоступно». Для границы этапов и другого согласования см. §10. При пустых правках «Сохранить» выключено, ошибки по §3.0 и §5.

### 3.2 O6 · «Магазин предлагает замену» у покупателя

Шаблон `order`. Главная, карточка заказа и чат ведут к одному предложению по действию «Посмотреть изменения».

| Сверху вниз | Компонент, данные и текст |
| --- | --- |
| Предложение | `OrderStatusCard`, «Магазин предлагает замену», «Ответьте до <время>» для открытого запроса. |
| Позиции | `Card`, `ProductRow`, `Radio`. «Было» / «Стало», при добавлении прежней строки нет. Для каждой строки «Принять», «Убрать», «Выбрать свою», исходное состояние «Нет ответа». |
| Пересчёт | `TotalsBlock`, «Итого было», «Итого станет», «Уже оплачено», «К доплате» или «К возврату» по серверному расчёту. |
| Подтверждение и итог | `StickyFooter`, «Подтвердить» / «Сохраняем…». После применения `OrderStatusCard` «Изменения сохранены» с «Было» / «Стало» и итогом. |

| Действие | Результат и запрос | Блокировка |
| --- | --- | --- |
| «Принять» / «Убрать» | Выбор в черновике → пересчёт до подтверждения. | Подтверждение до сверки. |
| «Выбрать свою» | §3.3 → выбор в текущей строке → пересчёт. | Подтверждение до выбора и сверки. |
| «Подтвердить» | `answerChanges` → актуальные условия и результат. Отправка части решений — §10. | Ответы и повтор кнопки до исхода. |

«Срок ответа истёк» либо «Предложение больше недоступно» и «К заказу» для закрытых предложений. Уменьшение или удаление, сделанное напрямую, сразу показывается как результат. Ошибки и потеря остатка — §5.

### 3.3 O6 · Подбор товара

`Sheet` «Выберите замену» или «Выберите товар» → `SearchField` «Поиск по товарам магазина» → `ProductRow` с фасовкой → `Stepper` при выборе количества → «Выбрать». Поиск читает товары текущего магазина и оперативные предложения. «Выбрать» возвращает правку продавца или решение покупателя в строку и запускает сверку, подтверждение правки блокируется на время сверки. Пусто — «Товары не найдены», занятый остаток — «Этого количества больше нет» с доступным количеством. При ошибке «Повторить» сохраняет поисковый запрос, «Назад» сохраняет исходный набор правок.

### 3.4 O7 · Предложение и результат в заказе

Шаблон `order`, блок получения.

| Сверху вниз | Компонент, данные и текст |
| --- | --- |
| Текущее время | `ListItem`, «Время получения», дата и окно или подпись режима B8. «Часовой пояс магазина». |
| Начать перенос | `Button`, «Изменить время» у продавца, «Попросить другое время» у покупателя при разрешённом действии. |
| Предложение | `OrderStatusCard`, «Магазин предлагает другое время» или «Покупатель просит изменить время», «Текущее время» / «Предлагаемое время». Для автора «Ждём ответа», «Отозвать предложение». |
| Ответ или итог | У покупателя «Подходит» и «Выбрать другое время», у продавца «Подходит» и «Предложить другое». Итог «Время изменено» с новой датой, «Предложение отозвано» или «Заказ закрыт» по состоянию. |

| Действие | Результат и запрос | Блокировка |
| --- | --- | --- |
| «Изменить время» / «Попросить другое время» | §3.5 с текущим способом получения. | Отправка до загрузки и выбора. |
| «Подходит» | `answerTime` → новое время и резерв. | Ответ, отзыв и повтор до исхода. |
| «Выбрать другое время» | §3.5 в режиме просьбы покупателя. Отправка закрывает исходное предложение и открывает просьбу. | Ответ по исходному предложению на время команды. |
| «Предложить другое» | §3.5 с окнами продавца. Последний шаг цепочки — §10. | Одновременный ответ по просьбе и повтор команды. |
| «Отозвать предложение» | `withdrawTime` автора → старое время с пояснением. | Отзыв, принятие и новый перенос до исхода. |

Закреплённое за заказом время видно, пока открыто предложение, даже если окно больше недоступно для новых броней. Отсутствие исходного резерва — §10. Закрытие и потеря окна — §5.

### 3.5 O7 · «Выберите другое время»

Шторка B8: «Выберите другое время» → «Часовой пояс магазина» → `ChipGroup` «Сегодня», «Завтра», «Другой день» → `ListItem` с окнами нужного способа, включая одно длинное окно. Для дневного режима день и подпись «В течение дня». Для режима согласования «Время согласуем с магазином», способ переноса без слотов — §10. У самовывоза своё расписание.

«Предложить время» / «Попросить перенос» отправляет `proposeTime` либо `answerTime` при встречном выборе. «Сохраняем…» блокирует выбор и подтверждение. «Назад» до отправки возвращает к заказу. Загрузка — «Проверяем время…», пусто — «Нет свободного времени», потеря места — «Это время уже заняли» и «Выбрать другое время». «Повторить» при ошибке сохраняет выбранный день и обновляет окна.

### 3.6 O8 · Списки переписок

Шаблон `list`. Иконка «Сообщения» в шапке витрины или кабинета. В кабинете иконка показывает ненулевой счётчик текущего сотрудника. На витрине «Чаты с магазинами», секции «Активные» и «Завершённые» в этом порядке. В кабинете «Переписка по заказам», непрочитанные и ожидающие ответа выше прочих (§10).

`Header` → названия секций `SectionHeader` → строки `ListItem`: «Заказ №<номер>», название магазина или имя покупателя, последняя запись, время, метка «Непрочитано» или «Ждёт ответа» по состоянию. «Загрузить ещё» читает курсор и блокируется до ответа. Выбор открывает чат, по возврате сохраняется позиция. Пусто — «Переписок пока нет». «О магазине» ведёт к контактам, при их отсутствии «Магазин ещё не указал контакты». Гостю — вход B9. Ошибка, офлайн и повтор по §3.0.

### 3.7 O8 · Чат по заказу

Шаблон `order` с лентой. Открывается из списка, B11 / O2 или прямой ссылки участника.

| Сверху вниз | Компонент, данные и текст |
| --- | --- |
| Шапка | `Header`, «Чат с магазином» / «Чат по заказу», ссылка «Открыть заказ №<номер>». |

| Редактор | `TextArea` «Сообщение», `PhotoPicker` «Фото», превью с действием «Убрать фото», «Отправить». |
| Чтение после закрытия | Вместо редактора «Переписка закрыта. История доступна для чтения». |

| Действие | Результат и запрос | Блокировка |
| --- | --- | --- |
| «Загрузить предыдущие» | Запрос по курсору, сохранить позицию чтения. | Повтор догрузки до ответа. |

При недоступном фото «Фото недоступно» и «Повторить» для ссылки. При выходе или смене магазина или пользователя местные черновики прежнего контекста очищаются. При закрытии права записи между входом и отправкой действует §5.

## 4. Сервер: команды и правила

### 4.1 Общий порядок

1. Проверить сессию, магазин и действующее право. Для O6 и O7 у сотрудника — `orders`, для O8 — `chat`. Финансовые поля и действия защищены по [блоку 5](seller-orders.md). У покупателя проверяется принадлежность заказа по B11, для чата дополнительно нужен вход B9.
2. В авторизованном контексте вернуть прежний результат известного ключа для той же команды. Изменённый после сверки ввод отправляется с новым ключом. Для новой команды сверить этап и фактическую передачу, версию или ревизию, тип и состояние предложения. Ошибка оставляет заказ и резервы без изменений. Обработка срока также проверяет, что заказ всё ещё допускает правку.
3. Записать затронутые снимки, резервы, согласование, финансовый результат, историю с автором и временем и outbox в одной транзакции. Telegram и live запускаются после фиксации. Ошибка доставки события не откатывает заказ.
4. Использовать отметку изменения заказа по [BL-12](../progress/BL-12.md) внутри команды. Адресный live-поток O2 передаёт IDs и ревизии. После переподключения сверка по курсору. Повтор команды и откат не создают сигнала. После отзыва доступа открытая сессия теряет право на чтение и запись.

### 4.2 O6 · Состав

1. `proposeChanges` сверяет тип каждой правки с исходной строкой. Удаление и уменьшение применяются сразу. Для замены и добавления сервер открывает `pending` на 30 минут от записи предложения. Старые условия этих строк остаются в силе до согласия. Сервер хранит, какие исходные позиции отсутствуют (уточнение §10).
2. `answerChanges` проверяет срок, принадлежность и действующее состояние всех строк, выбранные фасовки и доступность. У принятой замены новый остаток занимается и прежний резерв освобождается в одной транзакции. При изменившемся расчёте вернуть новый итог и запросить явное подтверждение. Сверх остатка принять нельзя, в том числе при гонке за последнюю фасовку.
3. При истечении срока сервер закрывает предложение один раз. Непринятые замены и добавления не применяются, отсутствующие исходные позиции удаляются без доплаты. Alarm ставится на ближайший срок. Команда проверяет тот же срок по серверному времени, включая гонку ответа с истечением.
4. Использовать действующий расчёт DOMAIN с подтверждёнными поступлениями. Согласованный рост фиксирует отдельное обязательство по O2 и O5b, сборка и передача продолжаются. Возврат ограничен чистыми подтверждёнными поступлениями. Пример 339 ₽ → 279 ₽ при оплате 339 ₽ даёт 60 ₽ к возврату. Предложения и применённые правки видны в заказе и O8. Покупателю по US-Z04 — Telegram с разницей «Было / Стало» и ссылкой «Посмотреть изменения».

### 4.3 O7 · Время

1. `proposeTime` проверяет доступность B8 для действующего способа и часового пояса магазина. Просмотр и предложение окна не занимают место. По заказу одновременно открыто одно предложение. Сочетание с составом — §10.
2. «Подходит» повторно проверяет новый слот. Новый резерв и снятие старого фиксируются вместе. В гонке за последнее место выигрывает один заказ. У другого прежний резерв сохраняется, ответ `SLOT_TAKEN`. Для того же окна повторное резервирование отсутствует.
3. Подтверждение выбора «Выбрать другое время» атомарно закрывает предложение магазина и открывает просьбу покупателя. Отзыв автором или отклонение фиксируют исход с прежним временем. У O7 нет срока, ответ по устаревшему ID возвращает `CHANGE_EXPIRED`. Последний встречный шаг — §10.
4. Успешный перенос обновляет время у обеих ролей и записывает событие O8. Предложение покупателю отправляется по US-Z04 и правилам бота блока 9, с прежним и предлагаемым временем и переходом к заказу. Отображение дат и переход суток проверяются в часовом поясе магазина.

### 4.4 O8 · Чат и уведомления

1. Доступ проверяется для списка, истории, сообщения и отдельного файла. Общего канала без заказа нет. Запись доступна до истечения 7 дней после завершения или отмены, далее история и вложения остаются для чтения. Проверка срока происходит при обращении, без фонового обхода.
2. У нового `send` проверить длину и частоту (§10), назначение `chat`, магазин, автора и завершение загрузки F9. Привязать файл к сообщению и заказу. Атомарно добавить сообщение, обновить непрочитанные и записать outbox. Повтор не расходует лимит. Приватная ссылка выдаётся только авторизованному участнику.
3. Непрочитанные обновляются при отправке и чтении. Отметка последней показанной записи не поглощает новое сообщение, пришедшее одновременно. Страницы имеют устойчивый курсор, история и счётчик обновляются потоком O2.
4. Продавцу о новом сообщении покупателя — O4 по роли и галочке «Сообщения». Роль, право `chat` и настройку сверить в момент отправки. Покупателю — бот магазина или Korzina по блоку 9 §11.7. Дедупликация по событию и получателю. Текст «Новое сообщение по заказу №<номер>», действие «Открыть чат».

### 4.5 Бюджеты

Сохранить [PERFORMANCE §6](../PERFORMANCE.md#6-измерение-и-бюджеты): карточка покупателя ≤ 3 SQL, продавца ≤ 4 SQL, неизменившийся виджет ≤ 1 SQL и 0 строк заказов. Списки, поиск и история читаются ограниченными страницами без N+1, счётчики берутся из сохранённых значений. У команды одна транзакция, внешние вызовы после неё. Для новых горячих путей O6/O7 и списка, чтения и отправки O8 закрепить численные пределы SQL и строк замером и тестом бюджета. Фон запускается при наличии работы. Временные файлы и ключи повторов очищаются по F9 и PERFORMANCE §5, история чата и связанные вложения сохраняются при закрытии записи.

## 6. Правила

- **П1.** Замена и добавление требуют согласия. Изменение без согласия может только уменьшить состав. [D07](../tasks/O6.md)
- **П2.** Старые условия предложенных строк действуют до ответа или истечения срока. Возврат ограничен чистыми поступлениями. [DOMAIN](../DOMAIN.md)
- **П3.** Время меняется при согласии и успешном резервировании. Старый резерв освобождается вместе с занятием нового. [O7](../tasks/O7.md), [B8](../tasks/B8.md)
- **П4.** Согласование — отдельная ось. Повтор команды даёт один результат и одно событие. [DOMAIN «Заказ»](../DOMAIN.md#заказ-6)
- **П5.** Переписка принадлежит заказу и его участникам. Закрытие сохраняет историю для чтения. [D21](../tasks/O8.md)
- **П6.** Telegram уведомляет после записи события. Факт доставки уведомления не меняет заказ. [DOMAIN «Telegram»](../DOMAIN.md#telegram-910)

## 8. Границы блока

- Проведение доплаты и возврата, передача реквизитов и отдельные платёжные экраны — [O5](../tasks/O5.md) и [O5b](../tasks/O5b.md). Блок 10 рассчитывает последствия, показывает обязательства и события со ссылками на доступные действия.
- O6 меняет состав, O7 — время, O8 отображает связанные события и ведёт к их действиям. Настройки расписания остаются в S4/B8, роли и вход — в S8/B9.
- Общий чат `general` исключён D21. Для связи без заказа есть контакты «О магазине». Рассылки — A12b. Вопрос «Если товара нет — что делать?» исключён из оформления D07.5.
