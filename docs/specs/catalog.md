## 1. Путь

| Откуда | Действие и переход | Возврат и прямая ссылка |
|---|---|---|
| Ссылка магазина или кнопка бота | Главная `/` | В шапке идентификация магазина, в выдаче его ассортимент. На demo ссылки сохраняют `shop`, если он указан. |
| Главная | «Все ›» у товаров → `/catalog`; у категорий → `/categories`; у брендов → `/brands` | Переход возвращает к позиции на главной. |
| «Все товары», «Все категории», «Бренды» | Вкладки ведут на `/catalog`, `/categories`, `/brands`. Из «Все категории» доступны «Все товары ›» и, при наличии брендов, «Все бренды ›» | При открытии URL сразу виден выбранный раздел. |
| Плитка категории или бренда | `push` → `/c/:id` или `/b/:id`. Чип подкатегории меняет `subcategory` на том же экране | Назад из товара возвращает в тот же раздел с выбранным чипом, фильтрами и прокруткой. |
| Список или обычный поиск | Фильтры и сортировка открываются шторками. Применение отражается в `sort`, `min`, `max`, `cat`, `brands`, `inStock` | Адрес хранит применённый выбор для возврата, общей ссылки и перезагрузки. Закрытие отменяет черновик фильтров. |
| Плитка товара | Фото или название → `push` `/p/:id`. «+» добавляет одну фасовку или открывает шторку (`variants` на текущем списке) | Назад к источнику с прокруткой и текущей корзиной. Прямая ссылка на товар открывает его сразу, назад без истории → `/`. `variant` может указать фасовку из поиска. |
| Карточка | Фото → полноэкранный просмотр. «Подробнее о товаре ›» → шторка `/p/:id/details`. Рекомендация → карточка, бренд → `/b/:id` | Закрытие шторки или просмотра оставляет карточку. Галерея сохраняет текущий кадр томатов при смене фасовки. |
| Плавающий «Нейропоиск» | `push` → `/search`. Ввод обновляет `q` заменой текущей записи, без отдельного шага истории на каждый символ | Возврат из товара восстанавливает запрос, фильтры и прокрутку. По прямой ссылке с `q` клавиатура сама не открывается. История запросов хранится отдельно на устройстве. |
| Плавающая «Корзина» | `push` → `/cart` | Возврат в исходный экран. Содержимое корзины восстанавливается из сессии магазина после перезагрузки и повторного открытия. Экран корзины описан в [спецификации покупки](purchase.md). |
| Шапка или блок «О магазине» | `push` → `/about` | Назад на главную. Прямая ссылка открывает сведения магазина. |

Применённые фильтры и запрос восстанавливаются из URL. Прокрутка восстанавливается при переходе назад в текущей истории. Кадр галереи, черновик шторки и положение клавиатуры относятся к текущему сеансу экрана.

## 2. Данные

| Источник | Поля и типы | Когда читаем |
|---|---|---|
| Контекст магазина | `ShopContext` и `catalogSpec`: название, тема и статус из контекста; валюта ISO 4217 и `hideOutOfStock: boolean` в спецификации каталога; категории и бренды в порядке продавца, публикация и видимость товара, видимость SKU | При открытии магазина. Управление значениями относится к S2/S6. |
| `GET /api/catalog/document` + `/page-offers` | [`CatalogTile`](../../src/shared/contracts/catalog.ts): `id`, `name`, `categoryId`, `brandId`, `image`, `variants[{id,name,photoId}]`. Документ также отдаёт категории (с `parentId`), бренды, `hasProducts`, `next`, `catalogVersion`. [`CatalogOffer`](../../src/shared/contracts/catalog.ts): SKU, `productId`, `priceMinor`, `oldPriceMinor`, `stock`, `visible`, `available`; ответ содержит валюту и версию | Главная, 16 товаров за страницу. Документ кешируется по магазину и публичной версии, политика клиента 5 минут. Live-данные читаются для SKU загруженных страниц, политика 30 секунд. При появлении новой версии главная запрашивает документ этой версии. |
| `GET /api/catalog/page` | [`CatalogListInput`](../../src/shared/contracts/catalog-list.ts): `scope=all\|category:<id>\|brand:<id>`, `sort`, `min`, `max`, `brands`, `cat`, `inStock`, `count`, `cursor`; ответ объединяет документ, `offers`, `count`, `next` | Каталог и навигация по категориям и брендам. Ключ клиента включает магазин, область и фильтры. На черновик шторки читается отдельный результат со счётчиком. Следующая страница использует `next` как непрозрачный курсор. |
| `GET /api/catalog/products/:id` | Тип ответа `readProduct`: `id`, `name`, `description`, `categoryId`, `brandId`, `brandName`, `currency`, `catalogVersion`, упорядоченные `images`, `variants` с `photoId`, ценами, остатком и `available`, `recommendations` с плитками и офферами | Карточка, подробности и шторка фасовок используют один ключ магазина и id. Политика свежести 30 секунд. |
| `GET /api/catalog/search` | [`CatalogSearchInput`](../../src/shared/contracts/catalog-list.ts): `q` 2–180 символов и общие фильтры; ответ с плитками, офферами, `count`, `suggestion`, `preferred` (товар → доступный SKU) | Обычный поиск после 250 мс, отдельный ключ на запрос и фильтры. Сервер возвращает до 16 плиток и счётчик совпадений. |
| `POST /api/catalog/shopping-search` | `{ q: string }` → `{ items, offers, groups: [{ term, ids, preferred }] }` | Поиск списка или блюда, кеш по магазину и строке, политика 30 секунд. Команда поиска читает данные без изменения корзины. `Idempotency-Key` здесь не требуется. |
| `GET /api/cart` и `POST /api/cart` | [`Cart`](../../src/shared/contracts/cart.ts): `revision`, `currency`, строки `CartLine`, `count`, `totalMinor`, `adjustments`, `review` при изменениях. Команда из каталога: `{variantId, quantity, expectedRevision}` + `Idempotency-Key`, ответ `Cart` либо ошибка с актуальным `cart`, если он рассчитан | Общий снимок на всех экранах покупателя, политика 30 секунд. Результат команды заменяет снимок. Подтверждение пересчёта описано в спецификации покупки. |
| Устройство | Последние восемь строк поиска в `localStorage`, ключ привязан к магазину | При входе на экран поиска. Запись после подтверждения или выбора результата, фасовки, запроса из истории или исправления. Очистка касается только истории магазина. |

Деньги в API — целые числа в минимальных единицах валюты. `stock: null` означает «без учёта остатка». Плитка, карточка и корзина используют серверные цену и доступность. Допустим предварительный пересчёт видимого количества и суммы на время команды с последующей заменой серверным ответом. Сортировку, фильтрацию, подсчёт совпадений и подбор аналогов выполняет сервер. Описания товара читаются для карточки, общей выдаче достаточно данных плитки.

## 3. Экраны

Общее для всех экранов: серый фон, отступы и закрепление по [DESIGN §5а](../DESIGN.md), фото по [правилам фото](../design-system/photos.md). Цель для основных касаний ≥44 px. Иконки подписаны для экранного диктора, шторки удерживают фокус и возвращают его на кнопку открытия. Чипы и опции работают с клавиатуры и сообщают выбранность. Скелетон показывает ожидаемую структуру, ошибка сохраняет выбор. В состояниях без сети уже загруженные данные остаются видимыми до свежего ответа. Поиск показывает отдельную подсказку о работе без сети. Для других экранов см. вопрос 10.

### 3.2 Общая плитка и шторка фасовок

| Элемент сверху вниз | Компонент | Данные, условия и текст |
|---|---|---|
| Фото с бейджем | `ProductImage`, `DiscountBadge` | Обложка и процент только при `oldPriceMinor > priceMinor`; без фото или при сбое — заменитель изображения. |
| Название, фасовка | `ProductTile` | Название товара, имя SKU или «N фасовок» с согласованием числа. |
| Цена | `Price` | `от` минимальной цены при нескольких доступных SKU с разной ценой, старая цена зачёркнута только при скидке. Для конкретного SKU с остатком 1–5 — «N осталось». |
| Управление | `AddToCart` | «+» → «− N +», подписи «Добавить в корзину», «Выбрать фасовку», «Убрать одну штуку», «Добавить одну штуку», «В корзине». Если добавлять нельзя — «Нет в наличии» или подсказка «Больше нет» у достигнутого лимита. |
| Шторка | `Sheet`, `Price`, `AddToCart` | «Выберите фасовку», название товара и строки видимых SKU с названием, ценой, остатком через контрол и состоянием «Нет в наличии». |

| Действие и условие | Результат | Запрос и блокировка |
|---|---|---|
| Фото или название | Карточка товара. При совпавшем весе в поиске — карточка с этим SKU | Чтение карточки, использует свежий кеш, если есть |
| «+», одна доступная фасовка либо поиск выбрал SKU | Добавить 1 | Команда корзины, на время ответа блокируются кнопки того же товара |
| «+», несколько доступных фасовок и ни одна ещё не добавлена | Шторка фасовок, с неё можно добавить разные SKU подряд | Чтение товара, блокируются только контролы в ожидании данных или команды |
| Степпер | Изменить количество SKU; «−» при количестве 1 убирает строку | Команда корзины. «+» блокируется при лимите или недоступности, «−» доступен для уже добавленного SKU на плитке и в карточке |
| Закрыть шторку | Возврат на исходный экран с подтверждёнными изменениями корзины | Без записи. По прямой ссылке очищается `variants` |

При пустой корзине плитка показывает самый дешёвый доступный SKU; для недоступного товара — первый показанный SKU. Если товар есть в корзине, обычная плитка управляет одной уже добавленной фасовкой по `selectOffer` (последняя подходящая строка снимка), поиск с точным доступным весом сохраняет приоритет найденного SKU. Несколько фасовок одного товара хранятся отдельными строками. Вариант доступа к другим фасовкам после первого добавления — вопрос 1.

Загрузка шторки — скелетон списка; пустой или недоступный товар — состояние чтения с возможностью закрыть шторку; сетевой сбой — «Не удалось загрузить» / «Повторить»; при устаревших цене или остатке результат команды синхронизирует количество и сумму с корзиной. В отсутствие сети загруженные предложения остаются видны, подтверждение количества зависит от ответа API.

Для всех списков: при загрузке — скелетон каталога; при отсутствии товаров в разделе — «Здесь пока пусто» / «На главную»; для скрытой или неверной ссылки — «Раздел недоступен» / «На главную»; для активной выборки без совпадений — «0 товаров» / «Измените цену или сбросьте фильтры» / «Сбросить фильтры». При сбое сети доступны имеющиеся плитки либо «Не удалось загрузить» с повтором при сетевой ошибке. Конфликт версии при подгрузке сохраняет уже показанную часть. Способ повторного открытия первой страницы без потери условий вынесен в вопрос 5. После успешного свежего чтения счётчик и плитки показывают новую выборку.

|---|---|---|
| Открыть «Фильтры» | Копирует применённый выбор в черновик | Чтение счётчика; закрытие доступно |
| Ввести цену, выбрать категорию, бренды, наличие | Обновляет черновик. Категория выбирается сразу, бренды подтверждаются «Готово» в подуровне | Чтение счётчика для валидного диапазона. Подтверждение показывает загрузку; остальные поля доступны |
| «Сбросить» в шторке | Очищает черновые фильтры, оставляет сортировку | Новый счётчик; основная выдача сохраняется до применения |
| «Показать N товаров» | Применяет через URL, закрывает шторку | Первая страница новой выборки, свежий результат из кеша можно переиспользовать |
| Снять чип или нажать «Сбросить» в панели | Снять соответствующий фильтр или все активные фильтры с сохранением сортировки | Чтение новой выборки |
| Выбрать сортировку | Сразу применяет порядок, закрывает шторку и сохраняет фильтры | Чтение новой выборки |
| Закрыть шторку | Отбрасывает изменения черновика | Без запроса к применённой выборке |

Поля цены используют числовой ввод с шагом валюты. При верхней границе ниже нижней показывается «Укажите цену больше или равную нижней границе», кнопка применения отключена. Нулевой счётчик разрешает открыть пустую выдачу. При сбое подсчёта или отсутствии сети доступна надпись «Показать товары», если счётчик ещё неизвестен. Свежий счётчик заменяет старый при успешном ответе. В пустой выдаче отдельный «Сбросить фильтры» сейчас сбрасывает также сортировку, см. вопрос 11.

| Действие | Результат | Запрос и блокировка |
|---|---|---|
| Выбрать фасовку | Меняет цену, скидку, остаток и управление количеством для этого SKU. Позиция галереи томатов сохраняется | Локальный выбор из полученных SKU. Отображение `photoId` в галерее — вопрос 2 |
| Добавить, «−», «+» | Изменяет только выбранный SKU | Команда корзины, контрол товара блокируется на время ответа |
| Открыть подробности или фото, листать, закрыть, свайп вниз в просмотре | Шторка или просмотр с возвратом к карточке и выбранному кадру | Подробности используют тот же запрос товара, просмотр может загрузить оригинал. Остальные действия не ждут загрузки фото |
| «Поделиться» | Telegram → диалог отправки ссылки; браузер → системное меню или копирование. «Ссылка скопирована» / «Не удалось поделиться ссылкой» | Запрос каталога не требуется, отмена меню оставляет карточку |

Загрузка — скелетон товара; при 404 — «Товар больше недоступен» / «На главную»; при сетевой ошибке — «Не удалось загрузить» / «Повторить». При пропаже сети показывается загруженная карточка, если она есть. После обновления цены и остатков выводятся актуальные значения; закончившийся SKU остаётся доступным для уменьшения уже добавленного количества в карточке. При скрытии товара следующая успешная загрузка показывает состояние недоступности. Фото без данных и фото с ошибкой используют один заменитель; просмотр закрывается независимо от загрузки оригинала.

В режиме блюда сервер ищет подходящие товары по словарю ингредиентов магазина, совпадения не гарантируют полной комплектации блюда. Панель фильтров относится к обычному поиску. Одна строка от 181 до 4000 символов сейчас идёт в групповой поиск как одна позиция; см. вопрос 9.

| Элемент | Компонент | Показ и текст |
|---|---|---|

Для `/about` отдельного чтения нет: используется контекст магазина, состояние закрытого магазина общее с главной.

## 4. Сервер: команды и правила

| Запрос | Действующие правила и инварианты |
|---|---|
| Документ и офферы главной | Публичные данные из хранилища текущего магазина. Публикация и видимость проверяются на сервере; наличие и цены SKU приходят отдельно от документа. Новая публичная версия меняет ключ кеша документа. |
| Страница каталога | Без пользовательской выборки используется документ по публичной версии. Для фильтров и сортировки магазин применяет область, фильтры и порядок до пагинации. Цена для выборки — минимум доступного SKU, границы включительные. Бренды в мультивыборе объединяются, условия разных фильтров пересекаются. Курсор связан с областью и версией, в сортированной выборке также с фильтрами, ключом порядка и версией выборки. |
| Карточка | Сервер возвращает только доступный покупателю товар и видимые SKU, применяет `hideOutOfStock`. Рекомендации — до четырёх других опубликованных видимых товаров той же категории с хотя бы одной доступной фасовкой. |
| Обычный поиск | Индекс FTS5 в хранилище магазина, запрос нормализует регистр и «ё/е». Приоритет названия, бренда и категории выше описания. Если нормальный поиск не дал результатов, одиночное слово от четырёх букв может получить близкое совпадение. Явные г/кг/мл/л сопоставляются с доступным SKU. Подсказка не заменяет введённый запрос автоматически. |
| Список и блюдо | Сервер валидирует пределы 4000 символов и 40 позиций. Повторяющиеся строки ищутся один раз. Для блюда применяется общий словарь и совпадение по названию. Эти чтения не пишут историю и не создают событий. |
| Изменение количества | Проверяются сессия покупателя, активность магазина, входные данные, ключ повтора и ревизия. Отдельная строка на SKU, `quantity: 0` удаляет строку, максимум команды 999 и 50 разных SKU на корзину. Фактический остаток ограничивает количество. Команда не резервирует товар. Сервер сохраняет снимок и результат ключа повтора транзакционно. Повтор того же запроса с тем же ключом возвращает записанный результат; другой запрос с тем же ключом даёт конфликт. Параллельное изменение с устаревшей ревизией получает свежий снимок и конфликт. |

Внешних вызовов для каталога, поиска и выбора фасовки нет. Политика кеширования описана в §2. Серверные критерии и бюджеты проверяются существующими тестами каталога, поиска и корзины по [PERFORMANCE §6](../PERFORMANCE.md) и [TESTING §2](../TESTING.md). Правила записи заказа и уведомлений относятся к покупке и заказам.

## 5. Ошибки сервера → поведение экрана

| Код / сбой | Где | Что видит покупатель и что сохраняется | Действие |
|---|---|---|---|
| `NOT_FOUND` / 404 | Раздел или товар | «Раздел недоступен» либо «Товар больше недоступен». В шторке фасовок — общее сообщение чтения. Корзина сохраняется. | «На главную» на полном экране; закрыть шторку. |
| `SHOP_NOT_FOUND` | Контекст витрины | «Магазин не найден», без доступных действий каталога. | Открыть действующую ссылку магазина. |
| `VALIDATION` | Фильтры, курсор или поиск | Некорректные параметры или запрос, содержимое поля сохраняется. Для лимитов списка — сообщения §3.7. | Исправить ввод. Для устаревшей страницы — вопрос 5. |
| `VERSION_CONFLICT` | Страница каталога | «Каталог обновился. Обновите список.». Текущая выборка и уже загруженные плитки сохраняются при ошибке подгрузки. | Обновить список с первой страницы, сохранив область и фильтры. Кнопка для этого — вопрос 5. |
| `VERSION_CONFLICT` | Корзина | «Корзина изменилась. Попробуйте ещё раз.». Количество и сумма синхронизируются с `details.cart`. | Повторить нужное изменение после проверки количества. |
| `STOCK_CHANGED` | Размещённый на экране SKU стал недоступен | «Товар больше недоступен». Серверный снимок заменяет предварительное изменение. | Выбрать доступную фасовку или убрать старую строку через корзину. |
| Успех с количеством меньше запрошенного | Изменение количества | «Больше нет», показано возвращённое количество. Если цена или остаток изменились, серверный `review` разбирается в B6. | Проверить количество или открыть корзину. |
| `UNAUTHORIZED`, `FORBIDDEN` | Команда корзины | «Нужна сессия покупателя» или «Магазин временно закрыт». Предварительное изменение снимается. | После восстановления сессии или доступности магазина повторить действие. |
| `IDEMPOTENCY_CONFLICT`, `VALIDATION` | Команда корзины | Серверное сообщение, например «Ключ уже использован с другим запросом» или «В корзине может быть до 50 разных фасовок». | Исправить причину перед новым действием. |
| Сеть / 5xx | Чтение или команда | Скелетон до ответа, затем сообщение экрана и повтор. Загруженные данные и выбор сохраняются. Для команды показывается ошибка, предварительное изменение снимается при окончательном отказе. | Повторить чтение. Автоповтор команды использует прежний ключ и ревизию. |

## 6. Правила

1. **П1.** Ассортимент и навигация изолированы по магазину. Навигация показывает видимые разделы. Прямая ссылка и поиск открывают только опубликованные и видимые товары. Видимость распроданного товара зависит от настройки магазина. [DOMAIN](../DOMAIN.md), B2–B5.
2. **П2.** Цена, скидка и остаток относятся к SKU, строка корзины также относится к SKU. Изменение одной фасовки сохраняет количество другой. [DOMAIN](../DOMAIN.md), B4.
3. **П3.** Фильтрация, сортировка и подсчёт применяются ко всей серверной выборке. Назад и прямые ссылки восстанавливают применённые условия. B3b, [DESIGN §5а](../DESIGN.md).
4. **П4.** Поиск, исправление, подбор по блюду и выбор фасовки сами по себе корзину не меняют. Количество меняется только по кнопке. B5, B5b.
5. **П5.** Одна корзина на сессию магазина. Плавающая сумма и количество в плитке, шторке, карточке и поиске берутся из одной модели корзины. [DOMAIN](../DOMAIN.md), [DESIGN §5а](../DESIGN.md).
6. **П6.** Интерфейс показывает доступные действия текущего блока. R2, [решение 18.11.2026](../DECISIONS.md).

## 7. Приёмка

| Дано | Когда | Тогда | Проверка |
|---|---|---|---|
| Активный магазин с категориями и брендами | Открыть его ссылку, «Все ›» и плитки разделов | Видны название магазина, действующие вкладки, правильные разделы и карточки по прямым ссылкам | [smoke] [холст] |
| Категория с подкатегориями и длинной выдачей | Выбрать чип и цену, прокрутить, открыть товар и вернуться | Видны тот же чип, фильтр и позиция прокрутки | [smoke] [холст] |
| Пустой, скрытый или удалённый раздел, плохая сеть | Открыть адрес или повторить чтение | Состояния пустоты, недоступности и ошибки различаются, путь выхода работает | [сервер-тест] [холст] |
| Товары с разными ценами, в том числе закончившимися фасовками | Сортировать по цене, задать границы и пройти страницы | Учитываются доступные SKU. Нет повторов и пропусков. Нулевая выборка имеет путь сброса | [сервер-тест] [smoke] [холст] |
| Товар с несколькими SKU, один в малом остатке | Открыть шторку, добавить две разные фасовки, достичь лимита, удалить одну | Две отдельные строки. Плюс у лимита отключён, количество второй строки и сумма синхронны | [сервер-тест] [smoke] [холст] |
| Карточка с несколькими фото или без фото | Сменить кадр и фасовку, открыть и закрыть просмотр, перейти по ссылке из «Поделиться» | Галерея доступна с клавиатуры, томаты сохраняют кадр, покупка и корзина доступны, ссылка открывает нужный товар | [smoke] [холст] |
| Поиск по названию, бренду, категории, опечатке и явному весу | Ввести запрос, выбрать подсказку или открыть найденный SKU и вернуться | Выдача следует строке, подсказка применяется нажатием, вес сохраняется на плитке, возврат восстанавливает поиск | [сервер-тест] [smoke] [холст] |
| Список с найденными и ненайденными строками, блюдо и список из 41 позиции | Вставить запросы, добавить найденный товар, очистить поиск | Есть сгруппированные результаты и список пропусков, блюдо показывает подходящие ингредиенты, лимит виден без потери ввода, корзина переживает очистку | [сервер-тест] [smoke] [холст] |
| Цена, остаток или ревизия изменились между показом и командой | Повторить команду или получить конфликт | Количество ограничено сервером, снимок восстанавливается, повтор с тем же ключом не дублирует действие | [сервер-тест] [холст] |
| Плитки открыты из разных входов, магазин работает в Telegram и браузере | Добавить SKU, открыть корзину, вернуться, перезагрузить | Корзина магазина и источник возврата согласованы, кнопки не перекрывают покупку; будущих действий на экране нет | [smoke] [холст] |

## 8. Не входит

- Создание и изменение товаров, фасовок и ручных рекомендаций (S2), настройки внешнего вида, сведения магазина (S6) и выключение фильтров продавцом (S, `catalogFilters`). Маленькая витрина и дополнительные поля фильтра относятся к A.
- Содержимое экрана корзины и оформление (B6–B10): адрес, получение, вход и профиль, расчёт доставки, оплата, создание заказа. История и статусы заказов — B11 и блок заказов. Чат — блок O.
- Избранное и сердце на карточке (B12); отзывы (A2), истории (A3), кэшбэк (A4), выгоды и персонализация (A5/A12), «Любимый товар», подбор по истории покупок, нейрорекомендации, предзаказ и другие функции фазы A/O.
- Внешний ИИ и внешние источники для поиска, автоматическое добавление списка или блюда, обещания состава или диеты. В перечне идей отсутствуют новые поля и команды API.

## 9. Открытые вопросы

| № | Ситуация сейчас | Предлагаемое решение и что меняется |
|---|---|---|
| 1 | После первого добавления плитка многофасовочного товара показывает степпер одной фасовки; чтобы выбрать другую, нужен вход в карточку. | Оставить степпер текущего SKU и добавить явный вход «Фасовки» на плитке, либо сохранить текущий путь через карточку. Определяет состав плитки. |
| 2 | История US-C05 ожидает смену фото по SKU. Карточка использует общую галерею и сохраняет позицию для всех товаров, хотя API отдаёт `photoId`. Для томатов сохранение кадра согласовано. | Сохранять кадр у томатов и переходить к привязанному фото для остальных товаров, либо сохранять кадр у всех. Определяет поведение галереи. |
| 3 | Шторка фасовок при недоступном SKU показывает «Нет в наличии», даже когда строка этого SKU есть в корзине. Плитка и карточка в таком случае позволяют уменьшить количество. | Разрешить «−» для имеющейся строки и в шторке, либо оставить удаление в карточке и корзине. Определяет недоступное состояние шторки. |
| 4 | Чип подкатегории и строка «Категория» могут дать несовместимое пересечение. | Сделать их двумя способами выбора одного условия либо сохранить пересечение и показать оба условия в панели. Определяет связь чипов и шторки. |
| 5 | После конфликта версии на подгрузке сервер просит обновить список. Общий компонент ошибки не даёт кнопку повтора для 409. | Добавить «Обновить список» на конфликте и читать первую страницу с прежними фильтрами, либо оставить обновление страницы браузера. Определяет действие в ошибке каталога. |
| 6 | При обычном поиске без совпадений ниже сообщения показаны первые товары каталога, без подписи. | Подписать альтернативы «Другие товары магазина» либо сохранить текущую выдачу. Определяет вид пустого поиска. |
| 7 | Запрос веса без доступной точной фасовки может показать товар с другой фасовкой и её «+» без пояснения. | Показать нейтральную подсказку «Проверьте фасовку» на такой выдаче, либо оставить обычную плитку. Определяет показ результата с весом. |
| 8 | Кнопка «Корзина» показывает «Пока пусто» уже при первом ожидании ответа. | Показать «Загрузка…» до снимка либо оставить текущую подпись. Определяет состояние первого чтения корзины. |
| 9 | Текст из одной строки длиннее 180 символов попадает в групповой режим, даже если разделителей нет. | Сообщить об ограничении обычного запроса, сохранив текст, либо сохранить групповой поиск по одной строке с явной подписью. Определяет границу режимов. |
| 10 | Без сети поиск даёт предупреждение о цене; незагруженная выдача может остаться без результата, а на других экранах отдельной подписи о состоянии сети нет. | Показать «Нет соединения» и «Повторить» при отсутствии снимка, оставить загруженные данные с кратким статусом. Определяет состояния без сети. |
| 11 | «Сбросить» оставляет сортировку, «Сбросить фильтры» при нуле снимает и её. | Сохранять порядок при любом сбросе фильтров либо назвать полное действие «Сбросить фильтры и сортировку». Определяет действие в нулевой выдаче. |
| 12 | Поиск возвращает до 16 плиток, счётчик может быть больше. | Показать «Показано N из M» с предложением уточнить запрос либо сохранить один общий счётчик. Определяет подпись к выдаче. |
| 13 | В поиске корзина скрыта при любом фокусе поля, включая ввод с внешней клавиатурой. | Оставить скрытие по фокусу либо показывать кнопку, когда экранная клавиатура закрыта. Определяет доступ к корзине во время поиска. |

Ответы на эти вопросы задают, какие варианты попадут на новый холст. До выбора базой служат перечисленные правила, карточки и принятые решения.
