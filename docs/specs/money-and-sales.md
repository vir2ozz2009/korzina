## 1. Путь

| Вход | Переход | Назад, прямая ссылка и восстановление |
|---|---|---|
| Кабинет → «Деньги» | Корень вкладки `/seller/money`. Сегодня по времени магазина. «К получению сейчас» открывает список всех открытых поступлений; группы открывают свой список. «Операции» → `/seller/money/operations` (`push`) | Сохраняются магазин, применённый период и выбранная группа. Период можно передать прямой ссылкой; без него — сегодня. Список и прокрутка восстанавливаются при возврате в том же сеансе |
| Задача или операция → заказ продавца | `push` в существующую карточку заказа с фокусом на «Оплата» | «Назад» возвращает к исходной выборке и позиции. Прямая ссылка на заказ без истории возвращает к списку заказов. Если открытая задача закрыта, строка исчезает после обновления списка, карточка показывает результат |
| Свой заказ покупателя → доплата или возврат | История заказов, существующая ссылка из сообщения/чата либо вход гостя по D01 → карточка. Из неё `sheet`: выбор способа → инструкция → чек или «Указать реквизиты» → форма | «Назад» закрывает текущую шторку или возвращает предыдущий шаг, сохраняя заказ. Прямая ссылка ведёт на заказ и доступное действие после проверки. После перезагрузки восстанавливается заказ с серверным состоянием; неотправленный текст реквизитов и выбранный файл в URL и постоянный кеш не записываются |
| Главная → «Статистика» → «Статистика продаж» | `push` в подменю, затем `push` в рейтинг всех товаров за период по §14.2–§14.3 | Из рейтинга «Назад» ведёт в подменю, из подменю — на главную. При возврате из отчёта восстановить рейтинг, период, догруженные строки и позицию |
| Главная → «Статистика» → «Обзор продаж» | `push`; по умолчанию выручка с включённым сравнением. Нажатие показателя меняет график. Ссылка под показателем «Заказы» или «Выручка» открывает существующий список только выполненных заказов по дате выполнения за выбранный период | Из заказов «Назад» возвращает фильтры и прокрутку статистики. Список по выборке O9 не включает отменённые и не использует дату получения |
| Строка рейтинга / действие «Статистика продаж» в карточке списка «Товары» → «Статистика товара» | `push`. Из рейтинга — тот же период; из списка «Товары» — последние 7 завершённых дней. По умолчанию «Все фасовки» | Период, товар и фасовка сохраняются в ссылке. «Назад» возвращает к источнику по §14.3; при прямом входе без истории — к рейтингу с тем же периодом |

Период в O5 и O9 меняется одной шторкой. При повторном входе или открытии приложения проверяются сессия, магазин, права и актуальные данные. На demo и превью ссылки покупателя сохраняют `?shop=<slug>` по [правилу §13.1 блока 5](seller-orders.md#13-исправления-после-локальной-проверки-20112026).

## 2. Данные и контракты

Деньги — целое число минимальных единиц и валюта по [DOMAIN](../DOMAIN.md#деньги-7). `from` и `to` — локальные ISO-даты магазина, обе включены; на сервере период от начала `from` включительно до начала дня после `to` исключительно. Время событий и завершения — UTC (целая метка в миллисекундах); ключ отчёта — локальный день магазина. Идентификаторы обязательств, операций и файлов непрозрачны для клиента. Названия новых контрактов ниже задают форму до реализации.

| Контракт / чтение | Поля ответа и момент чтения |
|---|---|
| `SellerMoneyOverview` | При входе и смене периода: `currency`, `period`, `receivedMinor`, `returnedMinor`, `collectableMinor`, счётчики открытых групп (целые), ревизия. Суммы выполненных операций относятся к периоду; к получению и счётчики относятся к текущим обязательствам. Для сумм за период — полнота каждого показателя по §10.2 |
| `SellerMoneyTaskPage` | При открытии группы: `id`, вид (`review`, `topUp`, `refund`), номер заказа, сумма к действию, валюта, время, статус реквизитов для возврата, непрозрачный `cursor?`. Группа «К получению сейчас» использует те же строки поступлений с одним вхождением на обязательство |
| `SellerMoneyOperationPage` | При открытии «Операции» и смене периода: `id`, вид (`received`, `returned`), номер заказа, фактическая сумма, валюта, время, `cursor?`. Сортировка от новых к старым с устойчивым вторым ключом по ID |
| [`SellerOrder`](../../src/shared/contracts/seller-order.ts) / [`BuyerOrder`](../../src/shared/contracts/buyer-order.ts) | При входе в заказ или изменении его ревизии: существующие поля заказа плюс списки открытых обязательств нужного вида с ID, суммой и состоянием, сумма проведённых возвратов, статус реквизитов, выбранный способ доплаты, актуальный чек и доступная по роли история версий. Состояние чека доплаты отдельно от первоначальной оплаты. Защищённые поля и разрешённые действия выдаются по роли |
| Реквизиты возврата | При чтении оплаты заказа: состояние и привязка к возврату; текст или защищённый QR только покупателю своего заказа и продавцу с `payments`. Используем [F9](../tasks/F9.md), назначение `refund`. Проверка магазина, заказа, файла и прав повторяется при открытии файла |
| `SellerSales` | При открытии «Обзора продаж»: `period`, `currency`, единица графика и серверные итоги для выручки, заказов и среднего чека. Средний чек — точное отношение суммы к числу подходящих заказов либо `null`; округление только при отображении. Каждая точка содержит даты/время интервала и метрики. Дневная таблица загружается при раскрытии. При выключенном сравнении данные прошлого периода не запрашиваются |
| `SellerProductSalesRankPage` | При открытии рейтинга, смене периода и догрузке: применённый `period`, `revision`, `cursor?`, строки с `productId`, названием, целочисленным `quantity` или `null` и его полнотой, долей полосы от 0 до 1 или `null`. Сервер сортирует и рассчитывает полосы по всей выборке по §14.2 |
| `SellerProductSales` | При входе в статистику товара и смене фильтра: ID, название, период, валюта, доступные фасовки с пометкой архивных, выбранная фасовка, `quantity`, `orderCount`, `revenueMinor`. Используем идентификаторы и снимки проданных строк, включая архивные фасовки |

Обзор и статистика передают состояние каждого затронутого показателя периода: полный, неполный с подтверждённым значением или без подтверждённого значения (`null`). Для сравнения полнота считается отдельно по двум периодам. Заказ продавца возвращает доступную сумму для открытия возврата и необходимость указать его назначение при проведении.

Клиент отображает суммы, проценты, разбиение и доступность действий из ответа сервера. Кеш и курсоры привязаны к магазину, контексту прав, выборке и ревизии. Совпавшая ревизия оставляет прежний результат; на live-событие перечитывается только затронутый видимый запрос, скрытый помечается устаревшим. При смене магазина/аккаунта, выходе или отзыве прав скрываются прежние суммы, реквизиты и вложения; поздний ответ прежней сессии их не восстанавливает. Команды и их результаты — §4, ошибки — §5.

| Заказ / «Оплата · <способ>» · `order` | Существующая карточка §3.3 блока 5, открытая сумма, последний чек и «История чеков» при заменах. Блок возврата показывает остаток, «Уже возвращено <сумма>», статус и переданные реквизиты. В выполненном заказе с доступной суммой и без открытого возврата — «Открыть возврат» по §10.4 | «Подтвердить» → существующая шторка фактической суммы, «Отклонить» → причина. «Записать оплату», «Исправить оплату» и «Списать долг» — блок 5. «Открыть возврат» и «Вернул» открывают шторки ниже. Каждое подтверждение вызывает команду §4. При записи конфликтующие действия и повтор заблокированы |

- «Открыть возврат» открывает одноимённую шторку с «Доступно к возврату <сумма>», полем «Сумма» (по умолчанию доступная сумма) и кнопкой «Открыть возврат». При успехе шторка закрывается, карточка и группа «К возврату» показывают открытое обязательство. Покупатель видит состояние из §3.4.
- «Вернул» открывает шторку «Записать возврат» с полями «Сумма», «Комментарий» и кнопкой «Вернул». При однозначном назначении сервер подставляет его сам. В остальных случаях поле «За что возврат» предлагает «Конкретные товары», «Товары в целом», «Доставка» и «Переплата». Для «Конкретные товары» появляются позиции заказа и суммы по каждой выбранной строке. Если есть несколько назначений, продавец указывает суммы по ним так, чтобы они сходились с выплатой. Ошибка показывается у поля, введённые значения сохраняются. Полный открытый остаток подставлен, меньшая положительная сумма допустима.

Сотрудник без `payments` не видит денежную вкладку, ссылки, суммы и файлы. Прямой вход в денежный раздел даёт «Доступ ограничен». Для самой карточки заказа продолжают действовать существующие права на заказ. Пустые списки — «Финансовых задач нет» / «Операций нет». Закрытая другим сотрудником задача — «Задача уже закрыта», с переходом к списку и обновлёнными итогами. Для возврата, проведённого без формы реквизитов (например, наличными), остаётся действующий путь записи фактического возврата; передача реквизитов не подтверждает выплату.

### 3.2 «Период» · `Sheet` с формой · O5, O9

`Radio`/`ListItem` для периодов. Для денег и обзора магазина: «Сегодня», «Вчера», «Последние 7 дней», «Последние 30 дней», «Свой период». Здесь последние 7 и 30 дней включают текущий локальный день. У рейтинга и отчёта товара свои интервалы по §14.3. «Свой период» раскрывает поля «Начало» и «Конец» и кнопку «Применить». «Применить» выполняет одно чтение выбранного отчёта, шторка закрывается после валидного выбора. Закрытие без применения сохраняет прежний период и не отправляет запрос. Неполная или неверная дата — «Введите дату» у поля, конец раньше начала — «Конец периода раньше начала» под конечной датой. Фокус у первого неверного поля. Ошибка запроса отчёта оставляет доступным фильтр и «Повторить» для этой выборки.

### 3.4 Возврат · покупатель, O5b

В оплате заказа (`order`) при открытом обязательстве «Магазин вернёт вам <сумма>» и «Указать реквизиты». Форма `Sheet` / `form` «Реквизиты для возврата»: поле «Реквизиты», загрузка «Добавить фото QR», «Отправить». Достаточно непустого текста или одного допустимого фото; пустая форма — «Введите реквизиты или добавьте фото QR». Во время загрузки и записи «Отправить» заблокирована. Ошибка сохраняет введённый текст и позволяет заменить файл. После успешной записи форма закрывается, заказ показывает «Реквизиты переданы, деньги ожидаются». При частичном возврате — «Возвращено <сумма>» и «Осталось вернуть <сумма>». После погашения всего обязательства — «Деньги возвращены»; формы и кнопки больше нет. При отмене с чеком на проверке и без подтверждённых денег применяется [решение блока 3](after-order.md#9-решения-андрея), формы до появления возврата нет.

### 3.5 Статистика магазина и товара · продавец, O9

| Экран / шаблон | Состав сверху вниз | Действия и состояния |
|---|---|---|
| «Статистика» · подменю `list` | Два `ListItem`: «Статистика продаж» и «Обзор продаж» | Входы и состояния §14.1–§14.5 |
| «Статистика продаж» · `list` | Период, товары по убыванию проданного количества, полоса и количество в каждой строке | Отчёт товара, догрузка и состояния §14.2–§14.5 |
| «Обзор продаж» · `home` (вложенный) | Период, карточки «Выручка», «Заказы», «Средний чек» (подпись по §9.1); `Switch` «Сравнить с прошлым периодом»; график выбранного показателя; раскрываемые «Данные по дням» | Нажатие показателя меняет выделение и график, ссылка «Выполненные заказы» открывает список §1. Точка графика по нажатию или фокусу показывает значения и даты текущего и сопоставленного прошлого интервала; прошлая серия — пунктиром. Выключение сравнения скрывает вторую серию и процент. Таблица открывается отдельной кнопкой, дневной шаг неизменен. |

Заказ с несколькими единицами одной фасовки учитывается один раз; в «Все фасовки» заказ с несколькими фасовками того же товара также считается один раз |

В «Обзоре продаж» «Нет продаж» означает отсутствие выполненных заказов в выборке. При нулевой выручке после возврата показываются выполненные заказы. Состояния рейтинга и товара — §14.5. «Нет данных для сравнения» — если за прошлый период нет выполненных заказов; ноль за непустой период остаётся значением. Ошибка графика — «Не удалось загрузить график» и «Повторить» только для графика; фильтр доступен. Защита данных как в §3.1, в том числе при входе из карточки товара.

В «Деньгах» и статистике рядом с неполным показателем — «Данные за период неполные». Подтверждённую часть показываем числом, при отсутствии подтверждённого значения выводим «—». Процент по такому показателю скрыт при неполноте любого из двух периодов. Полнота остальных показателей определяется отдельно (§10.2).

### 3.6 Общие состояния и доступность

Все экраны используют [шаблоны и состояния](../design-system/templates.md) и [DESIGN](../DESIGN.md). Первая загрузка — каркас без нулей; при следующем чтении видимый фильтр и выбранный период сохраняются. Для сети — «Нет соединения», для ошибки чтения — «Не удалось загрузить данные» и «Повторить» по §5. При изменении данных перечитывается затронутое представление; результаты не переносятся между периодами. При отказе доступа кеш и действия сразу скрываются. Ошибка записи сохраняет исправимые поля и не показывает успех до ответа. Размер касания от 44 px; поля, выбор показателя, переключатель, точки графика и таблица доступны с клавиатуры; на ошибке фокус в первое неверное поле, при закрытии шторки — на кнопку открытия. Для сумм — цифровая клавиатура с точностью валюты, для реквизитов и комментария — текстовая. Используются существующие токены, карточки, списки и шторки.

## 4. Сервер · команды, согласованность и бюджет

Входы ниже дополняют существующие контракты. Команды продавца принимают `expectedRevision`, покупателя — `expectedVersion`; для всех записей обязателен `Idempotency-Key`. Успех отдаёт актуальный ответ заказа этой роли (с обязательством и новым состоянием), без лишнего чтения обзора. Чтения начинаются с проверки сессии, магазина, членства и права или владения заказом; доступ в заказ продавца и его список следует действующим правилам `orders`, в финансовые данные, команды и файлы — `payments`.

| Команда | Дополнительный вход | Результат |
|---|---|---|

Порядок записи: сессия, магазин и право; принадлежность заказа и переданных объектов; поиск результата повтора; ревизия; бизнес-условия. Тот же ключ и то же тело возвращают прежний результат, другое тело даёт `IDEMPOTENCY_CONFLICT`. При двух командах с одной ревизией проходит первая допустимая, вторая получает актуальное состояние и требует нового подтверждения. Такой же порядок для гонок замены чека, его подтверждения, передачи реквизитов и закрытия возврата. Повтор команды после потери ответа использует прежний ключ и тело. Денежные команды сохраняют этап исполнения; оплата при выдаче остаётся атомарной с этапом по блоку 5.

В одной транзакции с записью меняются заказ, история, финансовая проекция, связанные итоговые данные, ревизия и результат повтора. Уведомления используют существующие события и outbox, один раз на событие и получателя. Канал — бот магазина по [BOT1](../tasks/BOT1.md); при отсутствии бота денежное состояние остаётся в карточке заказа. Реквизиты, QR и содержание чека отсутствуют в открытой истории, уведомлениях и метриках. Привязку новых данных проверить при слиянии гостевого профиля, выходе, отзыве доступа, уборке временных вложений и удалении магазина по действующим операциям.

O9 использует проекции итогов магазин × день и товар/фасовка × день. Для однодневного графика требуется компактная почасовая разбивка дня по времени выполнения, с корректными локальными границами при 23/25 часах. Выполнение, откат, отмена выполненного заказа и проведение возврата атомарно меняют вклад заказа. При откате прежний вклад удаляется, следующее выполнение добавляет один вклад по новой дате завершения. Первичное заполнение из истории идемпотентно и согласовано с одновременными записями; что можно восстановить без догадок — §10.2. Результат сверяется с независимым расчётом на той же тестовой истории. При чтении рейтинга сервер объединяет каталог и агрегаты выбранного периода по ID товара, вычисляет порядок и полосы один раз для ревизии выборки. Для следующей страницы проверяет период и ревизию курсора по §2 и §14.2. Каталог и подменю не запрашивают показатели отдельных товаров. Все чтения O9 проверяют сессию, магазин и `payments` до выдачи данных.

[PERFORMANCE §6](../PERFORMANCE.md#6-измерение-и-бюджеты) задаёт пределы карточек продавца ≤4 SQL и покупателя ≤3 SQL. При совпавшей ревизии денежной выборки проверяется сессия и ревизия, финансовая проекция не читается. Полные чтения используют индекс магазина и периода/статуса, курсор и пакетное чтение. Числовые бюджеты SQL и прочитанных строк для новых чтений фиксируются по первой рабочей реализации в budget-тестах. Размер страницы ограничивает работу списка, статистика читает агрегаты периода без сканирования заказов и запросов на каждый товар. Приёмка включает малую и большую историю и измерение роста агрегатов по дням и проданным сочетаниям, включая почасовую разбивку.

## 6. Правила расчёта

1. **П1 · Два измерения дат.** Поступления и возвраты обзора относятся к датам фактических записей. Исправление корректирует сумму за исходный день поступления по §10.1. Список открытых задач и «К получению сейчас» не зависят от периода. Открытые поступления учитываются один раз по обязательству, включая находящиеся на проверке. Неоплаченный заказ без открытой финансовой задачи не создаёт долг по [§4.3 блока 5](seller-orders.md#43-оплата-доступ-и-запись).
2. **П2 · Деньги магазина.** Отдельная доплата не меняет первоначальную оплату. Чек, реквизиты и списание долга не создают поступления. Платёж напрямую курьеру исключён из операций, обязательств и выручки магазина по [D18](../DECISIONS.md). При отмене открывается возврат только фактически подтверждённых денег за вычетом проведённых возвратов, а поступление по уже отменённому заказу не восстанавливает заказ.
3. **П3 · Выручка и единицы.** Заказы в статусе `completed` учитываются по дате выполнения. Стоимость товаров и доставки магазина берётся из снимка заказа после скидок. Поздний возврат уменьшает выручку за дату выполнения в пределах стоимости соответствующей части заказа. Одно уменьшение цены учитывается один раз: если уменьшение уже вошло в итоговый состав или тариф, проведение выплаты отражается в операциях, а та же разница второй раз не вычитается из выручки. Проданное количество — из выполненного состава; оплата возврата сама по себе его не меняет (§9.2). Статистика товара исключает доставку.
4. **П4 · Сравнение.** Предыдущий период — столько же календарных дней непосредственно перед выбранным. Точки группируются по §9.3, обе серии показывают фактические границы своих интервалов, крайние интервалы обрезаются по датам соответствующего периода. Недели календарные (понедельник–воскресенье), месяцы календарные; если в одной серии нет сопоставленной точки, её значение показывается как «—». Сравнение итогов использует полные выбранные периоды. Процент при нуле или отсутствующем прошлом значении скрыт. Средний чек — §9.1, округление при отображении.
5. **П5 · Старые операции.** Старая отметка «Вернул» учитывается как закрытый возврат один раз; если выведена операция, она привязана к исходной записи. Отсутствующая сумма или основание для распределения не заменяются текущей ценой и не создают фиктивной даты/строки товара. Порядок отражения неполной истории — §10.2.

Исправленную сумму показываем за исходный день поступления. Если 300 ₽ исправили на 250 ₽, за исходный день в «Получено» отражается 250 ₽. Оба перехода — `push`. При открытии читается только выбранный отчёт. Нижняя вкладка «Деньги» ведёт к денежным задачам и журналу со своим периодом (§3.1–§3.2).

В каждой карточке списка «Товары» отдельная кнопка «Статистика продаж» открывает отчёт этого товара одним нажатием. Предложение по виду — `Button ghost md` в нижней строке рядом с «Наличие» или «Показать», с переносом на отдельную строку при нехватке места. Область нажатия от 44 px, доступное имя включает название товара. Фото и название открывают редактор, флажок меняет выделение, переключатель — наличие.

### 14.2 Рейтинг всех товаров

Шаблон `list`: заголовок «Статистика продаж», кнопка «Период» и обе даты, затем строки `ListItem`. Строка содержит название, число проданных единиц и полосу. Число читается отдельно от полосы, строка целиком открывает отчёт товара, включая нулевой или исторический.

Одна строка на товар. Количество — сумма единиц всех фасовок из выполненного состава по П3. Сервер включает все товары каталога, включая скрытые и с нулём, и исторические позиции с продажами в выбранном периоде. Порядок: количество по убыванию, название, затем стабильный ID. Полоса равна доле от максимума всей выборки. У каждого лидера с продажами полная полоса, при нуле — пустая. Когда известна только часть числа, строка использует подтверждённое число и пометку §10.2. Неизвестные количества идут после известных, показываются как «—» с той же пометкой и без полосы.

«Показать ещё» видна при наличии следующего курсора и блокируется до ответа. Новая страница добавляется к текущим строкам. Смена периода или устаревшая ревизия курсора возвращают к первой странице соответствующей выборки. Лимита «топ-N» нет. Ошибка догрузки описана в §14.5.

### 14.3 Период и возврат

В рейтинге и отчёте товара шторка «Период» предлагает «1 неделя», «2 недели», «3 недели», «4 недели», «Свой период». Пресеты — 7, 14, 21 и 28 завершённых календарных дней по вчера включительно в часовом поясе магазина. По умолчанию одна неделя. Две даты отображаются под кнопкой выбора, у «Своего периода» обе даты включены. Поля, ошибки и действие «Применить» — §3.2. «Обзор продаж» сохраняет свой набор фильтров из §3.2.

Из рейтинга отчёт получает применённые даты и «Все фасовки». Из списка «Товары» — одну неделю и «Все фасовки». Отчёт хранит применённый период и фасовку в ссылке (§1). «Назад» восстанавливает период, догруженные строки и прокрутку рейтинга либо поиск, фильтры, догруженные строки, выделение и прокрутку списка «Товары». Изменение фильтров в отчёте не меняет выборку источника. Ссылка с датами фиксирует интервал и после полуночи. Новый вход без дат рассчитывает период на момент открытия.

### 14.4 Отчёт товара

Один экран «Статистика товара» для обоих входов, шаблон `home`: название товара, «Период» с датами, «Фасовка» (`Select`), показатели «Продано», «Заказы», «Выручка» (§3.5, §6 и §9). «Все фасовки» включает архивные продажи. Архивную фасовку можно выбрать отдельно с пометкой «Архивная». Открытие отчёта и смена применённого периода или фасовки читают `SellerProductSales`. Кнопка «Применить» не отправляет повторный запрос при ожидании. При выборе другого фильтра результаты старого запроса не подменяют текущую выборку.

Под «Продано» показать «При таком темпе за неделю — около N шт.». Основание — продажи выбранного товара или фасовки за показанные даты. N = проданное количество × 7 / число календарных дней включительно. Округлить до ближайшего целого, половину вверх. При положительной оценке меньше одной единицы показать «меньше 1 шт.». Для 30 проданных за 14 дней показать «Продано 30 шт.» и ориентир 15 шт. При полном нуле показать «За период продаж не было». При неполном количестве, незавершённых или будущих днях в выборке оценку скрыть. Для архивной позиции показывать только историю продаж. Расчёт использует поля уже открытого отчёта.

Решение Андрея: в O9 показываем недельный ориентир по фактическим продажам. Объём закупки продавец определяет сам. Подсказка «Докупить» с учётом остатка и нехватки отложена.

### 14.5 Состояния и доступность

| Состояние | Что видно и что можно сделать |
|---|---|
| Загрузка рейтинга или отчёта | Каркас без нулей по §3.6. При смене выборки сохраняются текущие фильтры и навигация. Активный запрос догрузки блокирует только «Показать ещё» |
| Рейтинг без строк / все количества равны нулю | «Пока нет товаров» при пустом каталоге без исторических продаж. При известных нулевых продажах все товары остаются, с числом 0 и пустой полосой. У товара с полными нулевыми показателями — «Продано 0», «Заказы 0», «Выручка 0 ₽» для магазина в рублях |
| Неполная история | «Данные за период неполные» у затронутого показателя, подтверждённое число или «—» по §10.2. Остальные показатели сохраняются |
| Сеть / ошибка загрузки и догрузки | «Нет соединения» / «Не удалось загрузить данные», «Повторить» для того же периода и фасовки. При ошибке догрузки прежние строки и прокрутка сохраняются, повтор запрашивает ту же страницу. Фильтры доступны |
| Данные изменились | Перечитать видимую выборку по §2. Если ревизия догрузки устарела, «Список изменился», первая страница за прежний период. Невалидная дата и недоступная фасовка — §3.2 и §5 |
| Нет доступа / товар недоступен | Права на O9 проверяются по §3.5 и §4. Без `payments` скрыты карточка «Статистика» и кнопки в списке товаров, прямой вход показывает «Доступ ограничен» и «Назад» без данных. В доступном для чтения каталоге кнопка отчёта зависит от права O9 отдельно от возможности редактировать товар. В режиме «Только просмотр» с правом O9 кнопка видна и работает. При отзыве прав суммы и строки исчезают сразу. Несуществующий или чужой товар — §5 |

Шапка, шторка и состояния — из UI-кита по §3.6. Кнопки и строки доступны с клавиатуры. Шторка поддерживает фокус на неверной дате и возврат фокуса к кнопке «Период». В панели «Состояния» холста доступны загрузка, пусто, все нули, неполная история, сеть, ошибка чтения и догрузки, обновление данных и отказ в доступе.

### 14.6 Границы и приёмка

За две недели продано 30 багетов, 15 батонов и 0 упаковок сухарей: полная, половинная и пустая полосы. Для проверки исторической строки добавить архивный товар с продажей, для догрузки — вторую страницу. В каталоге открыть сухари своей кнопкой и увидеть «Продано 0».

На 360 и 390 px пройти сценарии 20–23 из §7. В этой ревизии нет входа из редактора или с витрины покупателя, правки остатка, списка заказов с недостачей, просмотров и эффектов продвижения.
