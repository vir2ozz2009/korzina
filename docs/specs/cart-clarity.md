## 1. Путь

1. Витрина → `/cart` (`push`, действующий вход). Сервер сообщает эффективный способ получения; для нового заказа это доступная доставка, иначе самовывоз, иначе недоступное состояние (§6.П5–П8).
2. Подпись применённого комбо → компактная `Sheet` с именем выбранного комбо → крестик/штатный жест/«назад» → та же корзина, прежняя прокрутка и фокус на подписи. Открытие/закрытие ничего не сохраняет на сервере. Самостоятельного URL шторки нет; обновление страницы возвращает в корзину.
3. Обычный код → действующая шторка ввода/сравнения → применить → сообщение по типу и результату сервера. Замена, отмена сравнения и удаление сохраняют прежние переходы 12.1.
4. Доставка ↔ самовывоз → действующая команда сохранения → серверный способ/тариф/итог обновляются вместе. При доставке без адреса — «Укажите адрес доставки», затем штатная шторка адреса. «Продолжить» открывает существующий следующий шаг покупки.
5. Назад из оформления, refresh и повторный вход в текущую незавершённую корзину сохраняют явный выбор покупателя. Успешное создание заказа завершает этот выбор; получение следующего заказа определяется заново. Ждать выдачи/оплаты/выполнения заказа для сброса не нужно.
6. В кабинете продавца → существующий изолированный «Пример корзины» → та же шторка комбо. Пример не изменяет реальную корзину, получение, остатки и лимиты.

## 2. Данные

Суммы — целые минимальные денежные единицы валюты магазина; форматирование — действующий `formatMinor`. Сервер остаётся источником цен, количества применений и доступности. Клиент не выводит стоимость комбо из общего итога корзины, сумм полных товарных строк или самостоятельно распределённых долей.

| Данные / контракт | Требуемое содержание и источник |
|---|---|
| `Cart`, `CartAdjustment` (`src/shared/contracts/cart.ts`) | Действующие `revision`, `currency`, `sourceId`, `label`, `amount`, `groups.{type,count,possible,limit}`, `allocations`. Скидка выбранного комбо — `-amount`, только его фактически применённые группы. |
| Дополнение `CartAdjustment.bundleDetails` для `groups.type=bundle` | Серверная проекция: `components: {variantId:string,name:string,unit:string,quantity:number}[]` (состав **одного** набора), `unitPriceMinor:number` (цена набора), `totalMinor:number` (цена только применённых наборов выбранного комбо). `totalMinor = unitPriceMinor × groups.count`. Экономия — действующий `-amount`. Состав и цена соответствуют применённой ревизии. Не новый расчёт скидок. |
| `promo.codeKind` и `promo.alternative.codeKind` | Серверная классификация распознанного введённого кода: `discount | bundle | gift`; для неизвестного/нераскрываемого кода поле отсутствует. Успешный обычный код: `reason=applied`, `codeKind=discount`. Тип не определять по символам кода. |
| Получение (`src/shared/contracts/receiving.ts`, ответ `/api/receiving`) | Добавить серверный `effectiveMode: delivery | pickup | null`, согласованный с доступностью и сводкой оформления. Выбранный адрес остаётся в `receiving`; `receiving=null` допустим при эффективной доставке без адреса. Не подделывать валидный `Receiving` пустым адресом. |
| Состояние текущего выбора | Сервер различает явный выбор покупателя и автоматический начальный способ. Конкретное хранение и расширение команды определяет реализация до UI; API должен позволять выбрать доставку до сохранения адреса, не создавая фиктивного адреса. Источник выбора и правила переноса — §6, предложения §9. |
| Адреса / снимок заказа | Сохранить `savedAddresses`, `lastUsedAddress`, `deliveryDraft`, их версии и изоляцию. Заказ сохраняет прежние финансовые `allocations`/оплаченные единицы. UI-проекция не заменяет снимок и не запускает перерасчёт прежнего заказа. |

Новые поля сначала согласовать в shared-контракте и сервере, затем использовать в потребителях/моках холста. Прежние ответы и незавершённые корзины не должны приводить к исключению: при неполной проекции шторка показывает состояние проверки и повтор; итог всей корзины как запасную цену комбо не использовать.

Чтение — действующие запросы корзины, получения и сводки оформления, существующие ревизии/живые обновления и кеш по [PERFORMANCE](../PERFORMANCE.md). Новый endpoint для шторки, отдельный polling и чтение каталога на каждое открытие не нужны. Ответы реальной корзины и примера содержат одинаковые поля описания комбо. После изменения количества, SKU, кода, цены/остатка или условий сервер обновляет расчёт; открытая шторка привязана к `sourceId` в **текущем** ответе, не к старому объекту.

## 3. Экраны

Общие каркас, отступы, цвет, типографика, нижнее действие и переходы — [DESIGN §2–5, §5а](../DESIGN.md), действующие UI-кит/токены. Перерисовки остальной корзины нет.

### 3.1 Шторка выбранного комбо

Назначение: объяснить состав и стоимость только выбранного комбо. Шаблон — действующий `Sheet`, вход из подписи применённого комбо в реальной корзине или примере продавца.

| Сверху вниз | Компонент | Данные / точный текст / когда |
|---|---|---|
| Заголовок, крестик и ручка | `Sheet`, штатная кнопка закрытия | Только имя продавца, например **«Комбо тест»**. Без общего заголовка «Почему такая сумма» и второго повторения имени. |
| Пояснение состава | Текст `text-caption` | «В одном наборе» только при `count>1`. |
| Строки состава | Текстовые строки в `Sheet` | `<Название> · <фасовка> × <количество в одном наборе>`. Например «Голубика · 125 г × 1», «Молоко · 500 мл × 1». Без цен/оплаченных долей компонентов. Длинный текст переносится. |
| Цена одного набора | Текст с выделенной суммой | При `count=1`: **«За набор — 60 000 ₫»**. |
| Несколько применённых наборов | Текст, выделенная сумма | При `count>1`: «2 набора × 60 000 ₫», затем «Стоимость наборов — 120 000 ₫». Числа и склонение фактические. Это сумма только выбранного комбо. |
| Экономия | Текст | **«Экономия 11 000 ₫»** для одного; «Экономия 22 000 ₫» для двух из того же примера. |
| Объясняющий лимит | `text-caption` | «По акции 2 из 3 наборов» только если `limit` задан, `count >= limit`, `possible > count`: неприменённые полные комплекты объясняются исчерпанным лимитом. При `limit=null/нет лимита`, при полном применении или проигрыше пересечению без исчерпания лимита эту строку не показывать. |

Нет «Наборов по акции — 1», таблицы `quantity × paidMinor`, цены полной товарной строки, общей суммы товаров/корзины, доставки и кнопки оформления внутри этой шторки. Общий итог **в основной корзине** остаётся на своём месте. Для подарка N+M действует прежняя шторка с оплаченными и бесплатными единицами; ветку подарка не упрощать.

| Действие | Результат / запрос | Блокировка |
|---|---|---|
| Подпись применённого комбо | Открыть текущий `sourceId`; дополнительного запроса нет | При пересчёте/ошибке не открывать неподтверждённые суммы |
| Крестик, жест, Escape/назад | Закрыть и вернуть фокус/прокрутку | Закрытие доступно и при ошибке |
| Серверный ответ при открытой шторке | Обновить состав/число/цену/экономию целиком; исчезнувшее комбо закрыть | Пока расчёт неподтверждён, денежные значения заменить состоянием проверки |

Состояния и восстановление — §3.4. Доступность: заголовок диалога = имя комбо, штатная ловушка/возврат фокуса, зона закрытия ≥44 px; на 360/390 нет горизонтальной прокрутки, при длинном составе доступен скролл. Новых полей ввода нет, клавиатура не открывается.

### 3.2 Обычный промокод

Назначение: объяснить область успешно применённого обычного скидочного кода. Используются действующие `ListItem compact`, `Input`, `Button`, `Sheet` и сравнение 12.1.

| Элемент | Данные / текст |
|---|---|
| Заголовок строки | Введённый код из ответа сервера либо прежнее «Промокод» |
| Подпись успешного обычного кода | **«Применён к товарам без скидки»**, только `applied + discount`; заменяет прежнюю подпись «Промокод применён», не дублирует её отдельным абзацем |
| Уточнение условий обычного кода | **«Промокод действует на товары без скидки»** при известном типе `discount`, когда требуется подсказка/причина `regular_price`; не универсальная оговорка для пустого поля с ещё неизвестным типом |
| Код комбо/подарка | Действующее нейтральное подтверждение «Промокод применён» и его действующие условия; подписи обычного кода нет |
| Не применён / проиграл автоматике | Действующие причины из `promo-message.ts`, включая «Скидка магазина выгоднее»; подписи успеха нет |

Применить/заменить/сравнить/оставить/убрать — прежние действия и команды 12.1 с той же ревизией и ключом повтора. Pending блокирует повторную отправку и конкурирующую замену; неизвестный код не стирает действующий. На ошибке фокус остаётся у поля, введённое сохранено. После удаления исчезает подпись успеха. Остальные тексты и состояния — [12.1](promo-discounts.md#5-ответы-и-восстановление), без попутного редактирования.

### 3.3 Получение в текущей и следующей корзине

Назначение: показать серверный способ получения и сохранить выбор внутри незавершённого заказа. Шаблон — текущий `CartShipping` в корзине покупки, штатные карточки-радио и `ListItem` адреса.

| Элемент | Данные / текст / когда |
|---|---|
| Способы | «Доставка» / «Самовывоз», текущие иконки и описания. Выбор соответствует серверному `effectiveMode`, недоступный способ не выбирается. |
| Доставка без адреса | Выбрана доступная доставка; строка **«Укажите адрес доставки»**. Стоимость — действующее «Рассчитаем по адресу», не ноль/«Бесплатно» без серверного основания. |
| Сохранённый подходящий адрес | Действующее восстановление/повторная проверка адреса. Неподходящий сохранённый адрес не подтверждать автоматически: показать необходимость указать/проверить адрес доставки. Адрес можно исправить штатным действием; его наличие не превращает прошлый самовывоз в предпочтение нового заказа. |
| Только самовывоз | Выбран самовывоз, показаны адрес и часы. Нет переключения в отсутствующую/приостановленную доставку. |
| Нет доступных способов / пауза | Текущие причины сервера и «Получение пока недоступно»; при общей паузе — действующий баннер. Пауза не удаляет адреса/намерение, оформление заблокировано по прежним правилам. |
| Сумма/нижнее действие | Прежние серверный тариф, подписи и проверки покупки; не подменять итог только визуальной сменой radio. |

Выбор самовывоза/доставки — сохранить актуальную ревизию, затем показать согласованные способ/адрес/тариф. Нажатие доставки фиксирует намерение и при ещё не заполненном адресе; закрытие ввода адреса не означает выбор самовывоза. На время сохранения блокировать повторный выбор и переход к оформлению. Ввод/редактирование адреса — действующая шторка и проверки; на ошибке введённое не терять. Никакого автоматического выбора недоступной доставки или подтверждения неизвестного адреса.

Если ранее выбранный способ стал недоступен, показать причину и действующий доступный вариант согласно серверу. Недоступное намерение не использовать для тарифа/оформления; его сохранение в черновике не означает, что radio может остаться на недоступном способе.

### 3.4 Состояния, общие для затронутых частей

| Состояние | Что видно | Действия / восстановление |
|---|---|---|
| Первый запрос | Штатный скелетон; нет выдуманного способа и цены комбо | Дождаться ответа; закрытие/назад доступны |
| Пустая корзина / нет комбо | Прежнее пустое состояние / нет подписи комбо и его шторки | Вернуться в каталог; вопрос сохранения выбора при ручной очистке — Q1 |
| Пересчёт / изменились данные | «Проверяем корзину…»; суммы открытого комбо не выдаются за актуальные | После ответа обновить единым снимком; при review — штатное подтверждение покупки |
| Комбо исчезло / выключено | Шторка закрыта, корзина показывает новый расчёт | Продолжить доступные действия; старый `sourceId` не открывает старую цену |
| Ошибка / нет сети | Прежняя ошибка и «Повторить»; при сетевой ошибке команды кода — «Нет связи. Повторите.» | Сохранить ввод/намерение, получить свежую ревизию; не показывать неподтверждённую скидку/доставку как принятую |
| Сохранение / повтор команды | Прежний loading; конкурирующие действия заблокированы | По ответу показать текущее состояние; повтор не создаёт новый заказ/сброс выбора |
| После оформления | Прежний экран готового заказа; его способ и суммы по снимку | Следующая корзина начинается заново по §6.П7, даже если в ней остались недоступные строки |

## 4. Сервер: команды и правила

| Путь / действие | Проверки и результат |
|---|---|
| `GET /api/cart`, изменение корзины `POST /api/cart` | Сессия/магазин/ревизия, существующий денежный расчёт. Добавить согласованную проекцию выбранных наборов и тип введённого кода; не читать историю заказов/каталог на каждое открытие шторки. |
| `POST /api/seller/promotions/example` | Прежние права, изоляция и учебный расчёт одной акции; та же проекция/подписи, реальное получение не записывается. |
| Команды промокода `POST /api/cart` | Прежние apply/compare/keep/remove, `expectedRevision`, `Idempotency-Key`, ошибки и защита проигравшего кода. Метаданные типа относятся именно к текущему/сравниваемому коду, не к первой найденной акции. |
| `GET /api/receiving`, сводка/quote | Одинаковое правило `effectiveMode` из явного выбора и текущей доступности. Отсутствие адреса не равно недоступности самой услуги: доставка может быть начальным способом с необходимостью указать адрес. За пределами зоны нельзя оформлять как доступную доставку. |
| `POST /api/receiving` | Действующие сессия, магазин, `expectedRevision`; сохранить выбор/адрес и согласованную доступность. Для выбора доставки без адреса минимально расширить команду до UI, не ослаблять валидацию адреса при оформлении. Действующий receiving защищён ревизией: повтор может вернуть конфликт с актуальным состоянием, но не второе изменение. Новый протокол идемпотентности для всего получения не вводить. |
| `POST /api/checkout` | Прежние актуальные условия, quote, оплата/остатки/лимиты. В **той же транзакции успешного создания** снять относящиеся к оформленному заказу активный способ, комментарий и время; сохранить адресную книгу/подходящий последний адрес. Новый начальный способ определяется сервером. Повтор с тем же ключом возвращает прежний заказ и не очищает заново уже наполненную следующую корзину. Ошибка checkout ничего не сбрасывает. |
| Повтор/слияние/ручное опустошение | Текущие команды сохраняются; новые признаки выбора подключить к этим операциям после решений Q1–Q4. Они не дают старому способу оформленного заказа незаметно стать новым явным выбором. |

Новые записи в историю и уведомления: нет. Новые внешние вызовы: нет; адресный геокодер и его кеш — без изменений. Сохранить бюджет [PERFORMANCE §6](../PERFORMANCE.md#6-измерение-и-бюджеты); не добавлять SQL/N+1 ради пояснения, не повышать бюджеты. Регрессии денег/заказа, прав, изоляции, гонок и слияния остаются в Check. Финансовые доли и прежние заказы не перерасчитываются.

## 5. Ошибки сервера → поведение экрана

| Код / причина | Что сохраняется и что видит покупатель | Действие |
|---|---|---|
| `VERSION_CONFLICT`, `QUOTE_CHANGED` | Актуальная ревизия вместо старых цен/выбора; ввод кода/адреса сохранён как черновик | Перепроверить; для покупки принять новые условия штатно |
| `OUT_OF_ZONE`, адрес/район обязателен, неполные детали | Способ доставки не выдаётся за подтверждённую услугу; введённый адрес не стирается | Исправить адрес или явно выбрать доступный самовывоз |
| `PICKUP_UNAVAILABLE`, доставка выключена/на паузе | Причина сервера у способа; данные адресов сохранены | Выбрать доступный способ; если нет — оформление недоступно |
| Причина кода `regular_price` | «Промокод действует на товары без скидки», без подписи успеха | Добавить обычный подходящий товар, изменить/убрать код |
| Другие причины кода, `FORBIDDEN`/выключенный модуль, недоступная сессия | Действующее поведение 12.1; чужие/скрытые предложения не раскрываются | Исправить условия/войти/убрать код; прежние заказы доступны по прежним правам |
| Сетевая ошибка | Не утверждать успех; показан повтор; сохранены код/адрес/намерение | Повторить по текущему протоколу, затем показать серверный ответ |

## 6. Правила и уже принятые решения

Каждый П1–П9 — требование принятого решения CART-CLARITY, а не вопрос о концепции. Для реализации правило получает тест денег/состояния с номером пункта; вид/текст проверяются в существующем smoke, без тестов CSS и строк ради строк.

1. **П1 · Только выбранное комбо.** Шторка показывает имя, состав, стоимость только применённых наборов этого `sourceId` и их экономию. Посторонние товары, другие комбо и доставка эти суммы не меняют.
2. **П2 · Фактическое количество.** Для нескольких наборов состав дан на один, цена/экономия — на применённое число. Лишние единицы компонента не включаются в цену выбранного комбо; лимит объясняется только при его фактическом влиянии.
3. **П3 · Без бухгалтерских долей в UI комбо.** Распределение по товарам сохраняется на сервере/в снимке для заказа и возврата; N+M сохраняет принятое объяснение. Изменения расчёта исправленного FIX-PROMO-OPT не входят в задачу.
4. **П4 · Тип обычного кода.** «Применён к товарам без скидки» только для успешно применённого обычного кода по серверному типу. Не для проигравшего кода, кода комбо, N+M или будущей доставки.
5. **П5 · Новый начальный способ.** Доступна доставка → доставка; иначе доступен самовывоз → самовывоз; иначе нет выбранного способа и действует штатное недоступное состояние. Отсутствующий адрес запрашивается отдельно, не заменяет способ самовывозом.
6. **П6 · Текущий заказ.** Явный выбор действителен в текущем незавершённом заказе, сохраняется при назад/refresh/повторном входе и пересчёте акции. Тариф и оформление используют тот же серверный способ. Выключенный/недоступный способ не становится доступным из-за сохранённого выбора.
7. **П7 · Следующий заказ.** Только успешное создание заказа завершает текущий выбор: прошлый самовывоз не наследуется. Это относится и к оставшимся недоступным строкам. Повтор checkout не сбрасывает новый выбор/товары следующей корзины; ошибка оформления сохраняет прежний выбор.
8. **П8 · Адреса.** Смена начального способа не удаляет адресную книгу/последний подходящий адрес. Повторное использование адреса проходит действующие проверки и не отменяет явный самовывоз текущего заказа.
9. **П9 · Актуальность и паритет.** Шторка живёт по текущему `sourceId`/ревизии, исчезнувшая акция закрывает её. Пример продавца отображает такой же смысл цены и подписи, сохраняя собственную изоляцию.

Рыночная сверка 27.11.2026: [WooCommerce](https://woocommerce.com/document/setting-up-shipping-zones/#sort-shipping-methods-and-set-a-default) выбирает начальный способ из включённых методов подходящей зоны. Для Korzina это подтверждает проверку доступности, но приоритет доставки — собственное уже принятое решение Андрея.
