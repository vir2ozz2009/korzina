## 1. Путь

Продавец нажимает «Акции» в нижнем меню → «Продвижение» (список) → «Создать акцию» (шторка «Чего хотите добиться?») → цель → подходящий вариант → форма с выбранными условиями. Из той же шторки есть путь «Все виды акций» → вид → форма. Оба пути ведут к одному предложению. Далее продавец может проверить пример или открыть сводку сразу. Оба пути сходятся на подтверждении публикации (§13). «Назад» возвращает к предыдущим значениям и фильтру. Из проверочной корзины можно вернуться к условиям. «Сохранить черновик» сохраняет его в магазине, повторное открытие поднимает сохранённую версию. При выходе из изменённой формы дать сохранить или отбросить изменения.

Покупатель открывает «Корзину» → «Промокод» → «Применить». Строка с кодом открывает «Заменить» и «Убрать». После выбора нового кода шторка сравнивает два итога, «Заменить код» сохраняет новый выбор, «Оставить прежний» закрывает шторку. После возврата из оформления или перезагрузки восстанавливается код своей корзины и свежий расчёт. После входа через Telegram применяются правила объединения корзин B6 и условия текущего покупателя. Если у обеих корзин разные коды, предложить выбор с обоими итогами, сохранить один по подтверждению. Прямая ссылка на предложение проверяет магазин, доступ и актуальную ревизию.

## 3. Экраны

Предлагаемая компоновка по UI-киту. Шапка, списки, поля, строки суммы, кнопки и шторки — компоненты существующих экранов. Минимум 44 px для нажатия, на 360 и 390 px проверить все шесть нижних вкладок, включая «Деньги» и «Ещё». После открытия шторки фокус в первом поле, после ошибки — в проблемном, после закрытия — на вызвавшей кнопке. Клавиатура суммы цифровая, кода текстовая. Статус и ошибка читаются текстом.

Для всех экранов: загрузка — штатный скелетон, при ошибке чтения — «Не удалось загрузить» и «Повторить». При отсутствии сети сохранить введённые значения и показать «Нет связи». Пока идёт запись, недоступно повторное действие; прежние данные остаются на экране. Устаревший ответ не заменяет более свежий расчёт.

## 4. Сервер и команды

Контракт ниже описывает поведение новых операций. Обработчики и способ хранения выбираются при реализации.

| Команда и вход | Проверки → ответ и эффект |
|---|---|
| Список / карточка (фильтры или id) | Сессия, магазин, доступность дополнения, роль → разрешённые данные и действия. Один переключатель «Акции» на магазин для 12.1–12.3, по умолчанию включён у существующих и новых магазинов ready. Явные исключения сохраняются. Состояния предложений и права изолированы по магазину |
| Сохранить / опубликовать / отключить / включить / повторить (условия или id, ожидаемая версия, ключ повтора) | Владелец или управляющий. Проверять право на каждую команду. Уникальность введённого кода среди одновременно применимых предложений магазина независимо от вида; проверять при публикации и смене срока. Сумма больше нуля, процент до 100 включительно, условия и фасовки принадлежат магазину. Атомарно записать версию и обновить доступный покупателям список. Записать автора и время |
| Проверить пример / предложить замену (корзина, кандидат, контекст) | Сервер учитывает только подходящие доступные позиции, условия, версии и время. Возвращает оба итога при замене. Чтение; сохраняемый код и лимит прежние. Подтверждение замены с версией пересчитывает условия перед записью |
| Оформить (B10, quoteRevision, ключ повтора) | Сверить остатки, цены, получение, право покупателя, расписание и лимиты в транзакции заказа. Записать сумму, распределение и использование выигравшего кода вместе. Параллельное оформление не может занять одно последнее применение дважды. При ошибке не остаётся списания |
| Полная отмена до выдачи (событие заказа) | Освободить общий и личный лимиты использованного кода ровно один раз. Для разовой покупки с точным номером освободить также занятое право и лимиты выигравшего предложения независимо от способа применения (§10). Частичный возврат суммы/товара сохраняет использование. Старая цена заказа и события денег берутся из снимка. Повтор использования только по действующим условиям |

Один расчёт для примера, корзины, оформления и снимка. Перечитывать затронутые ревизии по смене состава, цены, покупателя, адреса, тарифа, срока, публикации и доступности. Не выполнять запрос на каждую фасовку и каждое сочетание. Бюджеты горячего пути — [PERFORMANCE §6](../PERFORMANCE.md), проверки — [TESTING](../TESTING.md). Фоновые рассылки при публикации отсутствуют.

## 5. Ответы и восстановление

| Причина / код | Что видит человек и что может сделать |
|---|---|
| Код неизвестен, истёк, отключён, исчерпан | «Код не найден», «Срок действия закончился», «Код больше не действует», «Лимит исчерпан» соответственно. Исправить или убрать; неудачная замена сохраняет прежний код |
| Личный лимит / нужна идентификация | «Вы уже использовали этот промокод» или «Подключите Telegram, чтобы проверить условия». После входа пересчитать. Гость может продолжить покупку без персональной скидки; телефон из оформления не удостоверяет личность |
| Недостаточно подходящих товаров | «Добавьте подходящих товаров ещё на …» с суммой или количеством. По достижении порога пересчитать |
| Устаревшая форма / QUOTE_CHANGED | Продавцу — «Условия уже изменились», перечитать карточку; покупателю — обновить расчёт и подтвердить новый итог. Сетевой повтор команды не создаёт второй заказ |
| Доступ закрыт / дополнение выключено | Скрыть вход и отказать в прямом запросе. Публичный ответ о чужом коде совпадает с неизвестным кодом. Прежние заказы доступны по обычным правам |

## 6. Правила

1. Одна область ввода, один ручной код, одна общая скидка на корзину. При равной выгоде ручного кода и автоматики выигрывает автоматика. Проигравший код виден, расход равен нулю.
2. Минимум оформления B10 проверять по товарам после позиционных скидок и до скидки на корзину, без доставки. Минимум акции — по подходящему подмножеству. В режиме 12.3 третий порог учитывает все подходящие для доставки товары. [Порядок расчёта](../DOMAIN.md)
3. Номер покупки для условия равен количеству выполненных заказов подтверждённого покупателя в данном магазине плюс один. «На первый» соответствует ровно №1, «Только на заказ №N» требует равенства, «Начиная с заказа №N» допускает также последующие номера. Для точного номера разовая выгода защищена с момента оформления в том числе для автоматической скидки (§10).
4. Денежный итог выбирается среди допустимых сочетаний; при известной доставке сравнивать полную сумму покупателя, при неизвестной — известную часть с явной пометкой. Округление один раз по правилам [§5 продвижения](../stories/promo.md); распределить итоговую скидку по подходящим строкам пропорционально их стоимости, оставшиеся минимальные единицы по наибольшим дробным остаткам, при равенстве в стабильном порядке фасовок. Учитывать распределение один раз.
5. Вход «Акции» виден владельцу и управляющему при включённой функции. Правка обычной цены фасовки сохраняет существующие права сотрудника на товары. У магазина с выключенным дополнением продолжают работать существующие цены и настройки доставки.

6. Если после оформления магазин убирает отсутствующую позицию, сохранить скидки оставшихся единиц и уже полученную бесплатную доставку. Вычесть оплаченную долю удалённой позиции из снимка. Для замены показать цену и новый итог, применить после согласия по O6. До оформления корзина пересчитывается по текущему составу. [Изменения заказа](order-changes.md)

## 10. Выбор акции по цели

Задача продавца — подобрать подходящие условия, проверить их на знакомой корзине и решить, сколько скидки он готов предоставить. Цель подставляет условия в существующую форму. Цены, доступность и применение определяет опубликованное предложение. Названия и значения по умолчанию ниже входят в одобренную спецификацию. Ревизия холста проходит отдельное одобрение.

### Вход и переходы

В «Все виды акций» 12.1 три строки: «Скидка» (автоматически; процент или сумма), «Промокод» (процент или сумма; нужен текст кода), «Цена по акции на товар» (выбрать товар и открыть его существующую форму фасовки). Прямые формы скидки/кода начинаются с «Любой заказ» и всех товаров. Для скидки на конкретный товар, фасовку или категорию служит выбор «На какие товары». Лимит кода по умолчанию — один раз на подтверждённого покупателя. Черновик прямой формы может воспроизвести любые условия варианта по цели.

Если из формы по цели поменяли область, номер или способ применения, название, объяснение пользы, предпросмотр и строки результата следуют сохранённым условиям. Для сохранения черновика достаточно обычной команды; неполные обязательные условия подсветить перед публикацией. При открытии сохранённого черновика выбирать цель заново не требуется. Из прямой ссылки на форму выход ведёт в список предложений текущего магазина.

Вход цены по акции открывает каталог в режиме выбора товара с возвратом в «Продвижение». Цена задаётся в редакторе фасовки с правами S2; срок и предпросмотр описаны в §13. Пустой каталог — «Сначала добавьте товар» и переход к обычному созданию товара при наличии права. Собственная строка кампании с отчётом для зачёркнутой цены не создаётся: в карточке товара уже есть «Статистика продаж». Обычная правка товара доступна также сотруднику с правами на товары по прежнему входу.

### Номер покупки и пример перед публикацией

- Номер N — целое положительное. Точный №1 отображать «На первый». Для точного №N требуется ровно N−1 выполненных заказов; для «Начиная с» достаточно N−1 или больше. При первом активном заказе без выполнения следующий заказ не становится вторым. Гость видит «Войти через Telegram и проверить скидку» и может оформить без неё. Номер телефона, адрес, куки и второе устройство не создают новую историю. Один подтверждённый аккаунт ведёт свою историю отдельно в каждом магазине.
- Для первого и точного номера в форме показать «Один раз на покупателя для этой покупки». Переключение на режим «Начиная с» показывает редактируемые лимиты. При нескольких подходящих разовых предложениях сравнить их по общим правилам корзины, занять право только у победителя. При оформлении выигравшей разовой акции фиксировать право по магазину, подтверждённому покупателю и точному номеру покупки одновременно с заказом и лимитом предложения. Одна такая выгода на номер даже при двух разных акциях, авто/коде и параллельном оформлении. Незанятое право не гарантирует скидку, если подходящий номер уже пройден. Механика «Начиная с» проверяет обычные лимиты предложения. Предпросмотр, проигравший код и открытая корзина ничего не занимают. Полная отмена до выдачи освобождает разовое право и соответствующие лимиты один раз; для следующей попытки вновь проверить номер и срок. Частичный возврат расход сохраняет.
- Уже занятое право → «Скидка на эту покупку уже использована» и пересчёт доступных предложений. Недостаточно выполненных заказов → «Скидка станет доступна после первой выполненной покупки» или подстановка требуемого количества. Для прошедшего точного номера → «Эта скидка действует только на заказ №…». При росте итога согласие по B10.
- В предпросмотре показать, кто и когда получит выгоду, фактическую скидку на примере и предел суммы скидок по предложению, когда его можно вычислить. Пример: 10%, не больше 150 ₽ за заказ, общий лимит 20 применений → «Максимум скидок по акции — 3 000 ₽». Фиксированная скидка и конечный лимит дают такую же верхнюю границу. Если общего лимита или денежного максимума нет — показать фактические условия («Без общего лимита применений», «10% от подходящих товаров») и сумму примера. При редактировании действующей акции отличать уже предоставленное от максимума по оставшимся применениям. Величина скидки не предсказывает продажи или прибыль.

## 11. Результаты предложения

Результаты доступны в карточке активной, отключённой или завершённой акции по действующим правам владельца/управляющего. В списке достаточно «18 заказов · скидок на 2 160 ₽» за всё время. В карточке сначала условия, затем «Результаты», период «За всё время» по умолчанию. Доступны последние 7/30 календарных дней и свой диапазон; границы включают местные даты магазина по дате выполнения. Для текущего дня указать «по сейчас». Назад из заказа восстанавливает предложение, период и место в списке. У прежней ревизии и новой версии один id предложения; каждая покупка сохраняет действовавшие условия. Выбор цели не создаёт отдельной кампании.

| Строка в отчёте | Определение, действие продавца |
|---|---|
| «Заказы с акцией» | Уникальные выполненные заказы, где эта акция фактически дала положительную выгоду при покупке. Нажатие открывает список с номером, датой, выгодой именно этой акции, суммой товаров и доступным по правам именем покупателя. Из строки — обычная карточка заказа. Для гостя достаточно «Гость». Пагинация и возврат к тому же периоду |
| «Сумма товаров в этих заказах» | Сумма всех товаров после всех скидок и денежных корректировок по правилам O9. Доставку показывать отдельно. Значение описывает корзины целиком. Для сравнения разных акций нельзя складывать выручку пересекающихся заказов |
| «Скидка по этой акции» | Суммировать фактически предоставленные скидки этого источника по сохранённым строкам, с поправкой на возвращённые единицы. Для A6 — скидка на доставку по подтверждённому тарифу. Расходы на курьера и себестоимость товара по этой сумме неизвестны |
| «Покупатели» | Уникальные подтверждённые покупатели с такой покупкой в периоде. Отдельно вывести число заказов гостей, если оно положительно. Число заказов гостя не превращать в число людей. Общая статистика магазина исключает дубли по orderId; внутри акции — по паре предложение/заказ |
| Показатель по условиям | При точном №1 — «Сделали первую покупку с акцией» (фактически первая выполненная покупка данного аккаунта в магазине). Для точного №N — «Сделали покупку №N с акцией» по фактическому порядку выполнения, а не просто по получению льготы. При разном порядке оформления/выдачи заказ остаётся в «Заказы с акцией», условие выдачи не меняется задним числом. Для «Начиная с №N» — число воспользовавшихся подтверждённых покупателей. Для скидки от суммы — заказы с акцией и средняя сумма товаров в них. Для обычной скидки/кода достаточно общих строк; показывать строки, соответствующие опубликованным условиям, независимо от пути создания |
| «Заказали ещё раз за 30 дней» | Для первого заказа показать число покупателей, у которых есть следующая выполненная покупка в магазине в течение 30 дней, с любой акцией или без неё. Знаменатель — подтверждённые покупатели с первой выполненной покупкой по акции в выбранном периоде, для которых завершились все 30 дней наблюдения. Отсчёт от времени первой выполненной покупки, ровно на границе 30 суток повтор включается. Окно повторной покупки может выходить за выбранный период. Формат «4 из 12», отдельно «Ещё у 6 покупателей период наблюдения продолжается». Если никто ещё не достиг срока — «Результат появится через 30 дней после первой покупки». При малом числе покупателей показывать абсолютные числа |
| Смена условий | Сохранять версию и вид результата на момент заказа. Если сменился сам критерий (например, с первого на третий заказ), общие строки охватывают весь период, строки о первом и третьем заказе строятся только по соответствующим версиям. Название и состояние из текущей карточки. Переименование сохраняет историю |

**Как отражать изменения заказа.** Пример, ввод или замена кода, невыигравший код, ожидающий тариф, открытый или полностью отменённый до выдачи заказ дают ноль выполненных заказов с акцией. После выполнения поздний возврат изменяет денежные строки за исходную дату по [правилам блока 11](money-and-sales.md). Один и тот же возврат учитывается один раз. Выполненная покупка с последующим полным возвратом остаётся фактом использования при покупке; её денежные показатели корректируются. Удаление строки до выполнения учитывается по фактически выполненному составу. Показатели количества товара/подарков для 12.2 считать по выполненным единицам с учётом возвратов.

**Данные и команды для реализации.** В снимке применения хранить магазин, id и версию предложения, id заказа, причину выигрыша, авто/код, условие по номеру, сумму и распределение по строкам или доставке, количества комплектов/подарков. Сохранять подтверждённого покупателя при наличии, момент выполнения и события корректировок. Порядок покупок при одинаковом времени определять стабильной последовательностью событий магазина. Сервер читает результат предложения по id и периоду, возвращает валюту, границы, общие и подходящие специальные показатели, зрелый и ожидающий размеры группы. Детализация заказов — тем же фильтром с курсором. Сверять роль и магазин на обоих чтениях, включая прямую ссылку. Для списка получать сводки одной выборкой/пакетом. При выполнении, согласованном изменении, подтверждении тарифа или возврате обновлять затронутые данные идемпотентно. Расчёт отчёта не входит в горячий путь корзины. Старый заказ без основания акции не приписывать новой акции по совпадению названия или кода.

**Состояния.** Черновик — «Результаты появятся после запуска». Запланировано — дата начала. Опубликовано без покупок — «Здесь появятся результаты после первого выполненного заказа со скидкой». В выбранном пустом периоде — «За этот период заказов с акцией нет», доступна смена периода. Пока данные грузятся — скелетон; при ошибке — «Не удалось загрузить результаты» и «Повторить», условия акции доступны. При отзыве права доступа закрыть отчёт и детализацию, убрать ранее загруженные данные при смене магазина или сессии. Для заказа с несколькими акциями показывать точную скидку каждой по источнику. Общий отчёт о приросте, вывод «акция привела N клиентов» и расчёт дополнительной прибыли потребуют других данных и метода сравнения.

### Список, цели и поля

- Под «Создать акцию» одна горизонтальная строка из двух кнопок выбора: **«Все виды ⌄»** и **«Все статусы ⌄»**. При выборе видны сами значения, например «Промокоды ⌄» и «Отключено ⌄». Под длинное значение зарезервировать место; узкое поле не сдвигает стрелку или соседний фильтр. Выбирается вся строка высотой от 44 px. Одна стрелка, включая браузер на телефоне. У перехода на другой экран/вложенный список — шеврон вправо. Проверить «Способ применения», «Размер скидки», «На какой заказ», «Аудитория», «Срок» и фильтры.

В вариантах знак процента означает автоматическую скидку, билет/бирка — промокод, ценник — цену фасовки. Размер 20 px, одинаковая колонка и отступ; название и пояснение начинаются на одной вертикали. Иконки декоративные для экранного диктора; смысл читается по подписи.

**Сводка перед запуском.** Показать реальное название, размер скидки и её максимум, способ применения и код при наличии, подходящие товары/фасовки, номер покупки/аудиторию, минимум, срок и часовой пояс, общий и личный лимит. Короткие группы строк; пустые необязательные условия не занимают отдельный ряд. Пример: «Первая покупка · 10%, до 150 ₽», «Автоматически · все товары», «На первый заказ · один раз на покупателя», «Сразу · без срока», «До 20 применений на всех». Если предел вычислим — «Максимум скидок — 3 000 ₽». Можно вернуться к редактированию; последняя кнопка подписывает фактическое действие: «Опубликовать», «Запланировать» для будущего начала или «Включить».

Сводку и пример строить из тех же условий и версии, которые будут сохранены. Предпросмотр по желанию; обязательная серверная проверка дат, прав, товаров, конфликтов кода и лимитов действует на обоих путях. При двойном нажатии — одна команда с одним ключом, включая создание копии; два разных осознанных повтора могут создавать разные черновики. При потере связи сохранить ввод, при устаревшей версии показать актуальные условия до нового подтверждения.

### Цена фасовки по акции

Из «Все виды акций → Цена по акции на товар» и из карточки товара открывать **один редактор фасовки**. В контексте акции назвать поля «Обычная цена» и «Цена по акции». Обе в валюте магазина, акционная ниже обычной. «Срок» → «Без срока» либо «Указать даты». Кнопка **«Как увидит покупатель»** открывает действующие компоненты плитки, карточки товара и строки корзины с выбранной фасовкой. Например, у томатов 500 г новая цена **80 ₽**, рядом зачёркнутая **100 ₽**. Кнопки «Изменить» и «Сохранить»; для будущего старта в сводке «Запланировать». До сохранения пример видит только продавец.

При выборе дат явно указать «По … включительно» и часовой пояс магазина. Пример 26–28 ноября: до местной полуночи 26-го — 100 ₽, с начала 26-го до конца 28-го — 80 ₽ с зачёркнутой 100 ₽, с начала 29-го — снова обычная цена без зачёркивания. Сервер хранит конец как исключающую границу следующего местного дня. Показать три состояния в переключателе примера. На открытой корзине пересчитать цену при смене периода, рост подтвердить на оформлении. В ранее оформленном заказе остаётся его снимок.

Сохранить возможность обычной правки цены по правам S2 и действующие пары цена/старая цена без срока. Для существующей пары 80/100 ₽ открытие формы ничего не меняет, бессрочная скидка продолжает действовать. Перед заменой её новым периодом показать обычную цену между периодами и после окончания. В первую редакцию входит один задаваемый интервал на фасовку, изменение существующего периода проходит через сравнение условий. Разные фасовки редактируются независимо. При изменении обычной цены во время акции проверить пару заново; после окончания использовать сохранённую актуальную обычную цену. Техническая опора — [редактор фасовки](../../src/features/seller/ui/catalog/VariantFields.tsx).

### Настоящая корзина покупателя

В текущем холсте уже есть «Витрина» → «Корзина» и отдельный продавцовый «Пример корзины». Для следующей ревизии **перенести актуальную композицию CartScreen из main** с действующими компонентами и их состояниями: условия получения и адрес, вход/контакт гостя, «Ваш заказ», количество и удаление, отсутствующие позиции, уведомления о пересчёте, стоимость доставки/самовывоза, итог и закреплённое действие оформления. Демонстрационные данные переключаются за пределами экрана. Проверить возврат из карточки товара и оформления, сохранение способа получения при смене кода и доступность кнопки при открытой клавиатуре. [Корзина покупателя](../../src/features/cart/ui/CartScreen.tsx)

В «Ваш заказ» после товаров — одна строка для ввода/замены/удаления кода. Между суммой товаров и итогом — фактически применённые скидки, рядом с каждой **причина и сумма**. Короткие тексты из действующих условий, например:
- «Первый заказ · 10%, до 150 ₽» и справа «−120 ₽» при подходящих товарах на 1 200 ₽; при 2 000 ₽ — «−150 ₽». Скидка применяется автоматически. Если нужен вход, написать «Войдите через Telegram для скидки на первый заказ», оставить обычное оформление.
- «По промокоду LETO10» и справа «−100 ₽» при подходящих товарах с обычной ценой на 1 000 ₽ и выигравшем коде 10%. При замене показать старый/новый код и оба итога до подтверждения. Ошибка или отмена сохраняют прежний код. Если код уступил автоматической скидке — причина у кода, фактическая сумма только у выигравшей акции. Отрицательная сумма в итогах учитывается один раз.
- Фасовка с ценой по акции показывает обычную и действующую цены в своей строке. По умолчанию обычный товарный промокод применяется к единицам с обычной ценой согласно [правилам продвижения](../stories/promo.md#4-как-сочетаются-скидки). Для воспроизведения отключить конкурирующую автоматику, оставить только томаты по 80 ₽ вместо 100 ₽ и ввести SVET15: итог 80 ₽, выгода по этому коду 0 ₽, объяснение «Промокод действует на товары без скидки».

**Подсказка до порога (12.1).** До применения автоматической товарной скидки показать в этом же блоке одну короткую строку, если только подходящей суммы не хватает: «Ещё 150 ₽ выпечки до скидки 10%». Считать по подходящим доступным товарам после позиционных цен, без доставки. Добавление, удаление, смена фасовки, покупателя, срока и кода обновляют подсказку. Не выдавать закрытые коды и персональные предложения другой аудитории. Показывать подтверждённую доступную выгоду; не обещать скидку, которая на пороге уступит уже действующей. Если подходят несколько подсказок, по умолчанию показать ближайший достижимый денежный порог, при равенстве — большую применимую выгоду и стабильный порядок. Если для оценки недостаточно данных, обещание скрыть. После достижения заменить подсказку на причину и реальную скидку; при уменьшении вернуть подсказку.

**Доставка (12.3).** В тех же существующих условиях получения при подходящем тарифе писать «Ещё 1 ₽ до бесплатной доставки», на пороге — «Доставка бесплатно». Её сумма добора считается по своей базе; условия платного курьера, самовывоза, неизвестного тарифа и единственного кода остаются в [A6](promo-free-delivery.md). На холсте 12.1 показывать товарный добор и текущую доставку из main. Промо-добор доставки проверяется в отдельном холсте 12.3.
