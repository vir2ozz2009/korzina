# Спецификация · Блок 3 · После заказа и профиль

## 0. Рамки

- B11 — активный заказ на витрине, карточка заказа и «Мои заказы» (US-Z01, US-Z02, US-Z03, US-Z07).
- B12 — избранное гостя и вошедшего покупателя (US-C07).
- B13 — профиль, связь с Telegram, данные и адреса (US-K03 и входы в B11–B12).
- Источники — [B11](../tasks/B11.md), [B12](../tasks/B12.md), [B13](../tasks/B13.md), [DOMAIN «Заказ»](../DOMAIN.md#заказ-6), [решения от 18.11.2026](../DECISIONS.md), [спецификация покупки](purchase.md) и действующий код B6–B10. Состав блока ограничен §8. Варианты в §9 ждут решения Андрея. Новые тексты и пути ниже — предложения для согласования.

## 1. Путь

| Вход | Переход | Возврат и восстановление |
| --- | --- | --- |
| «Готово» B10 → «Мои заказы» или карточка только что оформленного заказа | `push` в список или к заказу | «Готово» сохраняет номер и результат B10. После перезагрузки карточка читает свой заказ с сервера. |
| Главная или каталог → активный заказ → карточка → отмена | `push` к заказу, подтверждение в `sheet` | «Назад» восстанавливает список, позицию прокрутки и фильтры. После отмены карточка показывает «Заказ отменён», виджет убирает этот заказ. |
| Карточка → «Повторить заказ» → проверка → корзина | При изменении цены, остатка или состава показать проверку в `sheet`. После успешного переноса — `push` в корзину | Закрытие проверки оставляет заказ и корзину в исходном состоянии. Снимок прошлого заказа остаётся в истории. |
| Главная или товар → сердце → профиль → «Избранное» → «+» | Сердце действует на месте. Профиль и избранное открываются через `push`. Выбор фасовки и вход — `sheet` | «Назад» из карточки товара возвращает к тому же месту списка. После перезагрузки гостевой список восстанавливается для текущего магазина. |
| Профиль → «Мои данные» / «Мои адреса» → адрес | `push` к данным или списку, форма адреса повторно использует переходы B7 | При закрытии формы без сохранения серверный адрес остаётся прежним. После сохранения список и шторка адреса корзины используют новую ревизию. |
| Профиль → вход, привязка или выход | Вход и подтверждение выхода — `sheet`. После Telegram вернуться туда, где начата операция | Проверить новую сессию перед показом личных данных. После выхода профиль остаётся доступен в состоянии гостя. |

Предлагаемые пути: `/orders`, `/orders/:number`, `/favorites`, `/profile`, `/profile/data`, `/profile/addresses`. Все ведут в тот же магазин. Гостю открываются профиль и локальное избранное. Для закрытых экранов показать вход B9, после успешного входа заново проверить доступ. Прямая ссылка на заказ не даёт прав доступа. При перезагрузке не повторять команды автоматически с новым ключом. Сохранение незавершённого текстового ввода ограничено открытой формой, кроме сохранённых черновиков B7 и B9.

## 2. Данные

Имена новых контрактов предварительные. Все суммы в целых минимальных единицах с валютой. Номера заказов B10 сохраняются, ключом доступа служит сессия в выбранном магазине.

| Контракт | Поля | Источник и обновление |
| --- | --- | --- |
| `OrderResult` B10 → `BuyerOrder` | Номер и дата, сохранённые строки, изображение строки если доступно для снимка, суммы, получение, время, оплата и подтверждение. Текущие этап, статус оплаты, возврат к показу, серверные `canCancel`, `canReplaceProof` и версия | Сервер. Суммы и названия берутся из снимка заказа. Текущий каталог нужен только при повторе. Для старых снимков без фото используется плейсхолдер. |
| `ActiveOrdersSummary`, `BuyerOrdersPage` | Номер, этап, время для виджета, счётчик. Для списка также дата, итог и валюта. Ревизия, непрозрачный курсор истории | Ревизия по покупателю и магазину. При совпадении версии виджет не перечитывает строки заказа. Списки обновляются при открытии, явном повторе и после своих команд. Уже загруженная история остаётся видна при сбое. |
| `RepeatOrderPreview` | Кандидаты на перенос с актуальными ценами, доступные количества и причины пропуска. Старая цена, новая цена, версия корзины и идентификатор проверки | Сервер сверяет варианты из снимка с текущим каталогом и корзиной. Клиент отображает разницу. |
| `Favorites` | `productId`, дата добавления, версия списка. Для экрана — проекция плитки каталога или пометка удалённого товара | У гостя список на устройстве, отдельно по магазину. После входа серверный список плюс ещё не синхронизированные локальные изменения. Флаг избранного для плиток берётся из одного набора на экран, без запросов по одному товару. |
| `BuyerProfile`, `SavedAddresses` | Имя, аватар или инициалы, тип входа, контакт `BuyerContact` B9. Адрес — ID, название, поля `Receiving` B7, версия списка и последний использованный ID | Сессия магазина и серверный профиль. Новая версия после записи, выборке в шторке корзины и успешном заказе. Зона, тариф и обязательные поля проверяются по текущим настройкам B7. |

| Запрос или команда | Вход → выход | Повтор |
| --- | --- | --- |
| Читать активные заказы, список, карточку | Ревизия / вкладка и курсор / номер → соответствующий контракт или ответ «без изменений» | Чтение без ключа. Доступ проверяется при каждом обращении. |
| `cancel` | Номер, версия → обновлённая карточка и результат отмены | Ключ команды. При гонке с передачей — `CANCEL_NOT_ALLOWED`. |
| Проверить повтор / `repeat` | Номер → проверка. Подтверждённая проверка и версия корзины → новая корзина и список пропусков | Проверка без изменения корзины. Запись с ключом, при расхождении требуется новая проверка. |
| `replaceProof` | Номер, версия и ID завершённой загрузки F9 → текущий чек и карточка | Ключ команды. Если проверка оплаты уже завершена, новая версия чека не применяется. |
| Читать избранное / `favorite.add` / `favorite.remove` / `favorite.merge` | Текущий магазин и сессия, ID товара или локальные записи → версия и результат | Ключ на команду. Слияние при входе повторяемо, запись по одному товару не создаёт дублей. |
| Читать профиль / изменить имя или контакт | Сессия, новые поля и актуальная версия → обновлённый профиль | Изменение с ключом. Проверки номера и региона общие с B9. |
| Читать, добавить, изменить, удалить адрес | ID при правке, поля B7, версия списка → актуальные адреса и версия | Запись с ключом. `ADDRESS_LIMIT`, `VERSION_CONFLICT`, ошибки валидации B7. |
| Привязать Telegram / выйти | Доверенный обмен B9 / текущая сессия → результат сессии и маршрут | Одноразовый обмен. Конфликт связи — `LINK_CONFLICT`. Выход повторяем для того же устройства. |

## 3. Экраны

Общее — [DESIGN](../DESIGN.md) §§2–4, §5а, [шаблоны](../design-system/templates.md) и B7–B10. Зоны касания ≥44 px. Кнопки-иконки имеют доступное имя. Для шторок вернуть фокус к открывшему элементу, а при ошибке формы перевести к первому невалидному полю. «Готово» на клавиатуре использует те же проверки. Состояния загрузки и результат команды озвучиваются. Для всех экранов отсутствие сети — «Нет подключения к интернету» и «Повторить». Если личные данные уже загружены и принадлежность сессии известна, оставить их с «Обновлено <время>» и отключить команды, которым нужен сервер. При смене сессии очистить прежние личные данные до загрузки новых. Тексты в угловых скобках подставляются из ответа.

### 3.6 Профиль, вход и выход · B13

## 4. Сервер, настройки и бюджеты

1. **Доступ и чтение.** Вывести владельца из проверенной сессии магазина. Сверить владельца заказа и магазин до раскрытия номера, суммы, адреса или чека. Курсор принадлежит тому же списку и владельцу. Телефон — контакт, повторный ввод номера на другом устройстве не открывает историю. Для Telegram доступ восстанавливается после подтверждённого входа. Кеш личных данных разделён по сессии и магазину. При своей команде меняются только связанные ревизии. Бюджеты виджета без изменений и карточки — [PERFORMANCE §6](../PERFORMANCE.md#6-измерение-и-бюджеты).
2. **Отмена.** Проверить права и сохранённый результат по ключу, затем актуальный этап и версию в транзакции. До границы D05 выставить `cancelled`, освободить зарезервированные остатки и интервал один раз, записать событие автора и outbox в той же транзакции. Если подтверждённая оплата требует возврата, сохранить необходимость возврата по DOMAIN. Форма реквизитов и проведение возврата — O5b. Доставка события продавцу отдельно, ошибки доставки не откатывают заказ. При гонке с передачей действует первая успешно зафиксированная команда.
3. **Повтор.** По снимку взять SKU и количество, заново проверить актуальные варианты, цены, доступность и остатки с учётом уже добавленного количества. При записи повторно сверить проверку и версию корзины. Применить доступные добавления атомарно, объединить одинаковые SKU в пределах остатка. Не переносить оплату, контакты, срок получения или адрес из истории. Только оформление B10 занимает товар и время. Предел изменения корзины — PERFORMANCE §6. Бюджет команды повтора зависит от числа строк, без запросов на каждую строку.
4. **Замена чека.** Проверить сессию, принадлежность заказа, свежую завершённую загрузку F9, назначение `receipt`, магазин, состояние `pending_review` и версию. Атомарно сменить ID, записать историю замен для продавца и результат повтора. Старые файлы сохраняются как история, новый файл сам по себе не подтверждает оплату. Повтор не добавляет вторую запись. При гонке с проверкой продавцом сервер возвращает текущий статус.
5. **Избранное.** Писать по `productId` в текущем магазине. Слияние гостевого списка и аккаунта идемпотентно, одинаковый товар появляется один раз. Локальный список сохраняется до подтверждённой синхронизации. Запрос каталога не обращается к избранному по каждой плитке, публичный кеш каталога остаётся общим, данные сессии в него не попадают. Изменения корзины через обычную команду B6.
6. **Профиль, выход и адреса.** Нормализовать контакт как B9, проверять имя и адрес по правилам формы, режим доставки по B7. Сохранение адреса с ревизией и лимитом атомарно. Использовать последнюю реально использованную адресную запись по D19, B7 повторно проверяет возможность доставки. Изменение адреса профиля не меняет сохранённый снимок заказа. Привязка Telegram опирается на одноразовый подтверждённый обмен, проверка конфликта до переноса данных. Выход отзывает сессию устройства, локальная гостевая корзина и избранное остаются доступными. Повтор команды с тем же телом возвращает прежний результат, смена тела с тем же ключом — `IDEMPOTENCY_CONFLICT`.
7. **Настройки магазина.** Способ получения, карта, режимы адреса, контакт и плательщик доставки берутся из B7–B10 и сохраняются в снимке, где применимо. Контакты для обращения — настройки B10, доступ Telegram зависит от бота магазина S7. Экраны этих настроек относятся к S4–S7. У блока нет нового провайдера.

## 6. Правила

- **П1.** Свои заказы, адреса и личные списки доступны только в проверенном магазине и сессии. Номер телефона сам не даёт доступ к истории. [D01 и уточнение от 18.11.2026](../DECISIONS.md).
- **П2.** Снимок заказа не меняется от правок каталога или профиля, текущее исполнение и оплата показываются отдельно. [DOMAIN «Заказ»](../DOMAIN.md#заказ-6).
- **П3.** Отмена до границы D05 освобождает остаток и интервал один раз. [DOMAIN](../DOMAIN.md#заказ-6), [D05](../DECISIONS.md).
- **П4.** Повтор учитывает текущую корзину, цены и остатки. Изменившуюся цену принимают явно. [B11](../tasks/B11.md), [DOMAIN «Корзина»](../DOMAIN.md#корзина-5).
- **П5.** Замена подтверждения оплаты возможна только в `pending_review` и сохраняет историю. Состояние оплаты меняет сотрудник с соответствующим правом. [Решение от 18.11.2026](../DECISIONS.md), [DOMAIN «Оплата»](../DOMAIN.md#оплата-в-mvp-56).
- **П6.** Избранное хранит товар, привязано к магазину и сливается без дублей. Корзина меняется через действия B6. [B12](../tasks/B12.md).
- **П7.** Последний использованный сохранённый адрес подставляется в корзине, условия доставки проверяются заново. [D19](../DECISIONS.md), [B7–B8](purchase.md).
- **П8.** При оплате доставки курьеру суммы магазина и курьера показаны отдельно. [D18](../DECISIONS.md).

## 9. Решения Андрея (19.11.2026)

1. **Этапы заказа.** `placed` — «Оформлен» с подписью «Магазин скоро возьмёт заказ в работу» (не «Ждём подтверждения»: не пугать и не обещать). `accepted` — «Собираем», одна ступень, новый статус у продавца не вводится. Дальше «Передан курьеру» / «Готов к выдаче», «Завершён». Вкладки «Активные» / «Завершённые» (в «Завершённых» выполненные и отменённые).
2. **Чек.** `rejected` — «Магазин не подтвердил оплату — свяжитесь с магазином» и кнопка «Связь с магазином»; замена чека после отклонения не открывается (П5 без изменений). Отмена, пока чек на проверке, — «Оплата на проверке. Если деньги поступили, магазин их вернёт». «К возврату <сумма>» — только при подтверждённой оплате.
3. **Привязка Telegram с историей.** Не конфликт: шторка «Объединить профили?» · «Отмена» / «Объединить». После подтверждения заказы, адреса и избранное профиля по номеру переходят в профиль Telegram; имя и контакт — из Telegram, номер добавляется, если его не было. Слияние идемпотентно, без потери и дублей. Отказ («Отмена») оставляет оба профиля как были. Текст «Этот Telegram уже привязан к другому профилю» в §3.6 заменяется этой шторкой.
4. **Адреса и данные.** Лимит — 10 адресов. Адрес, удалённый из профиля, но выбранный в корзине, остаётся в корзине копией до смены выбора. Имя — 1–50 символов, пустое допустимо («Имя не указано»).
5. **Связь с D19.** После успешного заказа адрес доставки сам сохраняется в «Мои адреса» без названия (если такого ещё нет); покупатель может переименовать или удалить. При лимите — не сохраняется, заказ не блокируется.
