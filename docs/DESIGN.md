## 2. Токены — единственный источник

`src/styles/tokens.css` — значения (Tailwind v4, схема shadcn/MagicPath: `:root` + `@theme inline`). Codex переносит эти токены напрямую в CSS компонентов MagicPath и обновляет приложение и холст вместе. Отдельную именованную тему не создаём (§5). `docs/design-system/korzina-theme.json` — справочный экспорт, не критерий приёмки. Цвет витрины продавец выбирает из пресетов или задаёт свой (`src/shared/theme-presets.ts`) — поэтому акцент в компонентах только через токены `primary*`: заливка `bg-primary` + `text-primary-foreground`, акцентный текст `text-primary-text`. Откуда взяты значения и как сводить расхождения макетов — `docs/design-system/tokens.md`.

## 3. UI-кит (`src/ui`) — одинаковый в приложении и на холсте

Спецификация всех компонентов (варианты, состояния, размеры, эталонные узлы) — `docs/design-system/components.md`. Как из кита собираются экраны — `docs/design-system/reference-screens.md`.

Каркас (`src/app/shell`, F8): `Screen`, `Header`, `QueryBoundary`, `Transition`, `SheetRoute`; оболочка витрины (шапка магазина + плавающие кнопки «Поиск» и «Корзина», без панели вкладок) и оболочка кабинета (5 вкладок: Главная · Заказы · Товары · Деньги · Ещё, у каждой свой стек).

Восемь шаблонов экранов (`src/app/templates`): `home`, `catalog`, `product`, `checkout`, `order`, `form`, `list`, `feedback` — **`docs/design-system/templates.md`**. Все экраны, маршруты и переходы первой версии — **`docs/design-system/navigation.md`**.

Правило: новый визуальный элемент сначала добавляется в кит (и в `/dev/kit`), потом используется в экране.

## 4. Переходы — один механизм на всё приложение

- `push` — новый экран въезжает справа налево; «назад» — обратное движение; свайп от левого края = назад (iOS-ощущение).
- `sheet` — снизу вверх, закрытие свайпом вниз и кнопкой «Назад».
- `tab` — без сдвига, мгновенная смена с fade 120 мс, прокрутка вкладки сохраняется.
- Направление определяет `Transition` по истории роутера. В Telegram кнопка `BackButton` привязана к `router.history.back()`.
- Длительность 280 мс, `ease-out`; при `prefers-reduced-motion` — без сдвига.

## 5. Цикл работы с MagicPath (на каждый экран)

Проект MagicPath: **«Korzina»**, ID **`473310532867354624`**, создан в F6. Компонент «F6 · Токены и оформление» — `473310594376798208`, ревизия `473310594376798209`; его CSS содержит те же токены, локально встроенный Inter Variable и знак из `public/brand/korzina.svg`.

**Решение Андрея, 17.11.2026:** на тарифе Builder встроенного агента MagicPath нет; отдельную именованную тему **Korzina** не создаём. Codex переносит токены из `src/styles/tokens.css` напрямую в компоненты. Критерий создания темы и сверки `get_theme` отменён; F6 закрыта по выполненным проверкам кода, холста и demo.

Команды CLI ниже обозначают операции; выполняем их доступными MCP-инструментами (`start_component_code_session`, `submit_component_code`, `get_component_code_context`), без установки CLI.
Старый проект «Платформа корзины» (`473127254868766720`) принадлежит эксперименту Lavka — в нём не работаем и его компоненты образцом не считаем.

1. **Материал.** Codex смотрит блок в Figma (`docs/SCREENS.md` → `get_screenshot` / `get_design_context` нужного узла, подписи-инструкции рядом). Либо Андрей сам импортирует блок Figma в MagicPath — тогда Codex берёт этот компонент как референс.
2. **Холст.** Только из актуального `main` (AGENTS «Как начинать»). **Уже одобренные и выпущенные экраны не перерисовываются заново:** на холст для них идёт текущий код экрана из `main` плюс изменения задачи — иначе на холсте «возвращаются» старые решения (так было в пакете 1: закреплённая шапка, другой шрифт цены). **В сообщении Андрею с холстом первой строкой: «Собрано из main <короткий хеш коммита>»** — по нему видно, что копия не устарела. **Нажатия внутри экрана на холсте работают как в коде** (плитка товара → карточка, «+» → шторка фасовок только при >1 фасовке, components.md `AddToCart`); переходы между разными экранами на холсте не обязательны — их Андрей проверяет на превью и demo. **Строки DESIGN §5а важнее кадров Figma.** **Ничего, чего нет в Figma или в карточке, на холст не добавлять** (придуманные чипы, кнопки, подписи) — если элемента не хватает, это вопрос Андрею. `code start --project <ID проекта Korzina> --name "<ID> <Экран>" --width 390 --height 844`. Перед написанием Codex копирует `src/ui/*` и нужные части `src/app/shell` в `src/components/generated/ui/`, чтобы экран на холсте собирался **из тех же примитивов**, что в приложении. Данные — моки в `generated/mock.ts`. Все состояния экрана (загрузка, пусто, ошибка, варианты) переключаются внутри одного компонента.
3. **Проверка.** `code submit --wait`; Андрей смотрит на холсте и правит словами или руками. Итерации идут только здесь: это быстро и без бэкенда.
   **Стоп до одобрения:** экран не переносится в приложение и не вливается в `main`, пока Андрей не написал «одобряю» по конкретной ревизии. Пока ждёшь — серверная часть, тесты, отчёт; правки Андрея — новой ревизией на холсте.
**Холст — эталон дизайна, а не зеркало кода.** Одобренная ревизия на холсте показывает экран целиком, как задумано, включая элементы, которые в коде включаются позже (поиск — B5, адрес — B7 и т. п.). Скрытие «до своей задачи» холст не меняет. Новая ревизия на холсте нужна, только когда **меняется сам вид** одобренного экрана (другая раскладка, размеры, правило фото); при этом старую ревизию не трогать, новая — рядом с подписью задачи. Что реально работает сейчас — смотреть на demo.
4. **Перенос.** `code context <componentId> --revision <rev> --dir .tmp/mp/<ID>`. Экран кладётся в `src/features/<x>/ui/`, импорты `./ui/*` заменяются на `@/ui/*`, моки — на хуки `api.ts`. Если на холсте изменили примитив — переносим изменение в `src/ui` (а не форкаем его в экран).
5. **Подключение и проверка** в приложении на реальном API. Ревизию MagicPath записываем в PROGRESS.md.
6. **Сверка с одобренным перед вливанием:** в описании PR — снимки экранов с превью (390) рядом со снимками одобренной ревизии холста, по каждому экрану задачи. Отличие (кроме данных) — исправить до вливания; если отличие нужно (холст не умеет, данные другие) — написать Андрею, какое и почему.

Нельзя: держать в экране собственные цвета и тени, копировать JSX примитива внутрь экрана, делать покадровое сравнение с Figma. Цель — «тот же стиль, те же кнопки, та же логика», а не пиксель в пиксель.
