# P · Платформа

Правила: `ARCHITECTURE.md` §4–8.

### US-P01 · Изоляция магазинов
Как продавец, я хочу быть уверен, что никто не видит данные моего магазина.
- Данные магазина A недоступны из магазина B ни через витрину, ни через API, ни по прямой ссылке на файл.

### US-P02 · Обновление для всех
Как владелец платформы, я хочу выпускать изменение один раз для всех магазинов.
- Один деплой → новая версия у всех магазинов; миграция данных магазина применяется автоматически при первом обращении.

### US-P03 · Функции по запросу
Как владелец платформы, я хочу включать дополнительную функцию отдельным магазинам.
- Дополнение выключено по умолчанию; включение для магазина A не меняет магазин B; выключение прячет функцию, не удаляя данных.

### US-P04 · Новый магазин
Как владелец платформы, я хочу создать магазин одной командой.
- `npm run shop:create -- <slug> <name>` → магазин доступен на `<slug>.korzina.app` (на demo — через `?shop=`), владелец получает ссылку-приглашение.

### US-P05 · Быстро и надёжно
Как покупатель, я хочу, чтобы магазин открывался быстро на мобильном интернете.
- Бюджеты из `ARCHITECTURE.md` §9 выполняются на demo.
