# P · Платформа

Правила: `ARCHITECTURE.md` §4–8.

### US-P01 · Изоляция магазинов
Как продавец, я хочу быть уверен, что никто не видит данные моего магазина.
- Данные магазина A недоступны из магазина B ни через витрину, ни через API, ни по прямой ссылке на файл.

### US-P02 · Обновление для всех
Как владелец платформы, я хочу выпускать изменение один раз для всех магазинов.
- Один деплой → новая версия у всех магазинов; миграция данных магазина применяется автоматически при первом обращении.

### US-P03 · Функции по запросу
Как владелец платформы, я хочу включать дополнительную функцию отдельным магазинам.
- Дополнение выключено по умолчанию; включение для магазина A не меняет магазин B; выключение прячет функцию, не удаляя данных.

### US-P04 · Новый магазин
Как владелец платформы, я хочу создать магазин одной командой.
- `npm run shop:create -- <slug> <name>` → магазин доступен на `<slug>.korzina.app` (на demo — через `?shop=`), владелец получает ссылку-приглашение.

### US-P06 · Фото и файлы
Как продавец и покупатель, я хочу загружать фото с телефона быстро и не раскрывать лишнего.
- Фото с камеры телефона (в т. ч. HEIC с iPhone) загружается за секунды: перед отправкой сжимается.
- В сохранённых фото нет геолокации и данных камеры.
- Чеки, вложения в чате и фото в отзывах видят только участники заказа и сотрудники магазина с правом.
- Брошенные загрузки удаляются сами; магазин видит, сколько места занято, и получает понятное сообщение при достижении лимита.

### US-P07 · Данные не теряются
Как продавец, я хочу быть уверен, что каталог, заказы и фото можно восстановить после сбоя.
- Ежедневные резервные копии баз магазинов, платформы и файлов в отдельном хранилище; 30 ежедневных и 12 месячных копий.
- Восстановление магазина из копии проверяется перед запуском и раз в месяц.

### US-P05 · Быстро и надёжно
Как покупатель, я хочу, чтобы магазин открывался быстро на мобильном интернете.
- Бюджеты из `ARCHITECTURE.md` §9 выполняются на demo.
- Повторное открытие главной и каталога не нагружает базу магазина, пока товары не менялись; остатки и цены при этом всегда актуальны.
- Магазин, в котором никто ничего не делает, не создаёт фоновых запросов.
- Бюджеты SQL горячих путей (`PERFORMANCE.md` §6) проверяются тестами.
