## 1. Главная с серверными товарами

Проверить актуальный вариант главной в Figma и уже созданные варианты. Codex собирает новую мобильную главную в MagicPath и переносит её в общее приложение. Компоненты и переходы выбирает самостоятельно, недостающие состояния дополняет в стиле магазина. На компьютере мобильная версия располагается по центру.

Проверить demo по HTTPS. Подключить к существующему тестовому Worker собственные API, отдельные D1 и R2 Korzina; сначала проверить, не созданы ли они уже. Наполнить небольшой демонстрационный ассортимент идемпотентным сценарием. До кабинета продавца ассортимент поддерживает этот сценарий. Перед серверным модулем оценить аналог Lavka по docs/architecture.md, не подключаясь к её рабочим данным.

**Контрольный результат:** главная на тестовой ссылке показывает сохранённые серверные товары и обрабатывает загрузку, пустой ассортимент и ошибку с повтором. Статическая копия макета этап не закрывает.

## 2. Главная → каталог → товар → корзина

Собрать каталог, категории, поиск по названию, товар и корзину по необходимым макетам. Связать настоящими переходами, поддержать возврат и открытие прямых ссылок. Состав корзины сохранять после перезагрузки. Подключить серверную проверку цен и доступности; скидки и доставка рассчитываются по правилам магазина.

**Результат:** без регистрации покупатель находит товар, открывает его, добавляет в корзину и меняет количество. Проверены изменение цены/наличия после добавления, недоступный товар, пустой поиск, ошибка сети и повторная попытка.

## 3. Продавец управляет ассортиментом

Подключить Telegram-вход и серверную проверку прав. Создать список товаров, создание и редактирование, фотографии, публикацию и снятие с продажи. Покупатель, продавец и бот используют общие серверные правила.

**Результат:** изменения продавца сохраняются и отражаются на витрине; чужие данные недоступны.

## 4. Заказ от покупателя до продавца

Добавить адрес, условия доставки, создание заказа, список и карточку заказа продавца, согласованные статусы. Повтор отправки не создаёт дубль. Проверить путь обеих ролей и необходимые уведомления Telegram на отдельном боте Korzina.

**Результат:** тестовый заказ проходит через API и отдельную базу, продавец принимает его, покупатель видит подтверждённое состояние.

## 5. Остальные сценарии

Профиль, избранное, истории, программы скидок, отзывы и остальные экраны добавляем отдельными завершёнными сценариями. Интеграцию платёжного сервиса выполняем после его выбора; до этого не обещаем работающий эквайринг. Проверяем веб и Telegram Mini App. Выпуск на рабочие домены и перенос магазинов — отдельное решение.

## Данные и проверка

Первые API: магазин, категории, список товаров, товар, расчёт корзины. Все данные привязаны к магазину; начинаем с одного пилотного магазина, сохраняя изоляцию. Для каждого этапа фиксируем источники Figma, ревизию MagicPath, интеграцию, пройденный сценарий и ограничения. Макеты заранее целиком не переносим. Автоматические проверки — по риску изменения, API-тесты последовательно; обязательные проверки выпуска сохраняем. Секреты, права, кеширование, ограничение запросов и оптимизация изображений остаются техническими требованиями.
