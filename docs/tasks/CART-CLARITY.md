## Входит и одобренный результат

### 1. Обычный промокод

При успешном применении: **«Применён к товарам без скидки»**. Подсказка для обычного скидочного кода: «Промокод действует на товары без скидки». Не выдавать эту оговорку за универсальное правило кода на комбо или будущей бесплатной доставки. Вид/условия реально применённого предложения сообщает сервер; не угадывать тип по строке кода. Существующие объяснения отказа и проигрыша автоматике сохраняются.

### 2. Получение по умолчанию

Новый заказ начинается с доставки, если она включена и доступна. Выбранный самим покупателем самовывоз сохраняется внутри текущего незавершённого заказа при переходах назад и перезагрузке. После завершения заказа прошлый самовывоз не становится начальным выбором следующего. Сохранённый адрес не удаляется. При отсутствии адреса показать «Укажите адрес доставки»; недоступную доставку не выбирать. Если доступен только самовывоз — выбрать его; если ничего — штатное недоступное состояние.

Устранить причину на сервере и клиенте: сейчас activeReceiving предпочитает сохранённый способ, а removeOrderedLines сохраняет receiving. Нельзя менять только вид radio при прежнем серверном тарифе. Очистка и ручное повторное наполнение корзины, остаточные недоступные строки, повтор заказа и слияние гостевой корзины должны быть явно рассмотрены в спецификации; неопределённые случаи вернуть в Work до реализации.

### 3. Шторка комбо

Заголовок — имя набора, затем состав с фасовкой и количеством, цена комплекта и экономия. Пример:
- Комбо «Завтрак»
- Голубика · 125 г × 1
- Молоко · 500 мл × 1
- **За набор — 60 000 ₫**
- Экономия 11 000 ₫

Название берётся у продавца; пример не должен попасть в живые данные. Убрать общий заголовок «Почему такая сумма», строку «Наборов по акции — 1», распределённые доли товаров и итог всей корзины. Сейчас CartGroupDetails ошибочно показывает cart.totalMinor.

Для нескольких комплектов: «2 набора × 60 000 ₫», общий итог 120 000 ₫ и общая экономия; состав пометить «В одном наборе». Лимит показывать только когда он объясняет неприменённую выгоду: «По акции 2 из 3 наборов». Суммы — только по реально участвующим единицам выбранного комбо, не по всей строке товара и не по заказу. Финансовое распределение по товарам сохранить на сервере для заказа и возврата. При изменении корзины актуализировать выбранное пояснение либо закрывать его, если комбо исчезло.

## Нажимается и состояния

Существующая подпись комбо открывает компактное пояснение; крестик/штатный жест закрывает и возвращает в ту же корзину без сброса. Обычный код применяется/заменяется/удаляется прежними командами. Выбор получения сохраняется штатной командой с версией. Загрузка, потеря сети, ошибка, повтор, изменение расчёта и исчезновение акции не показывают устаревший финансовый итог.

Та же шторка и смысл сумм в изолированном примере продавца. Подарок N+M сохраняет своё принятое объяснение оплаченных/бесплатных единиц: упрощение комбо не должно его ломать.

## Готово, когда

- Шторка одиночного комбо показывает 60 000 и 11 000 из примера, независимо от посторонних товаров в корзине.
- Несколько наборов, лимит, лишние единицы одной фасовки, пересчёт и исчезновение комбо показаны без двойных сумм; сценарий FIX-PROMO-OPT сохраняет 450.
- Обычный код на смешанной корзине подписан правильно; только акционные товары, проигрыш автоматике и код комбо не получают ложного сообщения.
- Новый заказ выбирает доставку; самовывоз сохраняется при возврате/refresh текущего заказа; следующий заказ после самовывоза снова начинает с доступной доставки. Учитываются магазин без доставки и пауза.
- Никакие цены/способы получения в интерфейсе не расходятся с серверным оформлением; повтор команды не создаёт новое действие.
- Заказ/частичный возврат используют прежние сохранённые доли. Регрессии N+M, адреса, промокода, футера и перехода к оформлению зелёные.
- Снимки до/после и сравнение с одобренной ревизией 360/390, check:fast/связанные проверки, обязательные CI/smoke, затем demo и чек-лист с покрытием через Work.
- Локальный Codex проверяет затронутые маршруты с видеоповтором iPhone; непроверенные ранее iOS-клавиатура/Telegram не объявляются закрытыми без фактического прогона.

**Ближайший СТОП:** спецификация в Work, затем одобрение новой ревизии холста. Не начинать UI-реализацию на основании одной карточки.
