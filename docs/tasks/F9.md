# F9 · Медиа: хранилище фото и файлов
- **Цель:** R2 `korzina-media` (demo и prod — отдельные бакеты) + выдача через Cloudflare Images; модуль `server/modules/media` и компонент `<Img>`.
- **Загрузка:**
  - на клиенте перед отправкой: сжатие до длинной стороны 2048 px и JPEG/WebP ~85% (продавец снимает на 12 МБ — уходит 1–2 МБ); HEIC с iPhone конвертируется в JPEG;
  - на сервере: проверка типа по содержимому (не по расширению), размер до 10 МБ, удаление EXIF (геолокация, модель камеры) у всех фото, повторная конвертация HEIC, если пришёл с компьютера;
  - файл привязан к магазину, владельцу, назначению (`product`, `logo`, `cover`, `payment_qr`, `receipt`, `chat`, `review`, `refund`) и статусу `temp` → `attached`.
- **Выдача** (PERFORMANCE §2 п. 9): публичные назначения (`product`, `logo`, `cover`, `payment_qr`) — по постоянной ссылке с ресайзом (размеры: 160, 400, 800, 1600) и кешем на год; приватные (`receipt`, `chat`, `review`, `refund`) — только через API с проверкой прав, короткоживущей подписанной ссылкой. `<Img>`: `srcset`, плейсхолдер цвета `input`, ленивая загрузка ниже экрана, ошибка → заглушка.
- **Уборка:** ежедневная задача — `temp`-файлы старше 24 ч удаляются; файлы удалённых товаров и сообщений — через 30 дней; архивный магазин — по отдельному решению.
- **Лимит:** 2 ГБ на магазин (значение в настройках платформы, меняется в админке); при превышении загрузка отклоняется с понятным сообщением, в кабинете виден объём «занято / доступно».
- **Готово, когда:** тесты — фото 12 МБ с телефона загружается и отдаётся в 4 размерах; в отданном файле нет EXIF-геолокации; HEIC открывается; приватный файл недоступен другому покупателю и другому магазину; `temp` старше суток удаляется задачей; при превышении лимита — `STORAGE_LIMIT`.
