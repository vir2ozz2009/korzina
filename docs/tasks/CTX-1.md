# CTX-1 · Короткий и достаточный контекст новой задачи

Одобрено Андреем 27.11.2026. Отдельный документационный PR облачного Codex после первоочередного FIX-PROMO-OPT; начало по очереди в [передаче](../progress/audit-followup-2026-11-27.md). Магазин не меняется. Уровень мышления: высокий для сверки противоречий, далее средний для редактирования.

## Проблема и измеренная база

На main 0566290 AGENTS.md — 25 333 байта UTF-8, PROGRESS.md — 71 425; вместе 96 758. specs/README — 28 569, DECISIONS — 61 497, спецификация 12.1 — 88 389 при 257 строках. Ограничение «до 400 строк» не ограничивает контекст.

В выборке 12 локальных журналов три команды запрашивают весь PROGRESS через cat. Это наблюдение локальных чатов, не аудит облачных сессий. Байты не равны токенам или стоимости. Весь репозиторий автоматически не загружается.

## Читать для этой задачи

AGENTS.md, PROGRESS.md, PLAN.md как индекс, specs/README.md, tasks/README.md, CONVENTIONS.md; у DESIGN/TESTING/PERFORMANCE/ARCHITECTURE — соответствующие правила, которые переносятся/проверяются. Для карты 12.x — карточки A1/A1b/A11/A6 и заголовки соответствующих спецификаций. DECISIONS — релевантные решения, не переписывать их из памяти. Проверять фактический код/конфиги только там, где документ описывает реализацию.

## Входит

1. Сократить корневой AGENTS до целевого 6000 байт UTF-8: неприкосновенные границы, источники правды, начало/конец, маршрутизация. Подробные процедуры перенести в один канонический документ, ссылаться на конкретный раздел.
2. Сократить PROGRESS до целевого 4000 байт: текущая задача, этап, актуальные SHA/ревизии, следующий шаг и СТОП, ссылки на приёмку. Сохранить историю в docs/progress/archive/ по блокам. При переносе исправить относительные пути и сохранить входы по старым якорям либо явные перенаправляющие ссылки.
3. Добавить карты docs/blocks/12.1.md, 12.2.md, 12.3.md (цель до 4000 байт каждая): карточка → разделы спецификации → исходники/контракты → тесты/чек-лист, отдельно для Work, холста, реализации и локальной проверки. Карты — ссылки, не копии правил. Общий индекс PLAN используется построчно.
4. Установить чтение нужных разделов через поиск заголовка/диапазон. Разрешить расширение по реальной зависимости: деньги, права, изоляция, идемпотентность и возвраты не исключаются ради бюджета.
5. Удалить противоречивые текущие указания, сохранив исторические записи. В PROGRESS строка о предстоящей реализации 12.2 устарела после приёмки. Нормализовать docs/PLAN.md (регистр).
6. Сверить фактические зависимости package.json с ARCHITECTURE, реальный предел размеров из arch-rules/file-length-baseline с CONVENTIONS. Исправить ссылки на отсутствующий e2e/workday-regressions.spec.ts по реально заменившим его тестам, не выдумывать файл.
7. Составить таблицу конфликтов инструкций Work/репозитория: роль Figma, проект MagicPath, процесс и проверки. Однозначные устаревшие технические сведения исправить по коду/зафиксированным решениям. Не выбирать новый продуктовый процесс, ID проекта или разрешения по догадке. Если решения не хватает — рекомендация в Work; остальную чистку закончить.
8. Для правил с тестами сохранить силу денежных/правовых проверок; визуальные доказательства не заменяют автоматические тесты поведения. Возможное уточнение противоречивого требования «каждое решение — свой тест» представить в diff и сверить с TESTING, не ослаблять существующие тесты.
9. Добавить в шаблон отчёта короткое перечисление реально прочитанных основных документов и причин выхода за карту; не писать длинные журналы в обязательные файлы.

## Не входит

Код приложения, данные, prod/Lavka, платные сервисы, изменение разрешений, новые функции, переписывание спецификаций всех блоков, автоматическое изменение настроек модели/подключённых возможностей, удаление истории. Локальные файлы проекта Work за пределами Git облачный Codex не меняет: возвращает конкретный предложенный diff для синхронизации Work.

Новые scripts/CI здесь не добавлять: размеры и ссылки проверить разовой командой. Если нужен постоянный контроль — предложить отдельную карточку. Нельзя увеличивать project_doc_max_bytes вместо сокращения контекста. Вложенный AGENTS не считать автоматически подгружаемым по теме запроса: цепочка зависит от рабочей папки.

## Приёмка

- В отчёте до/после: байты каждого стартового файла, суммарный объём, исходный и итоговый SHA. Цель 10 000 байт AGENTS+PROGRESS — ориентир, а не разрешение выкинуть обязательное правило. При превышении дать причину и точный остаток.
- Таблица «старое правило → новое место» подтверждает сохранение границ prod/Lavka, изоляции, секретов, денежной истины, проверок, ролей и приёмки Андреем.
- Все переносимые относительные ссылки проверены; актуальный статус не противоречит истории. Приёмки 12.2/#315 сохранены.
- Проход по карте для трёх контрольных запросов: узкая правка корзины, серверный расчёт комбо, локальная проверка demo. Видно достаточное покрытие зависимостей без ненужных соседних блоков.
- Фактическую загрузку контекста проверить в трёх новых чатах по этим маршрутам, когда они будут доступны. Облачный Codex не создаёт и не отправляет сообщения в чужие чаты сам; возвращает короткие стартовые команды через Work. До живой проверки писать «структура проверена, фактическая экономия токенов не измерена», не обещать 90% экономии всего запроса.
- Документационный Check зелёный. Кодовые тесты для такой чистки не добавлять и полный runtime-прогон не запускать.
- docs/progress/CTX-1.md: размеры, карта сохранённых правил, проверенные ссылки, открытые конфликты и команды нового чата. Если нет неразрешённых смысловых конфликтов — влить docs-PR по постоянным разрешениям. Конфликтующую часть вернуть в Work, не блокируя готовую безопасную часть.

**СТОП:** отчёт в Work; проверка новых чатов и синхронизация внешних инструкций. Не менять статус продуктовых блоков на «принят» этой задачей.
