- **Источник:** замечание Андрея 19.11.2026 на demo (главная, «Молочные»): фото то обрезаны, то мелкие, то во всю плитку. Анализ — Claude.
- **Холст:** нужен — меняется вид одобренных экранов. Новая ревизия «F11 · Фото: единый вид» **рядом** со старой, старую не трогать.
- **Порядок:** шаг 1 → шаг 2 → **стоп**. Код (шаг 3) — только после «одобряю» Андрея на холсте.

## Причины (что сейчас не так)

1. `ProductTile.tsx` и `Gallery.tsx` передают `fit="cover"` — вопреки `photos.md` («предмет никогда не обрезается»). Отсюда обрезанный огурец в «Овощном миксе» и горлышко молока в «Молочных». Рамка плитки `tile` 179/142 — не квадрат, высокие предметы режутся сильнее.
2. `contentBox` считается и хранится, но нигде не применяется при показе. Фото с большими полями (круассан на тарелке, голубика) выходят мелкими, фото без полей (томаты) — во всю плитку.
3. `CategoryPhoto.tsx` — без маски мягкого края (в `photos.md` она есть): фото томатов видно прямоугольником другого белого. Доля предмета в зоне разная у 1×1 и 2×1.
4. Демо-фото разнотипные: часть — предмет на белом, часть — фон до краёв (курица на бумаге, томаты).

## Как у конкурентов (основа решения)

Instacart, Google Shopping, Лавка, Самокат: квадратная рамка, один светлый фон, предмет по центру и занимает постоянную долю кадра (~75–90 %), ничего не обрезается. Вырезку фона не делаем (решение 17.11) — тот же эффект даёт `contentBox` + `edgeColor`.

## Шаг 1 · Спецификация (`docs/design-system/photos.md`, `DESIGN.md` §5а, `DECISIONS.md`)

Переписать раздел «Показ» так:

- **Везде `contain`, `cover` нигде** (плитка товара, корзина, заказ, галерея, категории). Проп `fit="cover"` у `ProductImage` убрать.
- **Плитка товара — квадрат 1:1** (`shape="square"` по умолчанию; форма `tile` уходит из плитки товара).
- **Нормализация масштаба:** фото показывается обрезанным по `contentBox`, затем вписывается в рамку с полем **8 %** с каждой стороны → предмет занимает ≈85 % рамки по большей стороне. Нет `contentBox` — фото целиком с тем же полем.
- **Увеличение:** разрешено, но не больше **×2** от исходного размера `contentBox` при показе (чтобы не мылилось). Если ×2 не хватает до 85 % — предмет меньше, по центру. Это меняет правило «без увеличения» — строка в `DECISIONS.md` с пометкой «ждёт одобрения на холсте F11».
- **Фон рамки** — `edgeColor` фото, края фото растворяются в него на 10 px (как сейчас).
- **Галерея карточки** — те же правила, квадрат.
- **Плитка категории:** обрезка по `contentBox`, `contain`, маска мягкого края ~8 px, предмет занимает ≈85 % своей зоны **в любом размере** (1×1, 2×1, 1×2, 2×2), прижат к низу; на подпись не заходит.
- **Демо-фото (сид):** однотипные — предмет на белом фоне по центру; убрать фото «фон до краёв» (курица на бумаге, томаты кадром). Пересчитать `edgeColor` и `contentBox` для всех фото сида.
- **Полноэкранный просмотр** — без изменений (целиком, на тёмном фоне).

## Шаг 2 · Холст MagicPath

Ревизия «F11 · Фото: единый вид» рядом с текущей. Те же демо-товары и категории. Кадры:

1. Главная: мозаика категорий (1×1 и 2×1 рядом) + сетка товаров (минимум 6 плиток: томаты, голубика, овощной микс, молоко, курица, круассан).
2. «Молочные»: список из одного товара.
3. Карточка товара: галерея из 2+ фото.
4. Для сравнения — те же плитки в старом виде (скрин demo) рядом.
