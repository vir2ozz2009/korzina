# A12 · Личные предложения из карточки покупателя и продвижения

Подблок 13.1 · [Карта](../blocks/13.1.md) · US-A12 в [later](../stories/later.md).
**Карточка одобрена Андреем 28.11.2026.** Спецификация v1 с Q1–Q4 и коротким локальным планом одобрена 28.11.2026. Следующий этап — холст по передаче в карте; реализация ещё не разрешена.

- **Источники и контекст:** [исследование](../research/customer-offers.md); [спецификация](../specs/customer-offers.md) §1, §3–9. Правила подробно определены там; не придумывать отсутствующие решения.
- **Figma:** 78, узел 1004:61821; связанные 33/44/67/80 в файле [Korzina](https://www.figma.com/design/Y8MsoSYwEr373vVvlvXAGJ/?node-id=1004-61821). Объём визуальной сверки и отличия перечислены в исследовании; полной сверкой всех кадров не объявлено.
- **Холст:** учесть существующие холсты и экраны по карте 13.1 и проекту §1.1–1.2; общий 13.1, после одобрения спецификации; все новые и затронутые состояния 360/390 px.
- **Входит:** Реестр «Продвижение → Личные предложения», выбор получателя при создании оттуда; единая форма/история/ревизия с карточкой покупателя. Личная автоматическая скидка и разовый личный код; цель возвращения как преднастройка; одна шторка выдачи, встроенная сводка и необязательный пример; отзыв/замена/история; предложения в профиле и корзине; серверный расчёт, лимиты, возвраты, права, очередь уведомления и согласие покупателя по магазину (Q1 спецификации).
- **Нажимается:** Дать скидку → значение/условия → выдать; дополнительно — код; посмотреть пример; открыть историю; отозвать; повторить новым предложением; покупатель — использовать код без набора, подтвердить замену прежнего кода.
- **Не входит:** Массовые сообщения — A12b; кэшбэк — A4; любимый товар — A5; личная доставка, N+M/комбо, личная цена позиции, автоматический win-back и CRM не входят.
- **Отличия от справочника:** текущий каркас main; история сразу в карточке, выдача одной шторкой вместо обязательного отдельного экрана проверки. Состав карточки одобрен; макет ещё не создан.
- **Данные/API:** серверная личность и магазин; контракт до UI. Операции, поля, ревизии, права, инвалидация и ошибки — спецификация §§6–7, 13–14; экраны/процессы §§11–12.
- **Состояния:** загрузка, пусто, нет совпадений/телефона/выполнений, нет доступа, нет сети, частичная ошибка, изменившиеся данные; для A12 дополнительно гость, несовместимость, чужое/истёкшее/исчерпанное/отозванное предложение, результат уведомления неизвестен. Полный набор — спецификация §§12.1, 14.
- **Готово, когда:** C07–C21 и разграничение C02/C06 в спецификации покрыты с указанием среды и доказательств. Новые денежные/идентификационные правила не заменяются снимками.
- **Разрешённый результат / СТОП:** сейчас — холст по одобренной спецификации v1 → отдельное одобрение его точной ревизии Андреем. Реализация после одобрения холста; физический план L1–L3 не расширять.
