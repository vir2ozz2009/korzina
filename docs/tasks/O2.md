# O2 · Заказы и сборка у продавца — **58, финалы «02 · Заказы, исполнение и чат», «18 · Исполнение оплаченного заказа», «Карточка заказа в стиле Telegram»**

- **Figma (справочник Claude):** 58 (`632:49949`): `orders`, `new-list`, `preparing-list`, `ready-list`, `archive`, `search`, `no-search`, `empty`, `load-error`, `new`, `packing`, `packed`, `ready`, `transit`, `cash-received`, `completed`, `proof`, `pickup*`, `changes-pending`, `delivery-courier`, `readonly`, `conflict`, `action-error`, `verify`, `record-payment`, `handoff`, `finish`, `issue`, `order-menu`, `cancel`, `rollback-*`, `packing-many`, `address-editor`; финалы «02» (`840:50987`), «18» (`1217:56912`), «Карточка заказа в стиле Telegram» (`954:61072`).
- **Истории:** R02, R03, R04.
- **Холст:** нужен.
- **Входит:**
  - **Список заказов:** «В работе · N» и «История»; поиск по номеру, имени или телефону; фильтры по этапу и «Доставка / Самовывоз»; карточка в списке в стиле Telegram — номер и имя, сумма, **время получения крупно**, «Оплачен / Не оплачен», этап и способ, шкала этапов, «Собрано N из M», «Открыть сборку».
  - **Карточка заказа:** статус (номер продавца и «клиент видит №…»), покупатель (имя, телефон, адрес с копированием, «Чат по заказу» — после O8), **состав со сборкой** (отметить позицию «Собрано», «Отметить все собранными»), итог («Итого магазину»), оплата, получение (время, комментарий).
  - **Действия по этапам:** принять → собрать → передать курьеру / к выдаче → выдать / завершить; «Ещё»: **«Вернуть статус»** (откат с подтверждением), «Отменить заказ» с причиной.
  - **Оплата в карточке:** «Проверить перевод» → «Подтвердить поступление» (последний чек и история замен); «Наличные получены» — фактическая сумма; режим «доставку оплачивают курьеру» — отметка; пометка «Адрес не проверен на карте» и назначение стоимости доставки для «согласуем после заказа» (доплата покупателя — O5b).
  - **Решение Андрея 19.11.2026 — вкладка и уведомление:** в кабинете появляется вкладка «Заказы». **Уведомление продавцу о новом заказе переносится сюда из O4:** при создании заказа outbox → бот магазина (если подключён, иначе бот платформы) пишет владельцу и сотрудникам с правом «заказы» «Новый заказ №… · сумма · время получения» с кнопкой «Открыть» (Mini App кабинета на этом заказе). Один раз на заказ, вне транзакции, сбой отправки не влияет на заказ.
  - **Решение Андрея 19.11.2026 — обновления без опроса:** пока кабинет открыт и виден — одно WebSocket-соединение с hibernation в Shop DO на аккаунт (все вкладки, Web Locks + BroadcastChannel); сервер шлёт только сигнал «что изменилось» (тема, ID, курсор), клиент дочитывает изменённое. Вкладка скрыта — соединение закрывается, при возврате один запрос «что нового» по курсору. Запасной опрос — только если соединение не установилось, раз в 60 с и только пока экран виден. Опроса по таймеру при работающем соединении нет (в Lavka был опрос каждые 5 с — не повторять).
  - **Живые обновления** (PERFORMANCE §4): WebSocket с hibernation в Shop DO, сигнал «что изменилось» + курсор событий, одно соединение на аккаунт, резервный опрос только без соединения; ревизии списков (`unchanged` без чтения записей).
- **Нажимается:** вкладки, поиск, фильтры; заказ → карточка; «Открыть сборку»; отметки позиций; кнопка следующего этапа; «Ещё» → «Вернуть статус» / «Отменить»; «Проверить перевод» → «Подтвердить»; «Наличные получены»; «Скопировать адрес»; телефон → звонок.
- **Не входит (не рисовать):** изменение состава и замены (O6); перенос времени (O7); чат (O8); рабочий день и список сборки на день (O3); разделы «Деньги» (O5); уведомления (O4).
- **Отличия от Figma:** нет.
- **Данные (API):** список из `seller_order_index` (курсор, фильтры, ревизия); `GET` заказа; команды O1; команды оплаты: `confirmTransfer`, `recordCash`, `setDeliveryFee`; поток изменений (WebSocket); ошибки O1 + `FORBIDDEN` (без права «деньги» — оплата только просмотр).
- **Состояния:** загрузка; пусто; поиск без результатов; ошибка; конфликт параллельного действия; ошибка действия; только просмотр без прав; много позиций.
- **Готово, когда:** бюджеты «список без изменений» и «карточка заказа» (тесты); новый заказ появляется у продавца без перезагрузки; подтверждение перевода и наличных не зачисляет дважды (тест); откат статуса записан в историю (тест).
