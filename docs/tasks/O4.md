# O4 · Уведомления Telegram — **70, финал «35 · Бот магазина и уведомления», «Статус заказа в Telegram»**

- **Figma (справочник Claude):** 70 (`911:59820`); финал «35» (`1380:94064`): «События для рабочей группы», «Тестовое сообщение», «Уведомления на паузе»; «Карточка заказа в стиле Telegram» (`954:61072`, `25:2`) — вид сообщения о заказе.
- **Истории:** R01.
- **Холст:** нужен — вид сообщений в Telegram (карточка заказа как в кабинете).
- **19.11.2026:** уведомление продавцу «Новый заказ» сделано в O2 (блок 5) — здесь остальные уведомления продавцу и покупателю на том же outbox.
- **Входит:**
  - Продавцу «Заканчивается: <товар>, осталось N шт.» в Telegram (решение Андрея 20.11.2026, блок 6 §12.8; порог — как фильтр «Заканчиваются», ≤ 5 шт.; одно сообщение на переход через порог).
  - ~~Продавцу в рабочую группу (S7)~~ — заменено решением 2: лично по таблице ролей блока 8: новый заказ (номер, время получения, сумма, оплата, состав кратко, «Открыть заказ» — ссылка в кабинет), перевод на проверке, сообщение покупателя (после O8), запрос переноса (после O7) — по выбранным событиям S7.
  - **Покупателю в бот магазина** (если вошёл через Telegram): заказ принят, собран, передан курьеру / готов к выдаче, завершён, отменён; ссылка «Открыть заказ» в Mini App.
  - **Очередь отправки** через alarm Shop DO, который ставится только при появлении работы (PERFORMANCE §5); повторы с экспоненциальной задержкой и разбросом, учёт `Retry-After`; ошибка Telegram не ломает заказ; пауза уведомлений (S7) — события не отправляются.
- **Решения Андрея 22.11.2026 (сверка карточек блока 9, по образцу Shopify Home и Square Order Manager):**
  1. **«Главная» — только цифры, без карточек заказов.** Если магазин не открыт — сверху список готовности (блок 8). Если открыт: статус приёма (блок 7) → «Сегодня: N заказов · сумма» → «По этапам: Новые · Собираются · Ждут выдачи · У курьера» → «Требуют действия: принять · проверить чек · решить по оплате» (просроченные отдельно, красным) → «Долги клиентов: N ₽» → кнопки «Список сборки» и «Календарь». Каждая цифра открывает «Заказы» с нужным фильтром. «Ближайшие заказы» карточками — **убрать**.
  2. **Уведомления продавцу — по таблице ролей блока 8** (рабочей группы и «паузы уведомлений» нет). Столбцы: «Новые заказы» (уже работает), «Оплаты и чеки», «Отмены», **«Товар заканчивается»** (новый; по умолчанию владелец и управляющий; одно сообщение на переход через порог ≤ 5 шт.). «Сообщения покупателей» и «Перенос времени» добавятся в блоке 10.
  3. **Покупателю в Telegram:** «Заказ принят», «Передан курьеру» / «Готов к выдаче», «Завершён», «Отменён» + денежные из блока 5. «Собираем» не отправлять. Настройки у продавца нет — всё включено. Покупатель без Telegram — только в приложении.
  4. **Вне часов работы** на витрине: «Сейчас закрыто · примем заказ на <ближайшее время>», оформить можно на ближайшее время. Плашка паузы — уже сделана в блоке 7, здесь не повторять.
- **Не входит:** рассылки и акции (A12b); покупатели без Telegram получают статусы только в приложении (B11).
- **Данные (API):** outbox из O1 → очередь → Telegram Bot API (токен из секретов магазина); статус доставки сообщения в журнале без текста.
- **Состояния:** бот не подключён (события копятся не дольше суток и не отправляются); бот потерял доступ к группе — пометка в настройках S7.
- **Тесты решений 22.11.2026:** реш. 2 — каждое событие уходит только сотрудникам по таблице ролей и правам (проверка в момент отправки); «Товар заканчивается» — одно сообщение на переход через порог, не при каждом заказе; реш. 3 — покупателю приходят ровно 4 статусных события, «Собираем» — не приходит; повтор события не шлёт второе сообщение;
- **Готово, когда:** простаивающий магазин — 0 фоновых запросов (тест); повтор события не шлёт второе сообщение (тест); сбой Telegram не откатывает заказ; на demo сообщение о новом заказе приходит в тестовую группу.
