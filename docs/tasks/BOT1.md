# BOT1 · Бот только у магазина, без бота платформы

- **Решение:** Андрей 23.11.2026, строка «D13 заменено · бот только у магазина» в [DECISIONS](../DECISIONS.md). Заменяет D13, §9.12 блока 4 (запасной канал приглашений) и §10.9 блока 5 (запасной бот).
- **Холст:** не нужен — новых экранов нет. Тексты «Бота подключает администратор Korzina» и т. п. остаются.
- **Зачем:** сейчас на demo один бот одновременно бот платформы и (особым случаем `demoPlatformShop`) бот `lavka`. Из-за этого у `test2` нет входа покупателей, а сообщения идут от «Korzina.app Demo».

## Входит

1. **Бота платформы нет.** Убрать `PLATFORM_BOT_TOKEN`, `PLATFORM_BOT_USERNAME`, `PLATFORM_BOT_WEBHOOK_SECRET`, платформенный webhook и особый случай `demoPlatformShop` / `demo-telegram`. Все места, где сейчас «бот магазина, иначе бот платформы», — только бот магазина.
2. **Всё через бота магазина:** вход в Mini App и браузере, приглашения сотрудников, уведомления продавцу и сотрудникам (блоки 8–9), сообщения покупателю (блоки 5, 9, 10), чат.
   - Браузерный вход продавца и покупателя использует одноразовый код в ссылке `https://t.me/<бот_магазина>?start=<код>`. Вход подтверждает webhook этого магазина. Mini App проверяет подпись `initData` токеном своего бота.
3. **Магазин без бота:** витрина работает как сайт, покупатель — только гость; продавцу и сотрудникам уведомления не отправляются (не ошибка, без повторов в очереди); приглашение сотрудника недоступно с понятной причиной «Сначала администратор подключит бота». Подключение бота по-прежнему только в админке (как сейчас).
4. **Админка — из любого магазина.** Доступ по списку `PLATFORM_ADMIN_TELEGRAM_IDS` (только Telegram ID; ник не проверяется). Вход: Mini App или браузерный вход любого магазина с ботом → в профиле пункт «Админка платформы» виден только ID из списка. Права админки не зависят от того, через какой магазин вошли.
5. **Demo:** после выпуска Андрей сам вставляет ключ @korzinaapp_demo_bot в админке demo → `test2` → «Бот магазина». `lavka` остаётся без бота. Старые секреты `PLATFORM_BOT_*` в Cloudflare Андрей удаляет сам после проверки.
6. Обновить README (секреты) и ARCHITECTURE в местах про бота платформы.

## Не входит

- Подключение бота продавцом в кабинете (идея фазы A).
- Единый вид сообщений бота и «Заказ оформлен» (BL-13, отдельно).
- Передача бота продавцу — делается в BotFather, в коде ничего.

## Готово, когда (тесты правил с «BOT1» в названии)

- BOT1.1 в коде и конфигурации нет бота платформы (проверка `check:arch` или тест на отсутствие `PLATFORM_BOT_`).
- BOT1.2 уведомление продавцу и сообщение покупателю уходят через бота своего магазина; у магазина без бота — не отправляются и не ставятся в повтор.
- BOT1.3 вход продавца через бота магазина А не даёт доступ к кабинету магазина Б.
- BOT1.4 ID из списка входит в админку через любой магазин; ID не из списка — 403; совпадение ника без ID — 403.
- BOT1.5 приглашение сотрудника у магазина без бота отклоняется с причиной.
- BOT1.6 код браузерного входа магазина А не подтверждается webhook бота магазина Б.
- Smoke на demo: после подключения бота к `test2` покупатель `test2` входит через Telegram; продавец получает «Новый заказ» от бота `test2`.
