# R4 · Логи Cloudflare без лишнего объёма (≈15 минут, уровень «Среднее»)

Повод: 19.11.2026 Андрей увидел в Observability → Usage 0,10 ГБ логов в день (20 % бесплатных 0,5 ГБ). Основной объём — автоматические invocation logs: Cloudflare пишет запись на **каждый** запрос к Worker (CI smoke, e2e, превью, проверки). Наш код пишет мало (метрики — 1 %, ошибки — `console.error`).

## Входит

- В `cloudflare.config.ts` для `korzina-demo` и превью: **выключить автоматические invocation logs**, оставить логи `console.*` включёнными (ошибки из `server/middleware/errors.ts` и выборочные метрики пишутся всегда). Трассировки оставить как есть (1 %). Если CLI `cf` не поддерживает эту настройку — `headSamplingRate` логов 0.1 и пометка в отчёте, что ошибки тоже попадают с вероятностью 10 %.
- Строка в `docs/PERFORMANCE.md` §«Измерение»: что пишется в логи и почему invocation logs выключены; для prod (L2) решение принимать отдельно.

## Не входит

- Удаление старых Worker в аккаунте (`korzina-live`, `korzina-site`, `korzina-kit-preview`, `korzina-design-review`, `lavka-*`): без запросов они логов не пишут; удаление — только отдельным «да» Андрея.

## Готово, когда

- После вливания и одного прогона Demo smoke в Workers Logs видны записи `console.error`/метрик, но нет записи на каждый запрос; ошибка, вызванная вручную на demo, видна в логах.
