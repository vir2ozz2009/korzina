# O1 · Машина состояний заказа — **финал «16 · Переходы между действиями»**

- **Figma (справочник Claude):** «16 · Переходы между действиями» (`846:55167`) — проверенные переходы между экранами покупателя и продавца; блоки 40, 58.
- **Истории:** основа для R02–R04, Z01, Z03.
- **Холст:** не нужен — только сервер.
- **Входит:**
  - **Оси состояния** по DOMAIN «Заказ»: исполнение (`placed` → `accepted` → `ready` → `in_delivery` / `awaiting_pickup` → `completed`; `cancelled`), оплата (`unpaid` → `pending_review` → `paid` / `rejected` + доплаты), согласование (`none` / `pending` → `applied` / `declined` / `expired`), возврат (`none` → `required` → `in_progress` → `done` / `partial`).
  - **Команды переходов** — проверка роли, текущего состояния и ревизии заказа; запись автора, времени, причины; **откат на шаг назад** («Вернуть статус», O2) — отдельная команда с причиной.
  - **Отмена покупателем** — до передачи курьеру, при самовывозе — до выдачи (D05); отмена освобождает остаток и интервал ровно один раз.
  - **`order_events`** (история заказа), **`seller_order_index`** (список заказов продавца по этапам и датам), **outbox** для уведомлений (O4) — пишутся в той же транзакции.
  - Группы для покупателя «В работе / Выполнен / Отменён» вычисляются из осей.
- **Не входит:** экраны (B11, O2); уведомления (O4); деньги (O5).
- **Данные (API):** команды `accept`, `markReady`, `handOver`, `markPickedUp`, `complete`, `cancel`, `rollback` с `Idempotency-Key` и `expectedRevision`; ошибки `INVALID_TRANSITION`, `VERSION_CONFLICT`, `FORBIDDEN`, `CANCEL_NOT_ALLOWED`.
- **Готово, когда:** тесты каждого разрешённого и запрещённого перехода; повтор команды не создаёт второе событие; гонка двух сотрудников — один выигрывает, второй получает конфликт; отмена и откат возвращают остаток и интервал один раз; бюджет SQL команды перехода; T06 (часть).
