# S8 · Сотрудники, права и история действий — **71, 72 (история), финалы «32 · Сотрудники», «33 · Данные»**

- **Figma (справочник Claude):** 71 (`923:68813`); финал «32» (`1360:72512`): «Список команды», «Команда пока пуста», «Добавление через Telegram», «Поиск по нику или ID», «Аккаунт не найден», «Доступ уже есть», «Приглашение через сайт», «Приглашение отправлено / не отправлено / ожидает / истекло», «Отозвать приглашение», «Сотрудник открыл приглашение», «Получить и ввести код», «Вход на новом устройстве», «Карточка сотрудника», «Готовые уровни доступа», «Настроить права вручную», «Подтвердить отзыв доступа», «Недостаточно прав»; финал «33» (`1360:74936`): «История действий», «Фильтры истории».
- **Истории:** M10.
- **Холст:** нужен.
- **Входит:**
  - **Команда:** список сотрудников с ролью; добавить **через Telegram** (поиск по нику или ID → подтвердить) или **приглашением по email** (ссылка + код; ожидает, истекло, отозвать; провайдер почты — D17).
  - **Права:** готовые уровни (владелец, администратор, сборщик «только заказы», бухгалтер «деньги») или вручную по разделам (DOMAIN «Роли»); проверка «что изменится» перед сохранением.
  - **Отзыв доступа** — сразу на всех устройствах (подтверждение).
  - **История действий:** кто, что, когда, «было → стало»; фильтры по сотруднику, разделу и дате; служебные действия — «Система»; токены, реквизиты и переписка в журнал не попадают; доступ — по праву. **Это экран поверх журнала магазина из AD3** — второй журнал не делать.
- **Нажимается:** «Добавить сотрудника» → Telegram или email; сотрудник → карточка → уровень доступа или права вручную → «Сохранить»; «Отозвать доступ»; «История действий» → фильтры → запись.
- **Не входит (не рисовать):** выгрузки, справка и поддержка (A13); тестовая покупка (S9).
- **Отличия от Figma:** нет.
- **Решения Андрея 21.11.2026 (сверка карточек блока 8, по образцу Shopify staff notifications; ошибка Square — всем всё):**
  1. **Уведомления сотрудникам — один бот, каждому лично.** Пишет бот магазина, без него — бот Korzina. **Рабочей группы Telegram нет** (подтверждение группы, события группы, отвязка — убраны из S7). Сотрудник подключается сам, открыв ссылку-приглашение через бота (после этого бот может ему писать).
  2. **Кто что получает — по роли по умолчанию:** сборщик — новые заказы; бухгалтер — оплаты и чеки; владелец и управляющий — всё. В карточке сотрудника переключатели «Новые заказы», «Оплаты и чеки», «Отмены» и кнопка «Прислать тестовое». Сотрудник без права на раздел не получает уведомлений этого раздела, даже если переключатель включён (проверка на сервере). Сама отправка и очередь — O4 (блок 9); здесь — настройки получателей и тестовое сообщение.
  3. **Добавление сотрудника — только ссылкой-приглашением** в Telegram (как приглашение владельца в блоке 4): выбрать роль → «Скопировать ссылку» / «Поделиться» → сотрудник открывает → кабинет. Поиска по нику и приглашения по почте нет (почта — D17, отложена). Ссылка одноразовая, срок 7 дней, отзывается.
  4. **Готовые роли:** «Владелец» (всё), «Управляющий» (всё, кроме сотрудников), «Сборщик» (заказы и сборка), «Бухгалтер» (заказы и деньги); «Настроить вручную» по разделам. Права разделов — как в блоках 5–7 (`orders`, `payments`, `products`, настройки — только владелец).
  5. **Открыть магазин могут оба:** владелец магазина (кнопка «Открыть магазин» после списка готовности) и администратор платформы в админке. Приостановить — оба; пауза администратора продавцом не снимается (блок 7).
  6. **Тестовая покупка — необязательная**, по кнопке в списке готовности.
- **Данные (API):** список членов магазина; команды «пригласить» (Telegram, email), «изменить права», «отозвать»; история — чтение журнала AD3 с курсором и фильтрами; ошибки `NOT_FOUND`, `ALREADY_MEMBER`, `INVITE_EXPIRED`, `CODE_INVALID`, `FORBIDDEN`.
- **Состояния:** команда пуста; аккаунт не найден; доступ уже есть; приглашение ожидает или истекло; неверный или истёкший код; недостаточно прав; ошибка загрузки.
- **Тесты решений 21.11.2026:** реш. 2 — уведомление уходит только сотрудникам с правом и включённым переключателем; сборщик не получает оплаты; выключенный переключатель — не получает; реш. 3 — ссылка одноразовая, истёкшая и отозванная отклоняются, повторный вход по той же ссылке не создаёт второго сотрудника; реш. 4 — роль «Сборщик» не видит деньги и настройки ни в интерфейсе, ни через API, «Управляющий» не может менять сотрудников;
- **Готово, когда:** отозванный сотрудник теряет доступ на всех устройствах сразу (тест); сотрудник «только заказы» не видит деньги и настройки ни в интерфейсе, ни через API (тест); в истории нет токенов и реквизитов (тест).
