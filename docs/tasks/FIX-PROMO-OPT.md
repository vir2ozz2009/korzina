## Дефект и воспроизведение

Три товара A, B, C по 100 минимальных денежных единиц, в корзине по две единицы каждого; VND позволяет видеть эти числа без дробей. Три опубликованных автоматических комбо AB, AC, BC, каждое из одной единицы двух соответствующих товаров, цена 150, лимит null (без ограничений). Остатков достаточно, других скидок нет.

Фактически calculatePromo возвращает 500: два AB за 300 плюс два C за 200. Правильно 450: один AB, один AC и один BC. Каждая из шести единиц использована ровно один раз. Воспроизведено на настоящем calculatePromo проверенной ревизии; существующие calculate.test.ts и group-pricing.test.ts (8 тестов) проходят без этой регрессии.

Причина: priceOffer выбирает максимальный count, а search переставляет предложения, не рассматривая меньшие количества комплектов. Перестановка предложений не заменяет перебор допустимых количеств.

## Входит

1. Сначала добавить регрессию с ожидаемыми 450 и показать падение на исходном коде.
2. Исправить поиск допустимого минимального итога, включая частичное применение возможных комплектов и совместимые акции на остатке. Конкретный алгоритм выбирает Codex; разрешено разделять независимые компоненты пересечения товаров.
3. Сохранить лимиты, точные SKU, остатки, приоритеты при равенстве, ручное применение кода и отсутствие повторной скидки на одну единицу. Отключённый флаг сохраняет прежнее поведение без акций.
4. Использовать один серверный расчёт для реальной корзины, примера продавца и оформления. Сохранить суммы распределения по строкам и снимок заказа для возвратов.
5. Измерить число состояний/время вычисления на фиксированных корзинах с пересечениями и добором; исключить неконтролируемое повторение поиска для подсказок. Не повышать бюджеты без решения.
6. Никаких скрытых ограничений числа акций или приближённой цены, которая иногда выше допустимого минимума. Если точный расчёт не укладывается в существующие допустимые границы — контрпример и варианты в Work.

## Не входит

Переработка шторки/доставки/текстов (CART-CLARITY), бесплатная доставка 12.3, оптимизация документов CTX-1, новые продуктовые лимиты, проекции статистики, массовый рефакторинг и любые рабочие ресурсы Lavka/prod. Холст не нужен: исправляется расчёт существующего сценария.

## Данные и состояния

Прежние контракты — по возможности без изменений. При необходимости минимального расширения сначала контракт и сервер, затем потребители. Сохраняются версия корзины, идемпотентность, пересчёт при изменении цены/остатка/условий, ошибки и флаг promotions. Финансовый снимок существующего заказа не пересчитывается.

## Готово, когда

- Контрольный треугольник даёт 450; распределённые оплаченные доли, строки и общий итог согласованы.
- Перестановка строк и предложений не меняет деньги; проверены 0/1/несколько комплектов, лимиты 1/2/null, недостаток остатка, одинаковые/разные фасовки.
- Есть небольшой независимый полный перебор как тестовый эталон для нескольких детерминированных маленьких корзин: ожидаемое не вычисляется тем же алгоритмом.
- Проверены конкуренция с подарком и обычным кодом, равенство автоматического и ручного предложения, отсутствие расхода проигравшего кода.
- Реальная корзина, пример продавца и оформленный заказ дают одинаковый итог; повтор оформления не списывает товары/лимиты дважды. Существующие проверки возврата и снимка зелёные.
- Есть воспроизводимый замер сложности/времени для более плотного пересечения и подсказок; фактические числа и среда в отчёте, а не голословное «быстро».
- Локально check:fast и связанные тесты; API-тесты последовательно. Полный Check и обязательные smoke — в CI по правилам проекта, без дублирования полного прогона.
- После зелёных проверок выпуск только на demo; отчёт docs/progress/FIX-PROMO-OPT.md с SHA сборки, до/после, тестами и чек-листом затронутого пути на физическом iPhone.
