# Карточки задач

Одна задача — один файл `<ID>.md`. Индекс задач и порядок блоков — [`docs/PLAN.md`](../PLAN.md).

- Карточки блока пишет и сверяет с Figma Claude **до холста**: структура кадров и картинка каждого кадра. «По Figma» пишется только про то, что видно на кадре.
- Codex читает **только карточку своей задачи** и документы и разделы, которые она называет.
- Чего нет во «Входит», то не делается. Если пункт можно понять двояко или его нельзя выполнить без догадки, Codex спрашивает Андрея и не додумывает.
- Закрытую карточку не дописывают. Новое — новая задача или строка в `PROGRESS.md` → «Мелкие правки».

## Шаблон

```markdown
# <ID> · <Название> — <блоки Figma>

- **Figma:** блоки и узлы (→ `SCREENS.md`), какие кадры входят в задачу.
- **Истории:** id из `stories/`.
- **Холст:** нужен — почему (отличие от Figma по DESIGN §5а / экрана нет в Figma / меняется вид одобренного экрана) · или «не нужен — как в Figma».
- **Входит:** что появляется на экране и что делает сервер.
- **Нажимается:** что происходит по каждому нажатию. Чего здесь нет, то не нажимается и не показывается.
- **Не входит (не рисовать):** всё из кадров, что делает другой блок, с номером задачи или блока.
- **Отличия от Figma:** строки DESIGN §5а и решения Андрея по этому экрану; если отличий нет — «нет».
- **Данные (API):** запросы и команды, поля ответа, коды ошибок (`src/shared/contracts`). Новый или изменённый контракт фиксируется в коде первым, до экрана.
- **Состояния:** загрузка, пусто, ошибка и повтор, нет в наличии, данные изменились, особые случаи. Каждое состояние, которое выглядит иначе, попадает на холст (или в снимки PR).
- **Готово, когда:** тесты правил (TESTING §2) и шаги smoke (TESTING §7).
```

Для серверных задач без экрана поля «Холст», «Нажимается» и «Отличия от Figma» не пишутся.
