## Первый ограниченный PR · seller HTTP

На main `ee8be230810e2afffd5feb8b4194e5603c5d3568` точечно подтверждён дубль из текущего аудита (код аудита: `9e55c8d5a2f99782d3c0019a334a6d8fd3d2063a`):
- `src/features/seller/orders-api.ts` — `request`;
- `src/features/seller/money-api.ts` — `read`;
- `src/features/seller/sales-api.ts` — `read`.

Общее правило: запрос от сессии продавца с магазином и `sellerSessionHeaders()`, затем `checkResponse()`. Выделить только транспорт, возвращающий Response, и перевести эти три адаптера на него. Полный перечень вызывающих hooks/операций проверить адресным поиском перед изменением; это ещё не выполненная миграция всех потребителей.

Сохранить различия адаптеров: orders исключает undefined/пустую строку и задаёт no-store; money исключает falsy-фильтры и переводит TypeError в ConnectionError только без abort; sales исключает только undefined и валидирует JSON через Zod. Формирование URL/фильтров, парсинг, blob-ответы, signal, заголовки команд, idempotency key, query keys, retries и invalidation остаются прежними. Не добавлять общие значения cache/retry, меняющие прежнее поведение. Сессия и магазин вычисляются на запрос, не сохраняются глобально.
