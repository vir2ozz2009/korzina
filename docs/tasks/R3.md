## Входит

1. **Одно место для данных покупателя.** Сейчас объединение профилей разбросано: адреса сливаются внутри `mergeCustomerCarts` (корзина), заказы — `transferBuyerOrders`, избранное — `mergeCustomerFavorites`, всё вызывается из `auth/routes.ts`. Из-за этого в B13 потерялись заказы. Сделать модуль `server/modules/buyer/merge.ts` с одной функцией `mergeBuyer(storage, source, target)`, которая по списку переносит все данные покупателя (корзина, получение и адреса, избранное, заказы и чеки); адреса вынести из слияния корзины. **Тест-страж:** берёт из схемы магазина все таблицы с колонкой `customer` (или `owner`/`subject` покупателя) и падает, если таблица не упомянута в списке `mergeBuyer` или в явном списке исключений с причиной. Так новая таблица не сможет «потеряться» при объединении.
2. **Редактор адреса без дубля.** `src/features/profile/AddressEditor.tsx` заново объявляет поля «Квартира / Подъезд / Этаж / Домофон» и их ввод — взять `addressFields` и `ManualAddressFields` из `features/receiving` (B7). Заодно проверить BL-1 не нужно — это отдельная правка.
3. **Бюджеты SQL новых горячих путей** (`PERFORMANCE` §6, строка «Список заказов без изменений — 1 SQL»): виджет активных заказов при совпавшей ревизии ≤ 1 SQL и 0 чтений строк заказов; карточка заказа покупателя ≤ 3 SQL; набор избранного для плиток ≤ 1 SQL. Тесты `*.budget.test.ts`.
4. **Размер файлов:** `OrderScreen.tsx` (258) и `checkout.test.ts` (278) разделить до ≤ 250.
5. **Единая раскладка фич:** экраны `features/profile` и `features/favorites` — в подпапку `ui/`, как у остальных (`cart`, `catalog`, `orders`).
6. **Сырой SQL и Drizzle — записать правило.** Фактически в DO 22 файла пишут SQL строками и 9 — через Drizzle, а ARCHITECTURE говорит только «Drizzle».
