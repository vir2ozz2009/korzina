## F3 · Реализация и проверка

- Работа в `task/F3-contracts`, база — актуальный `origin/main` `7b5a14c`; чужих изменений не было. Код Lavka не читался и не копировался; для денежных правил прочитан только указанный DOMAIN файл `store-rounding-policy.json`.
- Общие схемы — `src/shared/contracts/`, коды/формат ошибок — `errors.ts`, RPC-клиент — `src/shared/api.ts`. Типы входа и ответа выводятся из того же Hono-роутера, который обслуживает DO; RPC проверен настоящим HTTP-запросом в Workers runtime. `check:arch` разрешает только стираемый `import type { AppType }` в одном файле; runtime-импорты сервера по-прежнему запрещены и проверены тестами.
- `money.ts`: безопасные целые минимальные единицы; промежуточные вычисления через BigInt; сложение, вычитание, умножение, округление, процент и распределение по наибольшим остаткам. Проверены RUB-примеры, последовательные скидки, начисление вверх / лимит списания вниз, сохранение суммы и переполнение. Ограничение скидки оставшейся базой остаётся обязанностью будущего сервиса скидок; F3 не добавляет такой сервис.
- Middleware создаёт новый `X-Request-Id`, единый JSON ошибок, `no-store`, проверяет ключ, JSON, размер тела и происхождение команды. Ошибки 500 не раскрывают текст исключения. Лимит — 120 запросов/мин на IP в Worker и в Shop, 429 с `Retry-After`; ограниченные карты в памяти, без SQL и фоновых задач. Это защита от всплесков в пределах изолята, сбрасывается при его перезапуске; глобальную квоту не обещает. Проверенные идентификаторы сессий появятся в F4; произвольная cookie не считается сессией.
- Новая Drizzle-миграция `0001` создаёт `idempotency` с составным первичным ключом `(scope, key)`. Ключ и отпечаток метода/пути/query/точных байтов JSON хешируются. Выбор магазина не входит в отпечаток: база уже изолирована по магазину. Ключ привязан к переданному сервером scope; будущие команды обязаны передавать проверенного пользователя/сессию после авторизации. Выполнение команды и сохранение тела, статуса и заголовков ответа — одна `transactionSync`, без внешних вызовов. Ошибка откатывает бизнес-запись и не занимает ключ. Записи не истекают автоматически: повтор остаётся защищённым после перезапуска; политики удаления бизнес-команд ещё нет.
- Проверочный `POST /api/diagnostics/echo` доступен только на demo и localhost; не меняет бизнес-данные, сохраняет только собственный ответ в idempotency. Для него используется неперсональный scope `diagnostics`; это не авторизация будущих команд. Проверены 5 конкурентных повторов, повтор после eviction DO, конфликт тела, разные scope и магазины, исправление невалидного запроса и индексный план без SCAN.
- `server/metrics.ts` оборачивает доступ к SQLite, в том числе через Drizzle: число попыток SQL, реальные `rowsRead`/`rowsWritten` курсоров, время SQL и потребления курсора, время обработчика. Счётчики отдельны для каждого запроса; миграции — вне запроса. Платформенные D1-чтения в эти SQLite-счётчики не входят. Выборка логов — 1%; только шаблон маршрута, ID магазина/запроса, статус, числа и длительности, без IP, query, тела, SQL или параметров. Служебный заголовок с метрикой удаляется публичным Worker.
