19.11.2026 · реализация `52aa303`. [Карточка](../tasks/R3.md)

- Объединение покупателя проходит в транзакции входа. Один список покрывает корзину, контакт, получение, сохранённые адреса, избранное, заказы и чеки. Тест сверяет список и объяснённые исключения со схемой магазина. С временной таблицей `r3_guard_probe(customer)` тест упал и указал её имя. После проверки таблица удалена.
- Редактор профиля использует поля адреса из получения. Экраны профиля и избранного перенесены в `ui/`. Оплата выделена из карточки заказа, тесты оформления и действий покупателя разнесены по файлам.
- Виджет при совпадении ETag читает сессию и ревизию одним SQL. Создание заказа обновляет ревизию триггером. Для первого заказа это две дополнительные записи SQLite, строка и индекс. Бюджет оформления с чеком теперь 19 записей при прежних лимитах 15 SQL и 32 чтения.
- Для карточки покупателя тест ограничивает запрос тремя SQL, для идентификаторов избранного на плитках — одним. Правило выбора между Drizzle и `storage.sql.exec` записано в [архитектуре](../ARCHITECTURE.md#5-модель-данных-верхний-уровень).
