# O9 · Статистика продаж

Андрей одобрил [ревизию `476021224615587840`](https://designs.magicpath.ai/v1/friendly-cliff-4656?revisionId=476021224615587840&history=design) 24.11.2026. Реализация следует [§14.1–§14.5](https://github.com/vir2ozz2009/korzina/blob/cf3c74e364f43b4b71edd37eb57ab15f4585dd0c/docs/specs/money-and-sales.md#14-статистика-продаж-и-вход-из-карточки-в-списке).

Карточка «Статистика» стоит сразу под карточкой магазина и отдельно запрашивает выручку за семь завершённых дней. Экран по клику использует тот же период. Рейтинг открывается из обзора, отчёт товара — из рейтинга и списка товаров. В списке выполненных заказов период применяется к дате выполнения.

## Решения и проверки

| Правило | Проверка |
|---|---|
| §14.1 · Семь завершённых дней и сбой сводки | Сценарий `e2e/shop-settings.spec.ts` на 390 px. При HTTP 500 работают копирование ссылки, предпросмотр витрины, «Сегодня» и открытие паузы. Проверены вход в статистику, возврат, повтор сводки и открытие клавишей Enter. |
| П2, П3, §9.1–§9.2 · Выручка после скидок, поздний возврат, средний чек и количество | `server/modules/seller-sales/rules.test.ts`: пограничные секунды вокруг полуночи магазина, исключение оплаты курьеру и отменённых заказов, возврат после полуночи, повтор команды, откат и новое выполнение. |
| §10.2 · Неполная история | Тот же набор. Прежнее выполнение без даты помечает период как неполный. |
| §14.5 · Право на статистику | Тот же набор. Проверены гость, сотрудник без права, выдача и отзыв `payments`, чужой магазин на всех входах. |
| §4 · Бюджет сводки | Тот же набор. После заполнения проекции до четырёх SQL на стороне магазина, без записи. |

Снимки на 390 px сохраняются в артефактах браузерного прогона как `seller-home-statistics-390.png` и `seller-statistics-390.png`. O5 и O5b по-прежнему требуют отдельных сценариев приёмки.
