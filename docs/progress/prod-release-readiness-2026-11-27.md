## Блокеры выпуска
1. **Изоляция prod не реализована.** cloudflare.config.ts фиксирует worker=korzina-demo и domain=demo.korzina.app даже при production; environmentResources различает только preview/demo. build:prod меняет APP_ENV, но не целевую инфраструктуру.
2. **Команда выпуска не пригодна для prod.** npm deploy запускает platform:setup --seed; platform-target/platform-cli выбирают только demo/preview. Требуются явный prod-target, защита от ошибочной базы, миграции без учебного seed и отдельная команда выпуска конкретного SHA.
3. **Первый запуск и перенос — разные работы.** Прод текущего репозитория не найден; рабочие домены заняты Lavka. Нельзя применять миграции нового проекта к старым D1. Нужны решение о чистом запуске/переносе, перечень магазинов, сопоставление данных и порядок переключения доменов/ботов.
4. **L2: резервное копирование и восстановление.** В дереве репозитория нет выделенной реализации backup/restore; у korzina-demo нет Cron schedule. Это не исключает внешнюю систему, но её покрытие DO SQLite + D1 + R2 не доказано. До запуска выполнить требования L2 и восстановить учебный магазин.
5. **Приёмка денежного исправления.** Закрыть F0–F8 FIX-PROMO-OPT и передать результат Андрею; приёмка CART-CLARITY это не заменяет.
6. **Проверки перед запуском.** [BACKLOG](../BACKLOG.md#проверки-перед-запуском) сохраняет незакрытые проверки блоков 8–12.2: роли/отзыв доступа/изоляция, живые Telegram-уведомления и чужой заказ, денежные сценарии, мобильные клиенты. Сначала сверить уже имеющиеся доказательства, затем пройти только остаток; не повторять все блоки.
