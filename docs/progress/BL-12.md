# BL-12 · Изменения магазина и длина файлов

Изменения заказа, каталога и профиля магазина отмечаются внутри команды. Контекст живёт один запрос. Ошибки и повторы с тем же ключом идемпотентности не запускают побочные эффекты. Новый путь заказа с отметкой `changes.order(number)` получает обновление списка продавца и запуск очереди без изменения `Shop`. Для записи профиля и каталога пересчитывается срок паузы продажи, для каталога также проверяется очередь пороговых уведомлений.

`check:arch` отклоняет новые файлы длиннее 250 строк и рост восьми оставшихся исключений из `scripts/file-length-baseline.ts`. `Shop`, редактор товара и кабинет продавца укладываются в 250 строк.

| Правило | Проверка |
|---|---|
| Новое действие заказа работает независимо от пути | «BL-12 новое действие заказа сигналит продавцу без правки Shop»: команда PATCH будит очередь, открытый WebSocket получает номер заказа, откат и повтор не будят очередь |
| Исключения по длине имеют верхнюю границу | `scripts/arch-rules.test.ts`: 250 строк разрешены, новый длинный файл и рост исключения отклоняются |

Локально прошли `check:fast` и `test:related`: 36 проверок архитектуры и 233 серверных теста. [PR #205](https://github.com/vir2ozz2009/korzina/pull/205)
