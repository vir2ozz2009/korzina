- D1: Drizzle-миграция `0002_confused_squadron_supreme.sql`, `feature_overrides` с PK `(shop_id,key)` и FK на магазин. Один индексный запрос читает сразу все overrides магазина, только key/enabled, с `withSession("first-primary")`, без кеша, polling и фоновых задач. `GET /api/shop` добавляет `features`; дополнительного клиентского запроса нет. Прежний бюджет SQLite DO (2 SQL, ≤3 строки) сохранён; отдельно проверены 1 D1 prepare на чтение флагов, ≤2 прочитанных строк для одной override, отсутствие записей и SEARCH по shop_id без SCAN.
- `requireFeature` закрывает прямой запрос с `403 FEATURE_DISABLED`; клиентские заголовки не задают флаг. Сбой D1 закрывает доступ. Флаг не выдаёт роль; отдельная проверка доступа продолжает действовать. Доступность сверяется при новом запросе; уже запущенные запросы не отзываются задним числом.
- Клиентские `FeatureProvider`/`useFeature` принимают текущий bootstrap магазина; без provider/до загрузки возвращают false. Проверено серверным рендером React: вход скрыт при off, виден при on, не переносится в другой provider. Подключение provider к реальной оболочке — F8; нового продуктового экрана в F5 нет, MagicPath/Figma не применяются, ревизия не создавалась. Demo/localhost-only `/api/diagnostics/features/cashback` проверяет middleware, но не обещает работающий кошелёк или расчёт денег.

Параметризованный UPSERT, одинаковое значение не пишет повторно, неверный ключ/значение и неизвестный магазин завершаются ошибкой. Локальные on/off и ошибка неизвестного магазина проверены настоящим CLI; удалённая авторизация cf в окружении отсутствует, миграция demo проведена авторизованным Cloudflare API. Админка — AD2.
