## Перед началом

Использовать учебный магазин test2 и только свои учебные заказы, чеки и QR. Денег не переводить. Подготовить две раздельные сессии покупателя и продавца. Для проверок доступа нужны владелец и сотрудники с правом `payments` и без него. Для отказа в доступе использовать также другого покупателя и другой тестовый магазин. Зафиксировать часовой пояс магазина. Суммы ниже приведены в единицах валюты заказа, символ валюты зависит от магазина.

Для каждой строки записать номер сценария, устройство, роль, номер учебного заказа, результат ✅/❌/⏸ и снимок. При ❌ указать действие, ожидаемый и фактический результат. При ⏸ записать, каких данных или прав не хватило. Для ночных регрессий использовать магазин e2e. Если для проверки неполной истории, догрузки или сравнения нужны особые данные, использовать подходящую учебную выборку. При её отсутствии поставить ⏸ по соответствующему шагу. Перед окончательным «Одобряю блок 11» отдельно запустить [«Регрессии»](QA1.md).

Покупатель видит ожидание, свой продавец с правом на деньги получает реквизиты. Проверить прямую ссылку с чужой сессией, чужим магазином и сотрудником без `payments`. Проверить «Нет продаж» при пустом текущем периоде и «Нет данных для сравнения» при пустом прошлом. «Выполненные заказы» фильтруются по дате выполнения, полный возврат сохраняет заказ, отменённые исключены. |
| 08 | Сверить заказ, выполненный до полуночи магазина, и выплату после неё. Выручка уменьшается в дне выполнения, операция возврата идёт в день выплаты. Закрыть изменённый период без применения и сверить прежнюю выборку. |

#### Ручная перепроверка поиска в «Операциях»

Остаток сценария 10 ([§3.6 и §5](../specs/money-and-sales.md#36-общие-состояния-и-доступность)). Только чтение в Chrome под продавцом с правом на деньги. В «Регрессиях» использовать штатную учебную сессию магазина [`e2e`](https://demo.korzina.app/seller/money/operations?store=e2e). Для ручного прогона на компьютере Андрея можно использовать [`block11-qa`](https://demo.korzina.app/seller/money/operations?store=block11-qa) или другой доступный учебный магазин, указав его в результате.

1. В обычной сети выбрать период с операциями. Записать даты и номер видимого заказа, который ещё не искали в этой вкладке. Открыть DevTools → Network, включить Preserve log и фильтр `money/operations`.
2. Включить Offline. Ввести этот номер в поле «Номер заказа или точная сумма». Дождаться «Нет соединения» и кнопки «Повторить». Поле доступно, введённый номер и даты сохранены. Запрос поиска в Network завершился сетевой ошибкой. Вместо ошибки не должно быть вечной загрузки или результата «Ничего не найдено».
3. Вернуть обычную сеть и проверить Network **до клика**. «Повторить» остаётся на месте, нового `GET /api/seller/money/operations` для этого поиска нет. Номер и даты остаются видимыми. Если кнопка исчезла сама, записать время её исчезновения и наличие GET до клика, отметить ❌.
4. Если «Повторить» доступна, нажать её один раз без перезагрузки страницы. Новый GET содержит прежние `from`, `to` и `search` и возвращает HTTP 200. Ошибка исчезает, номер и период остаются, все строки относятся к искомому заказу. Новой загрузки документа нет.
5. Записать ревизию из `meta[name="build-revision"]`, браузер, магазин, период и итог ✅/❌ сюда. При сбое приложить снимок или строку из Network без данных сессии. Потеря ответа при записи, роли и физические устройства остаются отдельными проверками.
