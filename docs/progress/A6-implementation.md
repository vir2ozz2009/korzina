## Результат

- Базовый тариф остаётся в S4; ссылка ведёт в одну `auto-delivery` с порогом/сроком/ревизией. Автоматическая доставка — отдельная акция общего списка, доставка по коду — выгода общей формы промокода; несколько кодов независимы.
- Общий серверный расчёт выбирает оплату с учётом доставки. Порог — после цен позиций/групп, до общей скидки; сценарий 590 против 500 закреплён отдельно. Неизвестный тариф, исходный ноль, отсутствие адреса, самовывоз и оплата курьеру различимы. Код/авто не приписывают себе исходный ноль; код скрывает лишний добор.
- Заказ хранит основание/редакцию/условия и первоначальный тариф. Поздний тариф проводит расход/освобождение внутри штатной версии/идемпотентной команды; отмена освобождает право, снятие позиции сохраняет бесплатную доставку. Денежная сумма/доплата используют фактически оплачиваемую доставку; результаты разделены по реальному основанию.
- Пример читает действующие каталог/настройки и сразу готовит корзину/учебный контекст. Нет записи в личную корзину, адреса, остатки, заказы, лимиты и результаты; невозможность собрать пример объясняется. «Изменить пример» необязательно и свёрнуто. Это код приложения, отдельно от холста; [PROMO-EXAMPLE-TRANSFER](PROMO-EXAMPLE-TRANSFER.md) получил собственные тесты, прежняя приёмка 12.1/12.2 не переобъявлена.
- Новый транспорт CONTEXT-CODE #340 не расширялся: три адаптера остаются отдельной завершённой задачей с [согласованным владением](CONTEXT-CODE-seller-http.md).
