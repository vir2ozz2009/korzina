## F2 · Проверки и эксплуатация

- D1 `korzina-demo-platform`: `shops`, `domains`, `invitations`; привязки `PLATFORM`, `SHOP` и SQLite-экспорт `Shop` в `cloudflare.config.ts`. Сид `lavka`/`test2` относится только к новому Korzina. Ресурсы и домены старого проекта не менялись.
- `resolveShop`: точный host из D1; `?shop=` и магазин по умолчанию разрешены только на `demo.korzina.app` и localhost. Положительный кеш в памяти и Cache API живёт не дольше 60 с; неизвестные магазины не кешируются. Заголовки покупателя не выбирают магазин.
- `Shop`: Drizzle-миграции входят в бандл и применяются через `blockConcurrencyWhile` при первом обращении. Идентификатор магазина сверяется с именем DO и сохраняется в его SQLite. Только `/api/shop` доступен снаружи; записи и приглашения не публикуются.
- Проверки Workers runtime: два host и query, неизвестный/выключенный магазин, подмена заголовков, изоляция SQLite после записи в A и перезапуска DO, миграция ровно один раз, атомарность создания, повторный сид, приватность токена. Старые тесты сохранены.
- `npm run dev` сам применяет локальную D1-миграцию и сид. `npm run platform:setup -- --seed` подготавливает demo (нужна авторизация `cf`); `--local` выбирает локальную базу. `npm run deploy` применяет D1-миграции перед публикацией; при Workers Builds новые D1-миграции нужно применять перед деплоем. Начальная миграция и сид demo уже применены.
- `npm run shop:create -- <slug> <name>` создаёт магазин на demo и печатает витрину `?shop=<slug>` и секретную ссылку `/seller/invite?...`; `--local` создаёт локально. Только хеш токена хранится в D1, срок приглашения — 7 дней; обработка входа владельца относится к F4/S1. На demo создан проверочный магазин `f2-created` теми же SQL-командами через авторизованный Cloudflare API.
- До настройки wildcard реальные адреса магазинов на demo открываются через `?shop=`; маршрутизация по host проверена в Workers runtime. Продуктовых экранов и ревизии MagicPath в F2 нет.
- Demo проверено через Cloudflare Browser Rendering: `GET /api/shop?shop=lavka`, `test2`, `f2-created` → 200 и разные правильные ID/имена, ответы `no-store`; неизвестный магазин → 404, закрытые приглашения → 404; подставленный `x-korzina-shop` не меняет выбранный магазин. Health → 200. Первый вызов каждого нового DO сам создал SQLite-таблицу настроек; отдельные ID подтверждены проверкой принадлежности внутри DO.
