## Чек-лист локального Codex

**Перед началом.** На Mac открыть iPhone Mirroring, записать модель, версию iOS, способ запуска (Safari или Telegram), фактическую CSS-ширину и `meta[name=build-revision]` на [demo-витрине](https://demo.korzina.app/?shop=promo-qa-121). Сверить SHA со сборкой в передаче Work. Использовать только `promo-qa-121`, не кабинет другого магазина. Зафиксировать исходные цены, фасовки, остатки и состояние QA-акций. Для сценариев с продавцом нужен авторизованный учебный владелец/сотрудник этого магазина с правами на акции и заказы.

- [ ] **D1 · §7.11.** В [кабинете QA](https://demo.korzina.app/seller/promotions?store=promo-qa-121) открыть черновик «Завтрак» с лимитом 2 и его изолированный пример. Добавить две пары. Должно быть «2 из 2 наборов по акции». Третья пара даёт «2 из 3 наборов по акции» с лимитом 2. Уменьшить до одной пары и проверить, что подсказка о доборе вернулась.
- [ ] **D2 · §7.8.** На списке акций QA сверить три счётчика на карточках с 1, 2 и 5 выполненными заказами: «1 заказ», «2 заказа», «5 заказов». Если таких данных нет, подготовить только учебные заказы и записать их номера. Непроверенные значения не засчитывать.
- [ ] **D3 · §7.3/7/10.** В покупательской корзине два разных товара по 3 и действующее комбо для этих фасовок, без конкурирующих акций. Дважды нажать «−» в первой строке с ожиданием пересчёта между нажатиями, потом дважды во второй. Последовательность 3+3 → 2+3 → 1+3 → 1+2 → 1+1. Строки не меняются местами, соседний товар не уменьшается, число комплектов и итог пересчитываются.
- [ ] **D4 · §10.** Открыть карточку с длинной фасовкой и «250 г». Длинный ярлык читается целиком, короткий виден без горизонтальной прокрутки. **Пальцем на самом iPhone** нажать «250 г», добавить товар и убедиться, что именно «250 г» показано в корзине. Клик мышью через Mirroring не заменяет нативный тап.
- [ ] **B1.** Подключённым учебным ботом открыть Mini App на iPhone как подтверждённый покупатель. В корзине открыть шторку «Промокод» и тапнуть поле на телефоне. Появляется **полноразмерная экранная клавиатура iOS**. Ввести учебный код на этой клавиатуре и убедиться, что поле реагирует. Панель аппаратного ввода и клавиатуру Mac не засчитывать.
- [ ] **§7.7.** Войти продавцом именно в `promo-qa-121`. В учебном заказе «200 + 100 за 240» убрать строку с оплаченной долей 80. Оставшаяся строка стоит 160 (с тем же масштабом и валютой магазина). До оформления удаление обязательной фасовки должно пересчитать условия набора.
- [ ] **§7.8.** Пройти оба входа («По цели» → «Увеличить сумму заказа» и прямой выбор механики). Для подарка и комбо сверить, что оба входа ведут к соответствующей форме. В отчёте подарка сверить один заказ, две группы и два подарка. В отчёте комбо при двух полных комплектах и лимите один — один проданный комплект. Из каждого отчёта открыть соответствующий выполненный заказ.
- [ ] **§7.9.** В черновике комбо в строке кофе открыть «Фасовка», сменить 500 г на 250 г (в списке только фасовки кофе). Добавить круассан отдельной строкой, сохранить, закрыть и повторно открыть черновик. В нём обе строки, у кофе 250 г.

**Готовность доступа.** У `promo-qa-121` не подключён учебный Telegram-бот. Старт Telegram-входа покупателя и продавца на demo вернул `AUTH_UNAVAILABLE` («Telegram магазина пока не подключён»), кабинет без сессии — 401. Для B1 нужны подключённый к этому магазину учебный бот с Mini App и тестовый покупатель с подтверждённым Telegram. Для D1/D2 и §7.7–9 нужен рабочий вход учебного продавца именно в QA-магазин либо действующая выданная временная сессия QA с правами на акции и заказы. Сессия другого магазина не подходит.

B2 и пройденные §7.1–2 целиком не повторять. Зафиксировать результаты и снимки, отменить только созданные учебные заказы с возвратом остатков, вернуть временно изменённые QA-данные, закрыть тестовые сессии. Опубликовать отчёт в Work. Приёмка — решение Андрея.
