# Шаблоны экранов

Каждый экран в `navigation.md` использует один шаблон. Шаблон — компонент в `src/app/templates/`, который уже содержит шапку, область прокрутки, закреплённый низ, safe-area и состояния (загрузка, пусто, ошибка с действием по типу). Экран передаёт ему только данные и содержимое слотов.

Восемь шаблонов покрывают все 100 экранов первой версии. Новый шаблон — только решением Андрея.

## Ошибки прав и повторы

- API-клиент сохраняет HTTP-статус и код ошибки; не превращает 401/403 в обычную сетевую ошибку.
- `QueryBoundary` при 401/403 показывает `ErrorState`: «Нужно войти как продавец», неактивная «Войти» и подпись «скоро» до S1. Повтора нет, автоматические повторы Query отключены для отказа в доступе.
- При отзыве доступа кешированные данные и закреплённые действия скрываются сразу, даже если в Query ещё остался предыдущий ответ.
- «Повторить» и автоматический повтор разрешены только для сетевой ошибки или 5xx. Прочие 4xx показывают сообщение без повтора. Ошибки загрузки файла следуют тому же правилу.

## Общие правила шаблонов

- Шапка: `back` (стрелка; в Telegram прячется, работает BackButton), заголовок, до двух иконок действий. На корнях вкладок — без стрелки.
- Закреплённый низ поднимается над клавиатурой и над нижней панелью вкладок; учитывает safe-area.
- Состояния данных показывает `QueryBoundary` шаблона: скелетон по форме слотов → данные | пусто (`EmptyState` с действием) | ошибка (`ErrorState`: 401/403 — вход, сеть/5xx — повтор, прочие 4xx — сообщение). Экран не рисует их сам.
- **Загрузка без «бац»** — одинаково для загрузки данных и загрузки кода экрана:
  - пока грузится код экрана (ленивый чанк), показывается **скелетон шаблона этого экрана** (шаблон известен из маршрута), а не текст «Загрузка…» и не пустой экран; текстовые заглушки загрузки запрещены;
  - скелетон повторяет форму итогового экрана: те же высоты шапки, карточек, плиток, строк, отступы — при появлении данных ничего не прыгает (CLS ≤ 0,1);
  - если данные пришли быстрее 150 мс — скелетон не показывается вовсе; если показан — держится не меньше 300 мс, чтобы не мигать;
  - содержимое появляется мягко: fade 150 мс (без сдвига), при `prefers-reduced-motion` — без анимации;
  - фото всегда в контейнере с заданной пропорцией и фоном `input`, затем плавно проявляются;
  - повторное открытие экрана берёт данные из кеша мгновенно, без скелетона; свежие данные подгружаются тихо;
  - код и лёгкие данные следующего экрана предзагружаются при наведении/касании ссылки и при появлении ссылки в зоне видимости (`preload: "intent"`), поэтому обычно скелетон не нужен совсем.
- Команды (сохранить, оформить, сменить этап) показывают ожидание на кнопке; ошибка — тост или текст под кнопкой, введённые данные не теряются.
- Ширина: на телефоне 100%; на десктопе колонка `max-w-[480px]` по центру до задачи A16.
