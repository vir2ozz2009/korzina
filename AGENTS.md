# Korzina — правила для агента

Korzina — платформа для продавцов еды, которые продают через Telegram. Одна кодовая база обслуживает сотни магазинов: витрину `<slug>.korzina.app`, Telegram Mini App, кабинет продавца и бота. Пишем с нуля. Lavka — только источник продуктовых правил, её код не копируем.

## Как начинать любой чат

1. `git status`, текущая ветка и HEAD. Чужие незакоммиченные изменения не трогай.
2. Прочитай `docs/PROGRESS.md`: в нём текущая задача и следующий шаг.
3. Найди карточку задачи в `docs/PLAN.md` и её истории в `docs/stories/README.md` (колонка «Задача»). Открой **только** файл раздела этих историй — в нём критерии приёмки. Читай только документы и разделы, которые называет карточка; не открывай весь `docs/` и `reference/` «для контекста».
4. На сообщения «Продолжай», «Дальше» и подобные бери следующую незакрытую задачу из PROGRESS.md.

| `docs/DESIGN.md` | Токены, UI-кит, шаблоны экранов, переходы, цикл с MagicPath. Перед любой UI-задачей |

| `docs/stories/` | Пользовательские истории: индекс + критерии приёмки по разделам (включая админку платформы — `platform-admin.md`) |

## Золотые правила

1. **Один шаг — одна завершённая вертикаль**: схема → API → экран → тест → проверка в браузере → коммит. Не начинай следующую задачу, пока текущая не на demo.
2. **Переиспользуй, а не копируй.** Экран собирается из `src/ui` и шаблонов `src/app`. Нужен новый элемент — добавь его в UI-кит, а не в экран. Переходы, шапки, состояния загрузки, пусто и ошибки уже есть в шаблонах; на странице их заново не пиши.
3. **Сервер — источник правды** о цене, остатке, правах, статусе заказа и деньгах. Клиент только отображает и отправляет команды.
4. **Маленькие файлы**: до ~200 строк, один компонент или модуль на файл. Без «на будущее»: не пиши код, которого нет в задаче.
5. **Визуал — свобода, правила — нет.** Визуальные решения принимай сам: стиль из Figma, и для недостающих экранов тоже. Противоречия в деньгах, правах и заказах — в `DECISIONS.md` и вопрос Андрею.
6. Секреты, токены и данные покупателей — только в `.dev.vars` и Cloudflare secrets, никогда в Git.
7. `main` автоматически публикуется на `demo.korzina.app`. Работай в ветке `task/<ID>`, вливай в `main`, когда проходят проверки (`npm run check`).
8. **Lavka не трогаем.** Репозиторий `vir2ozz2009/Lavka`, ресурсы Cloudflare с префиксом `lavka-`, домены `korzina.app`, `app.`, `admin.`, `lavka.korzina.app` и поддомены её магазинов, её боты и компоненты в старом холсте MagicPath — только чтение и только когда карточка задачи ссылается на Lavka. Свои ресурсы Korzina называем с префиксом `korzina-`.

## Проверки

- Задача закрыта, когда выполнены критерии её историй и «Готово, когда» карточки.
- Всегда: `npm run check` (типы, Biome, `check:arch`, юнит- и API-тесты). Правило `check:arch` не отключай — исправь код или спроси Андрея.
- Для UI: открой путь в браузере на ширине 390, проверь переходы, назад, загрузку, пусто, ошибку и повтор.
- Для денег, заказа и прав: тест на сервере для каждого правила из карточки.
- Старые тесты не удаляй и не ослабляй.

## Как заканчивать чат

1. Обнови статусы историй задачи в `docs/stories/README.md` (`сделано` — только если все критерии проверены на demo).
2. Обнови `docs/PROGRESS.md`: что сделано, ссылка на ревизию MagicPath, что проверено, что осталось, время (материалы / сборка / проверка).
3. Закоммить и запушь.
4. Последней строкой напиши Андрею: `➡️ Этот же чат / Новый чат. Напишите: «…»`.
